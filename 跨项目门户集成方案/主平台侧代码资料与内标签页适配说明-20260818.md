> 文档用途：回应《主平台内标签页适配与代码资料需求说明-20260818.md》，向场景库团队提供主平台（ices-union）的真实代码、内标签页机制与推荐通信协议，供其按真实实现完成最小范围改造。
> 编写日期：2026-08-18
> 涉及系统：主平台 `ices-union`（Vue 3 + Vite 6 + Vue Router 4 + Pinia）与场景库独立版（React，`http://47.122.104.52:8081/cockpit/`）
> 当前集成方式：主平台 `src/views/sceneLibrary/index.vue` 以 iframe 直接嵌入场景库独立版，不采用 qiankun。
> 仓库路径：`/root/3DDDD/ices-union/`

## 0. 结论速览（TL;DR）

回答需求中最核心的几个问题：

1. **不需要两套跳转逻辑**。主平台的 `router.push` 本身就"自动适配"内标签页开关：
   - 开关**开启**时，内标签组件（`MultipleTabs`）挂载并监听路由变化，自动把新路由加为内标签；
   - 开关**关闭**时，该组件不渲染、监听不注册，`router.push` 退化为普通同页跳转。
   - 主平台没有 `openPage` 之类的统一导航函数，但也不需要——直接 `router.push` 即可。
2. **不同模型 ID 会复用同一个标签，不会分别创建**。`/three-model/detail?id=2326` 与 `?id=2328` 的 `path` 相同，`addTab` 按 path 去重（忽略 query）→ 替换复用同一个标签。
3. **标签标题当前为固定"模型详情"**（`route.meta.title`）。如需显示模型名称，主平台可在详情页用 `useTabs().setTitle()` 动态设置。
4. **主平台侧改动量小**：只需在场景库 iframe 宿主页新增一个 `message` 监听 + 白名单校验 + `router.push`，约 40 行。无需改全局标签系统。
5. **一个需要双方确认的行为差异**：场景库路由 `ignoreKeepAlive: true`，从场景库标签切到模型详情再返回时，场景库 iframe 会**重新加载**（回到驾驶舱默认页），不保留切走前的内部页面状态。

**script setup 完整相关部分（L46-120）：**

```ts
import { computed, onBeforeUnmount, onMounted, ref } from 'vue';
import { useRouter } from 'vue-router';
import { useGlobSetting } from '/@/hooks/setting';
import { PageEnum } from '/@/enums/pageEnum';

const router = useRouter();
const glob = useGlobSetting();

const enabled = computed(() => glob.sceneLibraryEnabled !== false);
// 场景库入口：iframe src（原样使用，不附加 query）
const frameSrc = computed(() => glob.sceneLibraryEntry || 'http://47.122.104.52:8081/cockpit/');
// 加载超时（默认 30000），可经 VITE_GLOB_SCENE_LIBRARY_LOAD_TIMEOUT_MS 配置
const loadTimeoutMs = Number(glob.sceneLibraryLoadTimeoutMs) || 30000;

const frameKey = ref(0);
const loading = ref(false);
const errorMsg = ref<string | null>(null);
let loadTimer: ReturnType<typeof setTimeout> | null = null;

function clearLoadTimer() {
  if (loadTimer) { clearTimeout(loadTimer); loadTimer = null; }
}

// 开始加载：置 loading + 启动超时兜底
function startLoad() {
  errorMsg.value = null;
  loading.value = true;
  clearLoadTimer();
  loadTimer = setTimeout(() => {
    loading.value = false;
    errorMsg.value = '场景库加载超时，请检查网络后重试';
  }, loadTimeoutMs);
}

// iframe 加载完成（含 200 错误页）：正常进入独立版
function onLoad() { clearLoadTimer(); loading.value = false; }

// iframe 网络层加载失败：进入错误态
function onError() {
  clearLoadTimer();
  loading.value = false;
  errorMsg.value = `无法连接场景库服务（${frameSrc.value}）`;
}

// 重试：强制重建 iframe 并重新走加载流程
function retry() { frameKey.value++; startLoad(); }

// 返回主项目首页
const backHome = () => router.push(PageEnum.BASE_HOME);

onMounted(() => { startLoad(); });

onBeforeUnmount(() => {
  // 离开路由/标签页：iframe 随组件销毁，无 WebGL/轮询残留
  clearLoadTimer();
});
```

**路由定义 `src/router/routes/modules/sceneLibrary.ts`：** 一级菜单 `path: '/scene-library'`（`hideChildrenInMenu: true`）；子路由 `path: ''` + `hideMenu: true` + **`ignoreKeepAlive: true`**（组件不缓存，离开即销毁 iframe）；兼容旧链 `{ path: 'index', redirect: '/scene-library' }`。

### 2.2 关键事实

| 项 | 值 |
|---|---|
| iframe src | `VITE_GLOB_SCENE_LIBRARY_ENTRY`（默认 `http://47.122.104.52:8081/cockpit/`） |

### 4.2 打开页面的真实机制（核心）

**没有独立"打开标签"函数。** 链路为：

```
router.push({ path, query })
  → beforeEach 中 createPageGuard 调 setRouteChange(to)      (src/router/guard/index.ts:39)
  → mitt 事件 routeChange 派发                               (src/logics/mitt/routeChange.ts:15-24)
  → MultipleTabs 组件内 listenerRouteChange 回调执行 addTab   (src/layouts/default/tabs/index.vue:96-117)
```

`src/layouts/default/tabs/index.vue:96-117`：

```ts
listenerRouteChange((route) => {
  const { name } = route;
  if (name === REDIRECT_NAME || !route || !userStore.getToken) {
    return;
  }
  const { path, fullPath, meta = {} } = route;
  const { currentActiveMenu, hideTab } = meta as RouteMeta;
  const isHide = !hideTab ? null : currentActiveMenu;
  const p = isHide || fullPath || path;
  if (activeKeyRef.value !== p) {
    activeKeyRef.value = p as string;   // 激活当前标签
  }
  if (isHide) {
    const findParentRoute = router.getRoutes().find((item) => item.path === currentActiveMenu);
    findParentRoute && tabStore.addTab(findParentRoute as unknown as RouteLocationNormalized);
  } else {
    tabStore.addTab(unref(route));
  }
});
```

`src/router/guard/index.ts:32-47`（事件源）：

```ts
function createPageGuard(router: Router) {
  const loadedPageMap = new Map<string, boolean>();
  router.beforeEach(async (to) => {
    to.meta.loaded = !!loadedPageMap.get(to.path);
    setRouteChange(to);   // 通知 tabs / 菜单
    return true;
  });
  router.afterEach((to) => { loadedPageMap.set(to.path, true); });
}
```

### 4.3 `addTab` 去重逻辑（回应"path/fullPath/query 策略"）

`src/store/modules/multipleTab.ts:201-257`：

```ts
async addTab(route: RouteLocationNormalized) {
  const { path, name, fullPath, params, query, meta } = getRawRoute(route);
  // 404 / login / 无 name / Redirect 不建 tab
  if (path === PageEnum.ERROR_PAGE || path === PageEnum.BASE_LOGIN || !name ||
      [REDIRECT_ROUTE.name, PAGE_NOT_FOUND_NAME_404].includes(name as string)) return;

  let updateIndex = -1;
  // ① 先按 fullPath 精确匹配
  const tabHasExits = this.tabList.some((tab, index) => {
    updateIndex = index;
    return (tab.fullPath || tab.path) === (fullPath || path);
  });
  if (tabHasExits) {
    // 命中 → 原地更新 query/params/fullPath
    const curTab = toRaw(this.tabList)[updateIndex];
    curTab.params = params || curTab.params;
    curTab.query = query || curTab.query;
    curTab.fullPath = fullPath || curTab.fullPath;
    this.tabList.splice(updateIndex, 1, curTab);
  } else {
    // ② 忽略 query，只比 path
    const findIndex = this.tabList.findIndex((tab) => tab.path === path);
    if (findIndex !== -1) {
      this.tabList.splice(findIndex, 1, route);  // 同 path 不同 query → 替换复用同一标签
      return;
    }
    // ③ 均未命中 → push 新标签（dynamicLevel 限制略）
    this.tabList.push(route);
  }
  this.updateCacheTab();
  cacheTab && Persistent.setLocal(MULTIPLE_TABS_KEY, this.tabList);
}
```

**结论：**
- **标签唯一键**：渲染 key 为 `item.query ? item.fullPath : item.path`（`tabs/index.vue:13`）；去重优先 `fullPath`，其次 `path`（忽略 query）。
- **query 不同但 path 相同 → 复用同一标签（替换更新），不会分别创建**。
- 因此依次打开 `2326 → 2328 → 2316 → 2310` 是**同一个标签**不断被替换（模型详情标签只有一个），内容随 query.id 重载。


### 5.3 结论（回应 §5.4 第 6、7 问）

- **同一 `router.push` 自动适配开关**：是。addTab 完全由"组件是否挂载"驱动，与调用方无关。**不需要两套逻辑**。
- **是否存在统一导航函数**：不存在 `openPage`。`useGo`（`src/hooks/web/usePage.ts:19-40`）只是 `router.push/replace` 的薄封装，不感知开关，也不需要在本次使用。
- **开关关闭时多标签只是隐藏还是逻辑也停**：逻辑也停（组件卸载 → 监听移除）。

### 6.2 主平台宿主页实现（待新增，改动集中在 `src/views/sceneLibrary/index.vue`）

```ts
// ===== 新增常量（建议提取到文件顶部或独立 protocol.ts）=====
const SCENE_LIBRARY_ORIGIN = 'http://47.122.104.52:8081';  // 场景库源站 Origin 白名单（§7）
const HOST_ALLOWED_PATHS = new Set(['/three-model/detail']);
const HOST_ALLOWED_MODEL_IDS = new Set(['2326', '2328', '2316', '2310']);

// ===== 模板：iframe 加 ref =====
// <iframe ref="iframeRef" ... />（其余属性不变）

const iframeRef = ref<HTMLIFrameElement | null>(null);
const appStore = useAppStore();   // import { useAppStore } from '/@/store/modules/app';

function handleSceneLibraryMessage(event: MessageEvent) {
  // 1. 来源校验：必须是当前场景库 iframe 的 contentWindow
  if (iframeRef.value && event.source !== iframeRef.value.contentWindow) return;
  // 2. Origin 白名单
  if (event.origin !== SCENE_LIBRARY_ORIGIN) return;
  const data = event.data;
  if (!data || data.type !== 'scene-library:navigate' || data.protocolVersion !== '1.0') return;
  const { path, query } = data.target || {};
  // 3. 仅允许固定路由（拒绝任意 URL / javascript: / 协议相对地址）
  if (!HOST_ALLOWED_PATHS.has(path)) return sendResult(event, data, 'rejected', '非法路由');
  // 4. 仅允许固定模型 ID
  const id = String(query?.id ?? '');
  if (!HOST_ALLOWED_MODEL_IDS.has(id)) return sendResult(event, data, 'rejected', '非法模型 ID');
  // 5. 交给主平台既有导航（自动适配内标签开关，见 §5）
  router
    .push({ path, query: { id } })
    .then(() => sendResult(event, data, 'accepted'))
    .catch((e: any) => sendResult(event, data, 'failed', `导航失败：${e?.message || ''}`));
}

// 与 MultipleHeader.getShowTabs 同一口径：判断"当前会走内标签还是同页"
function currentMode(): 'multi-tab' | 'same-page' {
  const show = appStore.getMultiTabsSetting.show && !appStore.getLayoutHideMultiTabs;
  return show ? 'multi-tab' : 'same-page';
}

function sendResult(
  event: MessageEvent,
  data: SceneLibraryNavigateRequest,
  status: 'accepted' | 'rejected' | 'failed',
  message?: string,
) {
  const payload: SceneLibraryNavigateResult = {
    type: 'scene-library:navigate-result',
    protocolVersion: '1.0',
    requestId: data.requestId,
    status,
    ...(status === 'accepted' ? { mode: currentMode() } : {}),
    ...(message ? { message } : {}),
  };
  event.source?.postMessage(payload, event.origin);
}

// onMounted / onBeforeUnmount 中注册与清理：
onMounted(() => {
  startLoad();
  window.addEventListener('message', handleSceneLibraryMessage);
});
onBeforeUnmount(() => {
  clearLoadTimer();
  window.removeEventListener('message', handleSceneLibraryMessage);   // 卸载清理，防重复监听
});
```

> 说明：
> - 若场景库需要动态标签标题，`router.push` 成功后可在详情页设置。更简单做法是主平台详情页在 `onMounted` 按模型名调用 `useTabs().setTitle()`（见 §4.4）。
> - `event.origin` 是 iframe 源站 Origin（`http://47.122.104.52:8081`），作为白名单校验即可；不需要也不能校验 iframe 内部子页面。
> - `event.source` 为 `WindowProxy`，在 iframe 尚未加载完成时为 null 的场景，`iframeRef.value` 存在但 `contentWindow` 可能为 null，判断写 `event.source !== iframeRef.value.contentWindow` 可容忍（null 不匹配则拒绝，联调时确认）。

## 7. 消息来源校验与允许的 Origin（回应 §5.5 / §6）

### 7.1 安全校验清单（主平台必须满足）

1. `event.source === 场景库 iframe.contentWindow`（不信任 `event.source` 之外的任何来源）；
2. `event.origin` 命中场景库 Origin 白名单：**`http://47.122.104.52:8081`**（当前 dev/prod 唯一源站）；
3. `data.type === 'scene-library:navigate'` 且 `protocolVersion === '1.0'`；
4. `target.path` 仅允许 `/three-model/detail`；
5. `target.query.id` 仅允许 `2326 | 2328 | 2316 | 2310`；
6. 消息监听在宿主组件卸载时 `removeEventListener`，防重复监听；
7. 连续点击遵循主平台 `addTab` 既有去重策略（同 path 复用标签）；
8. 导航异常 `catch` 后回 `failed` 结果并记录日志，不静默失败；
9. 不改主平台全局标签规则，只在宿主页增加最小适配；
10. 场景库不得操作父页面 DOM / 标签数组 / Pinia 状态（协议只传导航意图）。

### 7.2 环境与通信限制现状

- **CSP / frame-ancestors / X-Frame-Options**：主平台 `index.html` 与构建产物**均无** CSP、无 `frame-ancestors`、无 `X-Frame-Options`；场景库源站响应亦无（2026-08-17 实测）。当前**不限制 iframe 通信**。
- **sandbox**：iframe 未设 `sandbox` 属性，仅 `allow="fullscreen"` → 场景库内 postMessage 不受沙箱约束。
- **Referrer Policy**：未设置，无通信限制。
- **主平台 Origin**：dev `http://8.146.211.204:3100`；生产 `http://8.146.211.204`（80 端口，nginx）。场景库发消息的 `targetOrigin` 需按环境配置。
- **通信封装**：`src/utils/` 下无 iframe 通信工具/SDK/统一消息协议，本次从零新增最小化监听即可。

## 12. 待双方确认的开放问题

1. **场景库返回状态保留**：场景库路由 `ignoreKeepAlive: true`，从"场景库"标签切到模型详情再返回时 iframe 会重新加载（回到驾驶舱默认页），**不保留切走前的内部页面状态**（需求 §3.1-5 期望"返回之前的场景页面"）。若需保留，选项：(a) 接受重新加载；(b) 去掉 `ignoreKeepAlive` 让组件/iframe 被 keep-alive 缓存（代价：WebGL/轮询资源常驻内存，需重评估）；(c) 场景库恢复"独立版自持深链/内部导航状态还原"。**请场景库团队确认期望。**
2. **独立/嵌入模式识别**：推荐主平台宿主加载后向 iframe 发送握手消息（如 `scene-library:host-ready`），场景库"收到握手=嵌入模式、未收到=独立模式"，比 `window.parent !== window` 更可靠（避免被其它站点 iframe 误判）。请双方确认握手消息格式。
3. **`router.push` 后是否需要等待**：主平台 `router.push` 是异步的，导航可能因权限守卫被重定向（如登录失效）。场景库侧建议以 `navigate-result` 为准，超时（如 5s）未收到响应给出降级提示。
4. **modelName 动态标题**：若采用，需确认由主平台详情页自行按 ID 取名（推荐，无需协议扩展），还是由场景库随请求携带。
5. **生产路由来源**：确认生产环境 `/three-model/detail` 是否由 Jeecg 后台菜单动态生成，其 `meta.title`/keepAlive 配置以菜单为准（§3.2 注）。
6. **线上 URL 形态**：`docs/scene-library-integration.md` 曾写 hash 路由，与源码 history 模式不符。联调时以实际部署 URL（`http://8.146.211.204/...` 无 `#`）为准核对。
