# 主平台场景库加载稳定性与导航计数需求

> 文档版本：`1.0`
>
> 编写日期：2026-09-09
>
> 接收方：主平台 `ices-union` 开发、测试与部署维护人员
>
> 关联场景库：`industrial-intelligent-cockpit`
>
> 需求状态：待主平台实施与双方联合验收

## 1. 需求目的

本次变更解决主平台“场景库”栏目下页面偶发空白、首次进入或重新进入响应缓慢的问题，并为“场景库”导航分支增加页面数量展示。

本需求只允许影响主平台的“场景库”一级导航及其全部后代节点。主平台的首页、模型库及其他业务导航不得出现计数徽标、样式变化、交互变化或性能回归。

## 2. 已确认现状

### 2.1 场景库入口解析错误

线上主平台访问 `/scene-library` 时，iframe 实际曾被解析为：

```text
https://8.146.211.204:3100/cockpit/?embedded=1&viewId=<viewId>
```

该地址落在主平台自身 Origin。主平台没有把 `/cockpit/` 完整代理到场景库服务，服务器又将未知路径回退为主平台 HTML，因此 iframe 会得到 HTTP 200，但加载的不是场景库应用，表现为无明确报错的空白页面。

场景库当前正式入口为：

```text
https://47.122.104.52/cockpit/
```

### 2.2 重复加载成本过高

主平台当前场景库路由配置曾使用 `ignoreKeepAlive: true`。离开再返回时 iframe 会销毁并重新创建，场景库入口、JavaScript 和当前三维模型均需重新初始化。

场景库生产入口 JavaScript 当前约 13.64 MB。线上响应未提供压缩编码，入口 JavaScript/CSS 也未提供适合带哈希静态资源的长期缓存头。三维模型文件已有版本化长期缓存，但无法抵消 iframe 应用壳反复加载的成本。

### 2.3 外部同步脚本会阻塞页面挂载

场景库当前生产 HTML 同步加载 `https://cdn.tailwindcss.com`，并引用 Google Fonts。外部网络波动时，同步脚本会推迟 DOMContentLoaded 和 React 挂载，形成长时间空白。

该项主要由场景库项目整改；若主平台采用同源代理模式，则主平台网关还需保证不重新注入、替换或阻塞场景库资源。详见第 7 节责任边界。

### 2.4 全量检查基线

2026-09-09 对 106 个外部模型页面进行生产浏览器检查：

- 106 个页面最终均完成三维渲染，未发现永久失效的模型文件；
- 场景接口预热后，中位响应约 236 ms，最慢约 524 ms；
- 四页面并发检查时，模型完成中位时间约 1.34 s，最慢约 19.84 s；
- 多个页面出现 10 s 以上首屏或模型等待，主要与应用入口、外部 CDN、并发解析和重复初始化有关；
- `cv-flange-bolt-loosening` 上游没有提供监测字段，页面模型可显示，但运行参数需由场景库侧提供业务兜底；
- 少数 FBX 存在材质或贴图兼容警告，但本轮均可渲染。

## 3. 主平台必须完成的加载稳定性变更

### 3.1 修正场景库入口

推荐采用源站直连模式，在主平台生产环境设置：

```env
VITE_GLOB_SCENE_LIBRARY_ENTRY=https://47.122.104.52/cockpit/
```

iframe 地址必须使用 URL API 生成，不得直接拼接字符串：

```ts
function buildSceneLibraryUrl(entry: string, viewId: string): string {
  const url = new URL(entry, window.location.href);
  url.searchParams.set('embedded', '1');
  url.searchParams.set('viewId', viewId);
  return url.toString();
}
```

生产构建后必须核验运行时配置，不能只检查 `.env` 源文件。最终 `iframe.src` 必须满足以下任一条件：

1. Origin 为 `https://47.122.104.52`；
2. Origin 为主平台，但已经按 3.2 节配置真实、完整的同源反向代理。

如果入口仍为相对路径且没有启用代理，主平台应在创建 iframe 前判定为配置错误，进入主平台自己的业务化异常页，不得继续加载主平台 HTML 形成无提示空白。

### 3.2 同源代理备选方案

如因安全策略必须使用主平台同源地址，则需要完整代理以下路径：

```text
/cockpit/             -> 场景库 standalone HTML
/cockpit/assets/      -> 场景库带哈希静态资源
/scene-library-api/   -> 场景库 API
```

要求：

- 不得把上述路径交给主平台 SPA fallback；
- 保留查询参数、状态码、`Content-Type`、`ETag`、`Last-Modified`、`X-Model-Version`；
- 模型流不得被网关截断，不得设置小于 50 MiB 的响应体限制；
- API 超时与静态资源超时分开配置；
- `/cockpit/` HTML 使用协商缓存或 `no-cache`，避免引用旧哈希文件；
- `/cockpit/assets/*` 带哈希文件使用 `public, max-age=31536000, immutable`；
- JavaScript、CSS、JSON、SVG 开启 Brotli 或 gzip；
- `/scene-library-api/model-showcase/*/model` 保留场景库返回的版本化长期缓存策略。

### 3.3 调整 iframe 生命周期

主平台场景库容器应满足：

- 同一个场景库标签页只维护一个 iframe 实例；
- `frameKey` 只允许在用户明确点击“重试”时变化，不得绑定 `viewId`、时间戳或普通刷新状态；
- 在主平台标签页之间切换后返回场景库，不应无条件销毁 iframe；
- 移除场景库路由上的 `ignoreKeepAlive: true`，或为该路由实现等效的单实例保活；
- 保活范围只包含场景库容器，不得缓存所有业务 iframe；
- 主平台退出登录、关闭场景库标签页或释放路由时，必须正常销毁 iframe，避免 WebGL 长期占用；
- 页面跳转期间不得叠加创建多个 iframe，DOM 中场景库 iframe 数量始终不超过 1。

如果主平台因内存限制无法长期保活，应至少保证带哈希入口资源正确压缩和缓存，并在返回场景库时恢复原 `viewId`，不能回到默认首页。

### 3.4 加载状态与失败判定

iframe 的 `load` 事件只能说明文档完成加载，不能证明加载的是正确应用。主平台需同时完成：

- 创建 iframe 前校验入口 Origin 或代理模式；
- 保留 30 s 总加载超时和人工“重试”入口；
- 超时、网络失败、入口配置错误使用面向用户的业务提示，例如“场景库服务暂未完成连接，请稍后重试”；
- 详细 URL、代理状态和错误码只写入开发日志，不直接展示给普通用户；
- 失败时不得循环自动重建 iframe；最多自动重试一次，其余由用户触发；
- 查询参数 `viewId` 无效时回到 `defaultViewId`，但必须记录告警供维护人员排查。

## 4. 场景库导航计数需求

### 4.1 生效范围

仅对以下树生效：

```text
主平台导航
└─ 场景库                  显示全部可访问页面总数
   ├─ 工业智能运维          显示本分类可访问页面数
   ├─ 工业产品知识库        显示本分类可访问页面数
   ├─ ...
   └─ 维修培训              显示本分类可访问页面数
```

禁止事项：

- 不得修改主平台全局菜单节点类型或默认渲染效果；
- 不得让首页、模型库或场景库以外的栏目显示计数；
- 不得给叶子页面显示 `0` 或 `1` 徽标；
- 不得硬编码 20 个分类和固定数量；
- 不得直接复制 React 独立版 `Sidebar.tsx`，主平台应按 Vue 3、Ant Design Vue 和现有菜单组件实现。

推荐通过“场景库专用菜单组件”实现；如果必须复用主平台公共菜单组件，应增加默认关闭的显式属性，例如 `showDescendantCount`，并且只在场景库根节点传入 `true`。相关 CSS 必须以场景库容器类名作为作用域。

### 4.2 唯一数据源

计数唯一数据源为本次交付的：

```text
主平台统一导航拆分方案-20260820/scene-library-menu.manifest.json
```

当前基线：

```text
schemaVersion: 1.0
menuVersion: 20260909-083801
根分类数: 20
manifest totalNodeCount: 1050
SHA-256: 15AD4ABA2715525DAF0ADDBB48452F2D45F4825C7867CE9A89C37BA821DD8195
```

主平台现有导入逻辑会为每个根分类生成一个位于首位的“首页”子菜单，并沿用根节点 `viewId`。因此：

- manifest 根节点在主平台中转化为对应分类的“首页”页面；
- `totalNodeCount=1050` 恰好对应主平台场景库下 1,050 个可访问页面；
- 独立版侧栏当前显示的 1,030 个叶子页面不适合作为主平台总数，因为它没有把 20 个分类首页计入总数；
- 主平台不得在导入后再次把分类节点和其首页重复计数。

### 4.3 统计规则

对每个启用的 manifest 根节点，统计其整个子树中 `enabled !== false` 的节点数量。根节点自身计为 1，对应主平台合成的“首页”。

```ts
interface SceneMenuNode {
  viewId: string;
  enabled?: boolean;
  children?: SceneMenuNode[];
}

function countEnabledPages(node: SceneMenuNode): number {
  if (node.enabled === false) return 0;
  return 1 + (node.children ?? []).reduce(
    (sum, child) => sum + countEnabledPages(child),
    0,
  );
}

const categoryCount = countEnabledPages(manifestRoot);
const sceneLibraryTotal = manifest.items.reduce(
  (sum, root) => sum + countEnabledPages(root),
  0,
);
```

补充规则：

- 被禁用的节点及其后代均不计数、不展示；
- 同一个 `viewId` 只能计数一次，发现重复应拒绝导入而不是静默去重；
- 计数在 manifest 导入或更新时计算，不对当前 DOM 数量进行统计；
- 搜索、折叠、权限过滤不应修改“目录总页面数”；如果主平台未来需要显示“当前用户可访问数”，必须另立需求并使用不同文案；
- 数字采用千位分隔，当前显示 `1,050`，不得显示 `999+` 或约数；
- manifest 更新后计数自动更新，不需要修改 Vue 模板中的常量。

### 4.5 视觉与交互要求

计数应作为辅助信息，不能抢占导航名称的视觉层级。

推荐表现：

- “场景库”一级节点右侧使用略强的紧凑徽标：`总计 1,050`；
- 每个可展开分类右侧使用低对比度数字徽标，例如 `21`；
- 分类徽标悬停提示：`含分类首页，共 21 个页面`；
- 叶子页面不显示计数徽标；
- 徽标使用主平台现有蓝灰色体系，激活态跟随当前导航高亮色；
- 使用 `font-variant-numeric: tabular-nums`，给徽标设置稳定的最小宽度，展开箭头位置不得因数字位数变化而跳动；
- 长菜单名称优先保证名称可读，徽标不可覆盖、省略或挤出容器；
- 折叠侧栏中可隐藏分类数字，但“场景库”图标悬停浮层必须显示总数；
- 所有计数应有 `aria-label` 或等效可访问文本，不能只依赖颜色表达；
- 不增加闪烁、滚动数字或持续动画；计数随 manifest 更新时可使用一次轻量淡入。

独立平台的 `components/Sidebar.tsx` 仅可用于理解“计数徽标”的视觉意图。其 `children.length` 与叶子递归总计逻辑不符合主平台合成“首页”后的统计口径，不得照搬。

## 5. 页面描述展示要求

主平台不得读取或展示 manifest 配对过程中的 `note`、`adaptation`、源文件名或模型维护说明。页面标题下的说明由场景库页面自身提供，主平台只负责正确加载，不得用模型接口的原始 `model_description` 覆盖。

用户界面中不得出现以下类型信息：

- “替换上游端点”“不再返回有效 FBX”“文件头已核验”等开发过程；
- “运行时近黑”“模型不能支撑”“已停用”等缺陷处置过程；
- 内部路径、IP、异常堆栈和自动重试细节；
- `12-Track_Drill`、`Kitbash3D` 等未经业务化处理的资产名称。

场景库侧将继续把批量模板文案调整为对应设备、监测参数、关键部件和风险信息。主平台验收时只需确认没有覆盖场景库文案，并使用当前场景库发布版本。

## 6. 性能目标与验收方法

### 6.1 响应目标

在 20 Mbps 下行、100 ms RTT、Chrome 无扩展环境中：

- 场景库容器和页面标题首次可见：P95 不超过 3 s；
- 已缓存后重新进入同一场景：P95 不超过 1.5 s；
- 普通小于 10 MiB 的模型完成显示：P95 不超过 5 s；
- 10–50 MiB 模型必须持续显示真实下载/解析进度，不得出现无反馈空白；
- 任何失败状态应在 30 s 内结束等待并提供一次确认式重试入口。

### 6.2 主平台功能验收

1. 打开 `/scene-library?viewId=eq-0`，确认 iframe Origin 正确且出现水轮机页面。
2. 依次访问 `eq-0`、`eq-1`、`eq-2`、`eq-3`，每页标题、三维模型和运行区均可进入。
3. 连续往返切换上述页面两轮，场景库区域始终只有一个 iframe、每个三维页只有一个 canvas。
4. 切到主平台其他标签页后返回，恢复离开前的 `viewId`，不回到默认首页。
5. 人工填入错误入口，主平台显示业务化连接提示，不出现长期空白或主平台页面套主平台页面。
6. 检查网络响应：带哈希 JS/CSS 命中压缩和长期缓存，HTML 不引用不存在的旧哈希文件。

### 6.3 导航计数验收

1. “场景库”显示 `总计 1,050`。
2. 20 个分类数字与 4.4 节完全一致。
3. 分类首页计入分类数字且不重复计数。
4. 叶子页面不显示 `0`/`1` 徽标。
5. 更新一份测试 manifest：新增、禁用、删除节点后，计数自动变化。
6. 场景库以外所有主平台导航截图与变更前一致。
7. 在常用侧栏宽度、折叠态、125% 和 150% 缩放下，文字、计数和展开箭头无重叠。

| 事项 | 主平台 | 场景库 |
|---|---|---|
| `VITE_GLOB_SCENE_LIBRARY_ENTRY` 正确生效 | 负责 | 提供正式入口 |
| iframe 容器、保活、重试和主平台路由恢复 | 负责 | 配合联调 |
| 同源反向代理、压缩和缓存 | 选择同源方案时负责 | 提供响应头与版本信息 |
| 场景库专属导航计数 | 负责 | 提供 manifest 与基线数量 |
| 其他主平台导航不受影响 | 负责 | 不涉及 |
| 移除 Tailwind CDN、构建拆包 | 不改写场景库产物 | 负责 |
| 页面业务描述与模型字段兜底 | 不覆盖、不二次拼装 | 负责 |
| 联合浏览器验收 | 共同负责 | 共同负责 |

主平台不得通过复制场景库源代码、修改场景库构建产物或硬编码 1,050 来规避接口、代理和 manifest 接入要求。

## 8. 发布与回滚要求

- 主平台提交中应将入口修正、iframe 生命周期、导航计数分别记录，便于独立回滚；
- 发布前记录主平台 commit、场景库 `menuVersion`、manifest SHA-256 和场景库 Release ID；
- 先在测试环境完成第 6 节，再进入生产；
- 入口配置回滚不得恢复到无真实代理的相对 `/cockpit/`；
- 导航计数出现问题时，只允许关闭场景库分支的计数开关，不得回滚或影响主平台全局导航组件；
- 生产发布后至少观察 30 分钟，检查 iframe 超时、静态资源 404、模型请求 5xx、重复 iframe 和前端内存增长。
