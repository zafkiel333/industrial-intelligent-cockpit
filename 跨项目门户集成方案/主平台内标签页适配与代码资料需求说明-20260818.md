# 场景库模型详情跳转与主平台内标签页适配需求说明

> 文档用途：提供给主平台开发人员，用于说明场景库需要实现的跳转效果，并请求主平台提供完成适配所需的具体代码与接口说明。  
> 编写日期：2026-08-18  
> 涉及系统：主平台（当前访问地址 `http://8.146.211.204:3100`）与工业智能驾驶舱/场景库项目  
> 当前集成方式：主平台通过 `iframe` 集成场景库页面，不采用 qiankun 作为本次功能的实现前提。

## 1. 背景与问题

场景库最初是一个可独立访问的前端项目。仿真分析菜单最前面的四个页面需要与主平台模型库通信并展示远端模型、运行数据及分析结果。四个页面同时提供“查看资源详情”入口，用于打开主平台中的对应模型详情页。

当前入口采用普通超链接并设置 `target="_blank"`，点击后会创建新的**浏览器标签页**。现在场景库已经集成到主平台中，继续创建浏览器标签会破坏主平台现有的页内多标签体验。因此，需要将这四个页面的模型详情跳转接入主平台已有的路由和内标签页机制。

本需求中的三个概念必须严格区分：

| 概念 | 含义 | 本需求中的处理 |
|---|---|---|
| 浏览器标签页 | Chrome、Edge 等浏览器顶部的标签 | 不允许新建 |
| 主平台内标签页 | 主平台顶部显示的“首页、部门管理、职务级别”等小标签 | 开关开启时使用 |
| iframe 页内页 | 在主平台内容区内嵌另一个完整页面 | 仅用于场景库集成本身，不用于承载跳转后的模型详情页 |

## 3. 期望实现效果

### 3.1 主平台内标签页开关开启

用户在主平台的“场景库”页面中进入上述任意一个仿真页面，并点击“查看资源详情”后：

1. 不创建新的浏览器标签页或浏览器窗口；
2. 主平台调用自己的模型详情路由，例如 `/three-model/detail?id=2326`；
3. 主平台现有内标签页栏新增或激活一个模型详情标签；
4. 新标签中显示主平台原生模型详情页面，不再套一层场景库 iframe；
5. 原“场景库”内标签应继续保留，用户可以点击该标签返回之前的场景页面；
6. 模型详情标签的标题、缓存、去重、关闭和切换行为，应遵循主平台现有内标签页规则；
7. 如果相同模型详情已打开，应遵循主平台现有策略激活或复用已有标签，避免由场景库自行维护第二套标签状态。

期望流程：

```text
主平台“场景库”内标签
        ↓ iframe 中点击“查看资源详情”
场景库向主平台提交受控导航请求
        ↓
主平台确认内标签页开关已开启
        ↓
主平台使用现有 Router / Tabs 机制打开模型详情
        ↓
内标签栏保留“场景库”，新增或激活“模型详情”
```

### 3.2 主平台内标签页开关关闭

用户执行相同点击操作后：

1. 不创建新的浏览器标签页或浏览器窗口；
2. 当前浏览器标签直接导航至目标模型详情路由；
3. 浏览器地址应变为对应的 `/three-model/detail?id=<modelId>`；
4. 场景库 iframe 页面退出当前显示区域，主平台原生模型详情路由成为当前页面内容；
5. 目标页面应呈现为用户在主平台中直接点击该模型详情链接时的正常页面形态；
6. 不允许在场景库内部再嵌套一个模型详情 iframe、弹窗、抽屉或其他“页内页”；
7. 主平台自身的顶部栏、侧边栏等是否保留，以主平台直接访问该路由时的现有表现为准。

期望流程：

```text
主平台“场景库”页面
        ↓ iframe 中点击“查看资源详情”
场景库向主平台提交受控导航请求
        ↓
主平台确认内标签页开关已关闭
        ↓
主平台在当前浏览器标签中直接进入模型详情路由
        ↓
当前内容替换为主平台原生模型详情页面
```

### 3.3 开关适配原则

- 内标签页开关的真实状态由主平台掌握，场景库不复制或猜测该配置；
- 每次点击时均以主平台当前有效配置为准，兼容配置在运行期间发生变化；
- 推荐场景库只发送统一的“打开模型详情”请求，由主平台决定使用内标签还是普通同页路由；
- 如果主平台现有 `router.push` 本身已经能在开关开启时触发内标签、关闭时只切换内容，则宿主只需统一调用该现有方法，不需要写两套重复逻辑；
- 场景库不得直接读写主平台的 Pinia/Vuex 状态或标签数组，避免两个项目强耦合。

## 4. 推荐的跨 iframe 协作方式

由于场景库位于 iframe 中，且主平台路由和内标签状态属于父页面，推荐由主平台提供一个受控的父子页面通信入口。可优先采用浏览器标准 `window.postMessage`；如果主平台已有成熟的 iframe 通信封装，应复用现有封装。

推荐职责分工：

| 参与方 | 职责 |
|---|---|
| 场景库 iframe | 在用户点击时发送模型详情导航请求，不自行操作主平台标签状态 |
| 主平台宿主页 | 校验消息来源、模型 ID 和目标路由，然后调用主平台现有导航方法 |
| 主平台 Router/Tabs | 根据当前内标签开关执行新增内标签或普通同页跳转 |

### 4.1 建议的请求消息

以下仅为双方确认接口时的建议格式，最终字段名可按主平台规范调整，但语义需完整保留：

```ts
interface SceneLibraryNavigateRequest {
  type: 'scene-library:navigate';
  protocolVersion: '1.0';
  requestId: string;
  source: 'scene-library';
  target: {
    path: '/three-model/detail';
    query: {
      id: '2326' | '2328' | '2316' | '2310';
    };
  };
  // 表示由宿主依据当前开关选择内标签或普通同页路由。
  openMode: 'host-default';
}
```

请求示例：

```ts
window.parent.postMessage(
  {
    type: 'scene-library:navigate',
    protocolVersion: '1.0',
    requestId: crypto.randomUUID(),
    source: 'scene-library',
    target: {
      path: '/three-model/detail',
      query: { id: '2326' },
    },
    openMode: 'host-default',
  },
  MAIN_PLATFORM_ORIGIN,
);
```

`MAIN_PLATFORM_ORIGIN` 必须是明确的主平台 Origin，不应在正式环境中使用 `'*'`。

### 4.2 建议的处理结果消息

建议主平台返回处理结果，以便场景库在路由被拒绝或发生异常时给出提示，而不是让用户点击后没有反馈：

```ts
interface SceneLibraryNavigateResult {
  type: 'scene-library:navigate-result';
  protocolVersion: '1.0';
  requestId: string;
  status: 'accepted' | 'rejected' | 'failed';
  mode?: 'multi-tab' | 'same-page';
  message?: string;
}
```

场景库不得在请求失败时退回 `window.open(..., '_blank')`，因为这会重新引入本次需要消除的浏览器新标签行为。失败时应显示明确提示并记录日志。

### 4.3 主平台处理逻辑示意

以下是逻辑示意，不要求主平台照抄；请主平台开发人员提供符合实际工程结构的代码：

```ts
function handleSceneLibraryMessage(event: MessageEvent) {
  // 1. 校验 event.source 必须是当前场景库 iframe.contentWindow；
  // 2. 校验 event.origin 必须是已配置的场景库来源；
  // 3. 校验消息类型和协议版本；
  // 4. 仅允许 /three-model/detail；
  // 5. 仅允许模型 ID 2326、2328、2316、2310；
  // 6. 调用主平台已有导航函数。

  const target = {
    path: '/three-model/detail',
    query: { id: event.data.target.query.id },
  };

  // 理想情况：该调用由主平台现有机制自动适配内标签开关。
  router.push(target);
}
```

如果主平台必须显式区分开关，可按实际 API 处理：

```ts
if (isMultiTabsEnabled()) {
  openInPlatformTab(target);
} else {
  router.push(target);
}
```

其中 `isMultiTabsEnabled`、`openInPlatformTab` 和 `router.push` 的真实来源、签名及调用上下文，正是本次需要主平台提供的代码资料。

## 6. 安全与稳定性要求

主平台接收 iframe 导航请求时必须满足：

1. 校验 `event.source` 是当前场景库 iframe 的 `contentWindow`；
2. 校验 `event.origin` 属于配置的场景库 Origin 白名单；
3. 不接受任意 URL，只允许固定路由 `/three-model/detail`；
4. 只允许模型 ID：`2326`、`2328`、`2316`、`2310`；
5. 不允许消息携带 `javascript:`、协议相对地址或任意外部域名；
6. 消息监听器必须在宿主组件卸载时清理，避免重复监听；
7. 连续点击时应遵循主平台现有标签去重策略；
8. 导航异常应可记录和提示，不应静默失败；
9. 不修改主平台全局标签规则，只在场景库宿主页增加最小适配；
10. 不允许场景库直接操纵父页面 DOM、标签数组或状态仓库。

## 7. 兼容与降级要求

### 7.1 场景库在主平台 iframe 中运行

必须使用主平台提供的宿主导航接口，由主平台决定内标签或同页导航。不得使用 `_blank`。

### 7.2 场景库独立访问

场景库仍可能通过独立地址打开。此时没有父级主平台通信接口，四个入口应在**当前浏览器标签**直接打开完整模型详情地址，可使用 `window.location.assign(detailUrl)` 或普通 `_self` 导航；不得创建新的浏览器标签。

独立模式与嵌入模式的识别方式需双方确认，优先使用显式运行配置或宿主握手信息；如果使用 `window.parent !== window`，应说明其适用条件。

### 7.3 宿主接口不可用

嵌入模式下，如果主平台未响应或拒绝请求：

- 场景库显示“暂时无法打开模型详情，请联系管理员或稍后重试”；
- 记录 requestId、模型 ID 和失败原因；
- 不自动创建浏览器新标签；
- 是否允许用户手动选择“在当前页打开”，需由双方另行确认，不能默认扩大跳转行为。
