## 1. 文档目的和实施边界

本文指导主项目完成“场景库”的开发接入、网关代理、部署、联调、验收和回滚。

主项目需要接入的只有：

1. 场景库 qiankun 微应用；
2. 场景库 API；
3. 主项目自己的菜单、路由、权限、标签页、面包屑和监控体系。

本项目自用的独立版不属于本次主项目交付范围。主项目不得用 iframe 或外链跳转替代 qiankun 正式集成，也不需要复制场景库 React 源码、静态文件或 Express 业务代码。

双方源码、构建和发布保持独立：

- 场景库团队负责场景库微应用和 API 源站；
- 主项目团队负责自己的容器页、路由、权限和同源网关；
- 主项目只消费已发布的版本化接口和微应用产物。

## 4. 主项目目标架构

```text
用户浏览器
  │
  └─ https://<MAIN_DOMAIN>/scene-library?view=<viewId>
       │
       ├─ 主项目 Vue 3 页面、导航、权限、标签页和错误处理
       │    └─ qiankun 容器挂载 industrial-intelligent-cockpit
       │
       ├─ /microapps/scene-library/
       │    └─ 主项目 Nginx/网关
       │         └─ http://47.122.104.52:8081/microapps/scene-library/
       │
       └─ /scene-library-api/
            └─ 主项目 Nginx/网关
                 └─ http://47.122.104.52:8081/scene-library-api/
                      └─ 场景库源站内部 127.0.0.1:3102/api/
```

关键原则：

- 浏览器侧同源，避免 CORS、Cookie 和 CSP 对接复杂度；
- 主项目只代理稳定公开路径，不感知源站内部 `3102`；
- 微应用和 API 的路径原样保留，避免入口脚本和运行时请求错位；
- 场景库故障不得阻断主项目其他菜单；
- 正常集成不使用 iframe。

## 5. 主项目前端调整

### 5.1 先复用现有微前端基础设施

既往资料表明主项目使用 Vue 3、Vue Router、Pinia、Ant Design Vue 和 Vite，并已有 qiankun 基础设施。实施时应先定位并复用现有：

- 微应用注册或 `loadMicroApp` 封装；
- 公共加载中、错误页和重试组件；
- 菜单/权限数据源；
- 标签页与页面缓存规则；
- 全局路由守卫；
- 请求追踪、前端异常和性能上报；
- 环境变量和运行时配置加载方式。

不要在场景库容器页再初始化第二套 qiankun 全局配置。若现有封装与下文示例命名不同，以主项目现有约定为准，但冻结路径和 props 协议不得改变。

### 5.2 建议的运行配置

推荐把参数放进主项目现有运行时配置，而不是散落在组件中：

```ts
export interface SceneLibraryConfig {
  enabled: boolean;
  name: 'industrial-intelligent-cockpit';
  route: '/scene-library';
  entry: '/microapps/scene-library/';
  apiBase: '/scene-library-api/';
  protocolVersion: '1.0';
  loadTimeoutMs: number;
}

export const sceneLibraryConfig: SceneLibraryConfig = {
  enabled: true,
  name: 'industrial-intelligent-cockpit',
  route: '/scene-library',
  entry: '/microapps/scene-library/',
  apiBase: '/scene-library-api/',
  protocolVersion: '1.0',
  loadTimeoutMs: 30_000,
};
```

环境差异只应体现在主项目网关的上游地址或功能开关中。浏览器侧 `entry` 和 `apiBase` 在各环境都保持同源相对路径。

### 5.3 菜单、权限和路由

建议新增一个主项目一级菜单：

| 属性 | 建议值 |
|---|---|
| 名称 | `场景库` |
| 路由 | `/scene-library` |
| 默认打开 | `/scene-library?view=smart-ops` |
| 组件 | 主项目新增的场景库容器页 |
| 权限码 | 按主项目规则新增，例如 `scene-library:view` |
| 标签页标题 | `场景库` |
| 面包屑 | `场景库`，可追加当前子页面标题 |

不要把场景库的所有内部子页面复制成主项目菜单。场景库内部仍有自己的紧凑导航；主项目若确需增加少量快捷入口，只需指向同一路由并改变 `view`：

```text
/scene-library?view=smart-ops
/scene-library?view=simulation
/scene-library?view=predictive-maintenance
```

Vue Router 示例：

```ts
{
  path: '/scene-library',
  name: 'SceneLibrary',
  component: () => import('@/views/scene-library/SceneLibraryHost.vue'),
  meta: {
    title: '场景库',
    permission: 'scene-library:view',
  },
}
```

实际路径、组件目录、权限码和菜单表字段必须服从主项目现有规范。

### 5.4 容器页职责

容器页只负责：

- 提供稳定且唯一的挂载 DOM；
- 检查功能开关和权限；
- 管理加载、成功、错误、重试状态；
- 向微应用传递协议 props；
- 同步 `route.query.view` 与微应用内部导航；
- 页面离开时卸载微应用；
- 上报加载时间、错误和当前版本。

容器页不得读取或修改微应用内部 React DOM，也不得向微应用传递主项目 Pinia、Router 实例或认证对象。

### 5.5 qiankun props 契约

```ts
interface SceneLibraryHostProps {
  protocolVersion: '1.0';
  container: Element;
  viewId?: string;
  apiBase?: string;
  locale?: 'zh-CN';
  theme?: Record<string, string>;
  visible?: boolean;
  navigate?: (viewId: string, title?: string) => void;
  reportStatus?: (status: { state: string; message?: string }) => void;
}
```

强制要求：

- `protocolVersion` 必须严格等于 `'1.0'`；
- `container` 必须是当前真实存在的 `Element`；
- `apiBase` 必须传 `/scene-library-api/`；
- `apiBase` 不允许传绝对 URL、协议相对 URL、反斜杠路径或非根路径；
- `theme` 的键只允许以 `--` 开头；
- 非法或不存在的 `viewId` 会回退到 `smart-ops`。

### 5.6 Vue 3 容器示例

以下代码展示必要控制流，主项目应把它适配到已有 qiankun 封装、错误组件和监控接口中：

```vue
<template>
  <section class="scene-library-page">
    <a-spin v-if="state === 'loading'" tip="场景库加载中……" />

    <a-result
      v-else-if="state === 'error'"
      status="error"
      title="场景库加载失败"
      :sub-title="errorMessage"
    >
      <template #extra>
        <a-button type="primary" @click="retry">重试</a-button>
      </template>
    </a-result>

    <div
      ref="containerRef"
      class="scene-library-container"
      :class="{ 'is-ready': state === 'ready' }"
    />
  </section>
</template>

<script setup lang="ts">
import { nextTick, onBeforeUnmount, onMounted, ref, watch } from 'vue';
import { useRoute, useRouter } from 'vue-router';
import { loadMicroApp, type MicroApp } from 'qiankun';

const APP_NAME = 'industrial-intelligent-cockpit';
const ENTRY = '/microapps/scene-library/';
const API_BASE = '/scene-library-api/';
const DEFAULT_VIEW = 'smart-ops';

const route = useRoute();
const router = useRouter();
const containerRef = ref<HTMLElement | null>(null);
const state = ref<'loading' | 'ready' | 'error'>('loading');
const errorMessage = ref('');
let parcel: MicroApp | null = null;

function currentViewId(): string {
  const value = route.query.view;
  return typeof value === 'string' && value ? value : DEFAULT_VIEW;
}

async function mountSceneLibrary(): Promise<void> {
  await nextTick();
  const container = containerRef.value;
  if (!container) throw new Error('场景库挂载容器不存在');

  state.value = 'loading';
  errorMessage.value = '';

  try {
    parcel = loadMicroApp(
      {
        name: APP_NAME,
        entry: ENTRY,
        container,
        props: {
          protocolVersion: '1.0',
          container,
          viewId: currentViewId(),
          apiBase: API_BASE,
          locale: 'zh-CN',
          visible: true,
          theme: {
            '--platform-brand': '#1677ff',
          },
          navigate: (viewId: string) => {
            void router.replace({
              path: '/scene-library',
              query: { ...route.query, view: viewId },
            });
          },
          reportStatus: (status: { state: string; message?: string }) => {
            if (status.state === 'ready') state.value = 'ready';
            if (status.state === 'error') {
              state.value = 'error';
              errorMessage.value = status.message || '微应用报告未知错误';
            }
          },
        },
      },
      {
        sandbox: {
          experimentalStyleIsolation: true,
        },
      },
    );

    await parcel.mountPromise;
    state.value = 'ready';
  } catch (error) {
    state.value = 'error';
    errorMessage.value = error instanceof Error ? error.message : String(error);
    // 在此调用主项目现有异常上报接口。
  }
}

async function unmountSceneLibrary(): Promise<void> {
  const current = parcel;
  parcel = null;
  if (current) await current.unmount();
  if (containerRef.value) containerRef.value.replaceChildren();
}

async function retry(): Promise<void> {
  await unmountSceneLibrary();
  await mountSceneLibrary();
}

watch(
  () => route.query.view,
  async () => {
    if (!parcel) return;
    await parcel.update({
      protocolVersion: '1.0',
      container: containerRef.value!,
      viewId: currentViewId(),
      apiBase: API_BASE,
    });
  },
);

onMounted(() => {
  void mountSceneLibrary();
});

onBeforeUnmount(() => {
  void unmountSceneLibrary();
});
</script>

<style scoped>
.scene-library-page,
.scene-library-container {
  width: 100%;
  min-width: 0;
  height: 100%;
  min-height: 0;
}

.scene-library-container {
  overflow: hidden;
}
</style>
```

注意事项：

- 主项目现有 qiankun 版本若没有导出 `MicroApp` 类型，可使用项目已有类型或只对所需方法定义本地接口；
- 若主项目统一通过 `registerMicroApps/start` 管理，不要混用另一套重复注册；应把相同 props 和容器职责放入现有包装层；
- `onBeforeUnmount` 不等待异步函数完成，主项目若有标签页关闭钩子，应在其生命周期内等待 `unmount()`；
- 容器不可被 `v-if` 在加载过程中销毁；错误组件可覆盖显示，但挂载节点应保持稳定；
- 同一 DOM 容器只允许存在一个微应用实例；重试前必须先卸载旧实例；
- 不建议把场景库加入主项目 `keep-alive`。若必须缓存，需验证 WebGL 上下文、定时器、请求和内存释放。

### 5.7 路由同步规则

主项目地址是状态事实源：

```text
/scene-library?view=<viewId>
```

同步顺序：

1. 用户从主项目菜单进入，主项目读取 `view` 并作为初始 `viewId`；
2. 微应用内部切换页面时调用 `navigate(viewId, title?)`；
3. 主项目使用 `router.replace` 更新查询参数，避免每次内部切换堆叠浏览器历史；
4. 用户前进、后退或从快捷链接进入时，主项目监听查询参数并调用 `parcel.update`；
5. 查询参数缺失或非法时，微应用回退到 `smart-ops`；主项目可把 URL 归一化为该值。

### 5.8 主题和样式隔离

主题示例：

```ts
theme: {
  '--platform-brand': '#1677ff',
  '--platform-page': '#e8eff4',
  '--platform-surface': '#f8fafc',
  '--platform-text': '#1f2937',
}
```

规则：

- 只有以 `--` 开头的 CSS 自定义属性会被接收；
- 不传主题时使用场景库默认主题；
- 不要传 `{ primary, background }` 一类旧语义对象；
- 主项目可先启用 qiankun `experimentalStyleIsolation` 并完成全量视觉回归；
- 严格样式隔离、Shadow DOM 或自定义 CSS 转换可能影响弹层、固定定位、字体和 Three.js 画布尺寸，不能未经验证直接启用；
- 主项目全局样式应避免无命名空间的 `div`、`button`、`canvas`、`svg` 等强选择器。

### 5.9 加载状态、错误和监控

主项目至少需要区分：

- 微应用 HTML 入口失败；
- JavaScript/CSS 下载失败；
- 加载超时；
- 协议校验或挂载失败；
- API 4xx/5xx/超时；
- 模型大文件下载失败；
- 微应用运行时异常；
- 卸载失败或重复实例。

推荐上报字段：

```text
mainAppVersion
sceneLibraryVersion
route
viewId
entryUrl
apiPath
httpStatus
durationMs
errorName
errorMessage
userId（脱敏）
requestId / traceId
browser
occurredAt
```

错误页必须局限在场景库内容区，不能替换主项目全局布局或阻断其他路由。提供“重试”和“返回主项目首页”，不要自动无限重试。

## 6. 主项目网关/Nginx 调整

### 6.1 上线顺序

必须先部署并验证同源代理，再发布会访问这些路径的主项目前端。否则用户会看到微应用入口或 API 404。

建议顺序：

1. 主项目服务器验证能访问场景库源站；
2. 增加微应用静态资源代理；
3. 增加 API 代理；
4. 执行 `nginx -t`；
5. 平滑 reload；

### 6.3 Nginx 推荐配置

如果主项目可以修改 `http` 级配置，可在 `http {}` 中定义 upstream：

```nginx
upstream scene_library_origin {
    server 47.122.104.52:8081;
    keepalive 16;
}
```

然后在主项目 HTTPS `server {}` 中增加：

```nginx
# 规范化目录入口，避免相对资源解析错误。
location = /microapps/scene-library {
    return 308 /microapps/scene-library/;
}

# 保留完整原始 URI。proxy_pass 后不要附加 URI。
location ^~ /microapps/scene-library/ {
    proxy_pass http://scene_library_origin;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host cockpit;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_connect_timeout 10s;
    proxy_send_timeout 60s;
    proxy_read_timeout 60s;

    # HTML 入口和固定文件名产物不能长时间强缓存。
    expires -1;
    add_header Cache-Control "no-cache" always;
}

location = /scene-library-api {
    return 308 /scene-library-api/;
}

# 上传、诊断和模型下载均通过此路径。
location ^~ /scene-library-api/ {
    proxy_pass http://scene_library_origin;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host cockpit;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Request-ID $request_id;

    client_max_body_size 100m;
    proxy_connect_timeout 10s;
    proxy_send_timeout 180s;
    proxy_read_timeout 180s;
    proxy_request_buffering off;

    # 模型响应较大，先采用流式透传，降低网关磁盘临时文件压力。
    proxy_buffering off;
}
```

如果主项目不能在 `http {}` 中定义 upstream，可把两处 `proxy_pass` 改成：

```nginx
proxy_pass http://47.122.104.52:8081;
```

不能写成下列形式：

```nginx
# 错误示例：带 URI 的 proxy_pass 可能改写路径，导致源站 404。
proxy_pass http://47.122.104.52:8081/;
```

配置注意：

- 上述 `Host cockpit` 用于匹配场景库源站 Nginx 的虚拟主机；
- 如果主项目网关不是 Nginx，应实现等价的“原路径透传”；
- 主项目对公网使用 HTTPS 时，浏览器仍只请求 HTTPS 主域名，不会产生混合内容；
- 不要把源站内部端口 `3102` 暴露或配置到主项目；
- 若主项目已有统一请求 ID、鉴权和审计头，以现行网关规范为准；
- 当前源站 API 自身没有主项目级用户鉴权，正式开放前必须在主项目权限和网关层完成访问控制；
- 建议网络层只允许主项目网关访问源站 `8081`，不要长期对全网开放。

### 6.4 CSP 和第三方资源

当前微应用运行时依赖：

```text
https://cdn.tailwindcss.com
```

如果主项目部署了 Content-Security-Policy，需要在联调环境评估并配置相应 `script-src`/`connect-src`，否则可能出现页面样式异常或脚本被拦截。

该依赖不适合作为长期生产方案。建议场景库后续把 Tailwind 样式编译进自身 CSS；在完成前，主项目安全团队需要明确是否允许该 CDN。不要为了单一微应用把整个主站 CSP 放宽为不受限。

### 6.5 压缩和缓存

当前 UMD JavaScript 约 17.1 MiB，文件名固定为 `scene-library.js`。主项目网关应：

- 对 JS/CSS 开启 gzip 或 Brotli；
- 不要对入口 HTML 和固定文件名 JS/CSS 设置长期 immutable 缓存；
- 支持 `ETag` 或 `Last-Modified` 条件请求；
- 不要把大 JS 加入主项目首页 preload；
- 只在用户进入“场景库”时加载；
- 对模型二进制采用流式代理并设置足够超时；
- 观察首屏耗时、带宽、内存和 WebGL 上下文数量。

## 10. 故障定位

### 10.1 微应用入口 404

依次检查：

1. 主项目域名请求是否进入正确 `server` 块；
2. `location ^~ /microapps/scene-library/` 是否存在；
3. `proxy_pass` 是否错误附加 `/` 并改写 URI；
4. 主项目服务器是否能连接源站 `8081`；
5. 是否被主项目 SPA 的 `try_files` 回退成主项目 `index.html`。

### 10.2 JS 请求 200 但 qiankun 无法挂载

检查：

- JS 的 `Content-Type` 和实际内容是否正确；
- 浏览器控制台是否有 CSP、跨域或脚本执行错误；
- 应用名是否严格为 `industrial-intelligent-cockpit`；
- `protocolVersion` 是否为 `'1.0'`；
- `container` 是否为真实且未销毁的 Element；
- 是否在同一容器重复注册或挂载；
- qiankun 沙箱配置是否改变 UMD 全局对象读取。

微应用同时提供两个 UMD 全局名用于兼容：

```text
window['industrial-intelligent-cockpit']
window.IndustrialIntelligentCockpit
```

### 10.3 API 404

检查浏览器请求必须以主项目域名的 `/scene-library-api/` 开头。若请求了 `/api/`，说明 `apiBase` 未正确传入；若请求到源站 IP，说明主项目配置错误或场景库版本不匹配。

### 10.4 API 502/504

检查：

```bash
curl -v --max-time 15 \
  http://47.122.104.52:8081/scene-library-api/health
```

然后查看主项目 Nginx error log、upstream 状态、网络 ACL 和超时。若只有模型接口超时，提高代理读超时并确认 `proxy_buffering off`，同时让场景库运维检查 `scene-library.service` 日志。

### 10.5 页面有内容但样式异常

检查：

- `scene-library.css` 是否成功返回；
- `cdn.tailwindcss.com` 是否被 CSP、防火墙或浏览器插件拦截；
- 主项目是否存在强全局选择器；
- qiankun 样式隔离级别是否与测试环境一致；
- 容器是否具有非零高度。

### 10.6 页面切换后仍持续耗费资源

当前 `visible=false` 只控制显示，不保证暂停运行。检查主项目是否真正调用 `parcel.unmount()`、容器是否被正确清空以及是否因为 `keep-alive` 没有触发卸载。默认修复策略是离开路由即卸载，而不是仅隐藏。

## 11. 回滚方案

### 11.1 只回滚主项目前端入口

适用于场景库不稳定但主项目其他功能必须继续运行：

1. 关闭 `sceneLibrary.enabled`；
2. 隐藏菜单或展示维护提示；
3. 保留网关代理，便于运维继续健康检查；
4. 发布主项目配置或前端回滚版本；
5. 验证其他菜单、登录、标签页和权限不受影响。

### 11.2 回滚主项目版本

按主项目现有发布系统恢复上一版前端和菜单/权限配置。场景库源站是独立服务，不需要随主项目一起回滚或停止。

### 11.3 回滚 Nginx

只有确认主项目旧版本不再引用微应用和 API 路径后，才删除或回滚两个代理 `location`。执行：

```bash
nginx -t
systemctl reload nginx
```

回滚后验证主项目首页、登录、核心接口和其他微应用。不要因场景库回滚覆盖整个主项目 Nginx 配置文件；应恢复变更前备份或删除独立 include。
