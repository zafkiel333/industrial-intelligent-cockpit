## 0. 开发原因和目标

本项目需要与 Vue 主平台部署到同一服务器，并作为主平台“场景库”一级页面运行。两个项目不合并源码，主平台使用 qiankun 把本项目 React 页面挂载到自己的内容区域，正常流程不使用 iframe。

本项目需要做到：

- 同一套业务代码支持独立运行和 qiankun 微应用运行；
- 独立入口继续显示原顶部栏、原导航和原项目名称；
- 微应用模式隐藏重复品牌外壳，保留紧凑版原导航；
- 所有现有页面、3D、数据、上传、诊断、预测和报告继续使用；
- 在主平台路由切换时正确挂载、更新和完全卸载；
- 静态资源与 API 支持服务器子路径；
- 不读取主平台 DOM、Vue Router、Pinia 或数据库内部结构；
- 修改集中在应用外壳、入口、导航、API Base、构建和资源清理，尽量不改业务页面。

## 1. 主平台开发相关情况

主平台使用 Vue 3、Vue Router、Pinia、Ant Design Vue 和 Vite，具有自己的顶部栏、全局导航、权限、标签页和面包屑，并已有 qiankun 基础设施。

主平台将：

- 增加“场景库”菜单和 `/scene-library` 路由；
- 在路由内容区提供 qiankun 容器；
- 从 `/microapps/scene-library/` 加载本项目微应用；
- 通过 props 传入当前页面、API Base、主题、语言和回调；
- 通过 `/scene-library-api/` 访问本项目 Express；
- 负责主平台范围的权限、加载、错误和回退；
- 不复制本项目菜单和业务接口。

本项目必须保持宿主无关：除了明确的 qiankun props，不能依赖主平台内部实现。

## 3. 本项目负责与不负责的内容

### 3.1 本项目负责

- standalone/microapp 模式识别；
- qiankun `bootstrap/mount/update/unmount`；
- 共享 `AppCore` 和两种外壳；
- 紧凑导航；
- 页面 ID 同步；
- API Base 和静态资源子路径；
- 样式隔离；
- 3D、轮询、事件和请求的生命周期清理；
- Express、模型缓存和后端版本；
- 两种构建产物和本项目回退。

### 3.2 本项目不负责

- 不实现主平台全局导航和登录页；
- 不读取主平台 DOM、Pinia 或 Vue Router；
- 不修改主平台 URL，只调用主平台提供的 `navigate`；
- 不复制主平台用户对象和权限系统；
- 不把 Express 路由迁入主平台后端；
- 不维护第二份业务页面或第二份 `MENU_ITEMS`；
- 不把服务器 IP 写进前端代码；
- 不为了微前端批量改动诊断规则和数据结构。

## 4. 最小改造结构

建议把现有应用拆为外壳和业务核心：

```text
Application entry
├─ standalone
│  └─ StandaloneShell
│     ├─ 原顶部栏
│     ├─ 原 Sidebar
│     └─ AppCore
└─ qiankun microapp
   └─ MicroAppShell
      ├─ CompactSidebar
      ├─ 集成工具条（必要时）
      └─ AppCore
```

`AppCore` 继续持有或接收：

- `activeTabId`；
- 现有页面渲染逻辑；
- 场景日志、弹窗和业务状态；
- 与页面内容有关的上下文。

不要把整个 `App.tsx` 复制成两个版本。独立和微应用模式只在外壳层分叉。

## 5. 运行模式识别

优先使用 qiankun 提供的运行标志或适配器，不只依赖 URL 参数：

```ts
type RuntimeMode = 'standalone' | 'microapp';

interface RuntimeConfig {
  mode: RuntimeMode;
  publicBase: string;
  apiBase: string;
  defaultViewId: string;
  protocolVersion: '1.0';
}
```

规则：

- qiankun 调用生命周期时为 `microapp`；
- 用户直接打开独立 HTML 时为 `standalone`；
- standalone 缺少主平台 props 也必须正常运行；
- microapp 不允许通过普通查询参数伪装为已授权宿主；
- API Base 可由构建配置提供，主平台 props 只能在允许的同源路径范围内覆盖。

## 6. qiankun 生命周期

### 6.1 必须提供的生命周期

```ts
export async function bootstrap(): Promise<void>;
export async function mount(props: SceneLibraryHostProps): Promise<void>;
export async function update(props: Partial<SceneLibraryHostProps>): Promise<void>;
export async function unmount(props: SceneLibraryHostProps): Promise<void>;
```

若采用的 Vite/qiankun 适配器导出形式不同，可按其已验证方式实现，但必须满足相同行为。

### 6.2 bootstrap

- 只执行一次性注册；
- 不创建 React Root；
- 不访问尚不存在的宿主容器；
- 不启动轮询、3D、模型更新或全局监听；
- 多次调用也不产生重复副作用。

### 6.3 mount

- 校验 `protocolVersion`；
- 校验 `container`、`viewId` 和 `apiBase`；
- 只在 props 指定的容器内查找或创建根节点；
- 创建一个 React Root；
- 以 `viewId` 初始化当前页面；
- 将主题和 API Base 放入本项目 Context；
- mount 完成后通过 `reportStatus` 上报 ready；
- 已存在实例时不能再次覆盖，应先完成上一实例卸载或拒绝重复 mount。

### 6.4 update

需要支持：

- `viewId` 变化：切换内部页面；
- `theme` 变化：更新本项目 CSS 变量；
- `visible=false`：暂停可暂停的动画、轮询和重试；
- `visible=true`：轻量刷新后恢复；
- `apiBase` 变化：仅在安全校验通过且没有进行中的关键请求时更新。

如果实际适配器没有稳定的 `update` 生命周期，可使用本项目 Integration Context 暴露的更新函数，由主平台的局部事件桥调用。对外字段不能改变。

### 6.5 unmount

卸载必须完成：

- React Root `unmount()`；
- 取消 `requestAnimationFrame`；
- dispose Three.js renderer、geometry、material、texture；
- 释放 OrbitControls、ResizeObserver、window/document 事件；
- 清理所有 interval、timeout、订阅和重试队列；
- 使用 AbortController 取消允许取消的请求；
- 移除微应用创建的弹层和 Portal；
- 清空模块保存的宿主回调和 DOM 引用；
- 不删除服务端模型缓存和用户上传数据。

这是本方案能否稳定运行的关键验收项。

## 7. 主平台 props 契约

```ts
interface SceneLibraryHostProps {
  protocolVersion: '1.0';
  container: Element;
  viewId: string;
  apiBase: string;
  locale: 'zh-CN';
  theme: SceneLibraryTheme;
  visible: boolean;
  navigate: (viewId: string, title?: string) => void;
  reportStatus: (status: SceneLibraryStatus) => void;
}
```

安全和兼容要求：

- 对所有字段做运行时校验，不能只依赖 TypeScript；
- `apiBase` 只接受允许的同源相对路径；
- `viewId` 必须存在于 `MENU_ITEMS`；
- `navigate` 只传页面 ID 和纯文本标题；
- `reportStatus` 不传堆栈、Token、文件 key 和服务器绝对路径；
- 协议不兼容时显示“场景库集成版本不兼容”，不要尝试带病运行；
- 回调执行失败不能让业务页面崩溃。

## 8. 页面与主平台路由同步

### 8.1 初始化

1. 读取 props `viewId`；
2. 在 `MENU_ITEMS` 中查找；
3. 有效则设置 `activeTabId`；
4. 无效则进入 `smart-ops`；
5. 回退后调用 `navigate('smart-ops', title)`，让主平台规范 URL。

### 8.2 内部切页

- 先更新本项目 `activeTabId`；
- 再调用主平台 `navigate`；
- 相同 ID 不重复通知；
- 不直接调用 `history.pushState` 或访问主平台 Vue Router；
- 页面标题只作为辅助信息，主平台一级名称仍为“场景库”。

### 8.3 外部地址变化

- 主平台前进/后退通过 `update` 传来新 ID；
- 本项目只更新页面，不重新 mount；
- 更新来源要区分 host/internal，避免循环；
- 子应用切换页面失败时保留最后正常页并报告状态。

## 9. 微应用外壳和紧凑导航

### 9.1 外壳

microapp 模式：

- 隐藏独立版大号品牌顶部栏；
- 不重复显示主平台用户、时间、通知和设置；
- 保留必要的当前业务标题、刷新和状态；
- 保留本项目导航，但改为紧凑布局；
- 根节点填满主平台容器，不使用 `100vw`；
- 不假设窗口就是完整页面；
- 只有一个主内容滚动区，不能无限向下扩展。

### 9.2 导航

- 数据只来自现有 `MENU_ITEMS`；
- 保留分类、父子层级、页面 ID、数量和选中态；
- 默认宽 220px，中等宽 200px，折叠 52～56px；
- 长标题最多两行，悬停/聚焦显示完整名称；
- 每组先显示 8 项，并提供“展开剩余 N 项”；
- 当前项必须自动显示并展开祖先；
- 菜单自身滚动，不拉高主内容；
- 搜索覆盖全部菜单，不受 8 项限制；
- 小容器宽度下覆盖式展开，避免挤压 3D 画面；
- 支持键盘操作和清晰焦点态。

宽度判断应以微应用容器 `ResizeObserver` 结果为准，不只看 `window.innerWidth`。

## 10. 样式隔离

qiankun 不像 iframe 一样天然隔离 CSS，因此必须治理：

- 所有新外壳样式限定在本项目根节点；
- 避免 `body`、`html`、`*`、裸标签等广泛全局覆盖；
- 不修改宿主 `body` 的背景、overflow 和字体；如确需修改，unmount 时必须恢复原值；
- Portal/弹窗优先挂到本项目容器内；
- class 命名增加项目作用域或使用 CSS Modules；
- 第三方组件样式逐项验证；
- qiankun 的样式隔离选项由主平台按现有策略启用，但本项目不能只依赖实验性隔离补救全局 CSS；
- 当前运行时 Tailwind CDN 应在微应用生产化前改为构建期方案，或完成严格作用域验证；
- 3D 视口保持适合灰模和白模的中深蓝灰，其他页面延续浅色主题。

主平台主题只映射到预定义 CSS 变量，不执行任意 CSS 文本。

## 11. API Base 改造

### 11.1 原因

本项目当前存在根路径 `/api/*`。微应用运行在主平台域名时，如果直接请求 `/api/*`，可能误入主平台后端。

### 11.2 统一函数

新增唯一浏览器端 API URL 生成器。行为示例：

```text
standalone apiBase=/api/
  apiUrl('model-showcase/x/bootstrap')
  → /api/model-showcase/x/bootstrap

microapp apiBase=/scene-library-api/
  apiUrl('model-showcase/x/bootstrap')
  → /scene-library-api/model-showcase/x/bootstrap
```

要求：

- 处理首尾斜杠；
- 查询参数使用 `URLSearchParams`；
- 拒绝任意外部协议和 `javascript:`；
- 不覆盖全局 `fetch`；
- 逐项迁移浏览器端 API 调用；
- Express 内部访问上游的 URL 不使用该浏览器配置；
- 静态搜索确认没有遗漏应迁移的 `fetch('/api`；
- 少数确实访问其他服务的请求必须独立配置和注明。

### 11.3 文件类接口

- 上传进度、大小限制和取消继续有效；
- 报告下载保留文件名和 `Content-Disposition`；
- 模型返回前校验 HTTP 状态和 `Content-Type`；
- 错误 JSON 不能送入 FBX/GLB 解析器；
- 模型版本、ETag 和更新时间继续保留；
- 模型刷新失败继续使用服务器最后成功缓存并标注更新时间。

## 12. 构建设计

同一源码生成两个产物：

| 构建 | public base | API Base | 输出示例 |
|---|---|---|---|
| standalone | `/cockpit/` 或独立域名 `/` | 同服务器默认 `/scene-library-api/`；独立域名可配置 `/api/` | `dist-standalone/` |
| microapp | `/microapps/scene-library/` | `/scene-library-api/` | `dist-microapp/` |

要求：

- 使用构建 mode 或明确脚本生成，不能复制产物后手工改；
- 微应用入口能够被 qiankun 正确解析并执行生命周期；
- JS/CSS/字体/图片/Worker/动态 import 使用正确 public base；
- 两个产物不能覆盖同一目录；
- HTML 不长期缓存，哈希资源可以长期缓存；
- 产物带构建版本，便于与 Express 协议核对；
- standalone 构建不依赖主平台脚本和全局变量；
- Vite/qiankun 适配器版本应先用最小页面验证，再锁定依赖版本。

## 13. Express 后端要求

`server.ts` 继续提供原 `/api/*`，不为了主平台复制一套 `/scene-library-api/*` 路由。Nginx 负责前缀转换。

需要保证：

- 监听端口可通过 `PORT` 配置，并新增可配置监听地址 `HOST`；正式同机部署建议 `HOST=127.0.0.1`；
- 生产环境由 systemd 管理；
- 外部模型上游通过 `VISUAL_MODEL_API_BASE_URL` 配置；
- 模型刷新间隔通过现有环境变量配置；
- `MODEL_CACHE_DIRECTORY` 指向发布目录之外的持久目录；
- 新增 `SCENE_DATA_DIRECTORY`，把上传文件和场景运行数据放到发布目录之外；禁止继续把生产上传数据绑定在版本化 `src/data` 中；
- 健康/版本接口轻量，不等待大模型下载；
- 健康信息不得返回密钥、对象 key、绝对路径和堆栈；
- 服务器关闭时尽量停止计时器和未完成任务；
- 日志能按请求 ID 定位，但不记录敏感信息。

当前生产 `server.ts` 会尝试服务 `dist`，且目前监听地址写为 `0.0.0.0`。在本方案中建议由 Nginx 直接服务两种前端产物、Express 专注 API，并让监听地址支持 `HOST=127.0.0.1`；若暂不改静态回退和监听实现，也必须保证 Nginx 只把 `/scene-library-api/` 转发给 Express，并通过防火墙/安全组禁止公网访问 3101，避免其 catch-all 截获主平台页面或后端端口直接暴露。

## 14. 错误与降级

- props 缺失或协议不兼容：显示明确集成错误；
- `view` 无效：回退 `smart-ops` 并通知主平台；
- API 暂时失败：继续使用页面已有的最后成功数据和更新时间；
- 3D 更新失败：继续显示服务端最后成功模型并标注更新失败；
- 单个页面异常：局部 Error Boundary，不让整个主平台空白；
- 主平台回调失败：本项目保持当前页，记录脱敏错误；
- 主平台停机：standalone 入口继续可用；
- 微应用发布失败：主平台可关闭入口或切回微应用上一版本。
