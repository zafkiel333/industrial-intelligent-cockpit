## 1. 当前现象与根因

场景库端已经完成改造并发布。用户在主平台的场景库 iframe 中点击“查看资源详情”时，页面会提示：

```text
主平台未响应模型详情跳转请求，请稍后重试。
```

该提示不表示场景库 API 或模型数据异常。它表示：

1. 场景库 iframe 已成功向父窗口发送 `scene-library:navigate` 消息；
2. 当前主平台宿主页没有注册对应的 `message` 监听器；
3. 主平台没有执行 `router.push`，也没有返回 `scene-library:navigate-result`；
4. 场景库等待 5 秒后超时，因此显示上述提示。

场景库与主平台为跨域 iframe：

| 系统 | 当前地址 / Origin |
|---|---|
| 场景库 iframe | `http://47.122.104.52:8081/cockpit/` / `http://47.122.104.52:8081` |
| 主平台开发服务 | `http://8.146.211.204:3100` |
| 主平台 80 端口站点 | `http://8.146.211.204` |

由于浏览器同源策略，iframe 不能直接访问主平台的 Vue Router、Pinia 状态或内标签数组。因此，要实现“内标签开启时打开内标签，关闭时同页跳转”，必须由主平台接收导航意图并执行自身的 `router.push`。

## 3. 目标交互效果

### 3.1 内标签开启

当 `multiTabsSetting.show === true` 时：

1. 用户在场景库 iframe 内点击“查看资源详情”；
2. 不新建浏览器标签页；
3. 主平台执行 `router.push`；
4. 主平台现有 `MultipleTabs` 监听路由变更，自动新增或激活“模型详情”内标签；
5. 详情页不在 iframe 内嵌套打开，而是主平台的正常路由页；
6. 详情页 ID 必须与所点击模型一致。

主平台现有标签去重逻辑会按 path 复用页签。因此连续打开不同 ID 时，预期复用同一个 `/three-model/detail` 内标签，仅更新 `query.id`，而不是为每个 ID 新建一个页签。

### 3.2 内标签关闭

当 `multiTabsSetting.show === false` 时：

1. 使用者仍点击同一按钮；
2. 主平台仍执行同一条 `router.push`；
3. `MultipleTabs` 组件未挂载，不会执行 `addTab`；
4. 当前浏览器页直接进入模型详情路由；
5. 不新建浏览器标签，不使用页内页或嵌套 iframe。

主平台不需要在消息处理器中为开关编写两套跳转实现。两种状态都必须使用 `router.push`，由现有标签系统自动适配。

### 3.3 独立访问场景库

用户直接访问 `http://47.122.104.52:8081/cockpit/` 时，页面不在 iframe 中。场景库端会使用当前浏览器标签直接导航到主平台完整模型详情地址，不新建浏览器标签。该分支已由场景库端实现，主平台无需额外处理。

## 5. 通信协议 1.0

### 5.1 请求：场景库→主平台

```ts
interface SceneLibraryNavigateRequest {
  type: 'scene-library:navigate';
  protocolVersion: '1.0';
  requestId: string;
  source: 'scene-library';
  target: {
    path: '/three-model/detail';
    query: {
      id: '2326' | '2328' | '2316' | '2310';
    };
  };
  openMode: 'host-default';
  modelName: '水轮机总成' | '污水泵KCM100HD' | '桥式起重机' | '拖车牵引车';
}
```

实例：

```json
{
  "type": "scene-library:navigate",
  "protocolVersion": "1.0",
  "requestId": "d9d74fc4-e5df-420f-87ce-56d6b379ac47",
  "source": "scene-library",
  "target": {
    "path": "/three-model/detail",
    "query": {
      "id": "2326"
    }
  },
  "openMode": "host-default",
  "modelName": "水轮机总成"
}
```

### 5.2 结果：主平台→场景库

```ts
interface SceneLibraryNavigateResult {
  type: 'scene-library:navigate-result';
  protocolVersion: '1.0';
  requestId: string;
  status: 'accepted' | 'rejected' | 'failed';
  mode?: 'multi-tab' | 'same-page';
  message?: string;
}
```

字段含义：

| 字段 | 说明 |
|---|---|
| `requestId` | 必须原样返回，场景库用它匹配当次请求 |
| `accepted` | 主平台已接受并完成 Vue Router 导航 |
| `rejected` | 协议、路由、ID 或来源不合法 |
| `failed` | 请求合法，但 `router.push` 或导航守卫处理失败 |
| `multi-tab` | 当前主平台内标签处于开启状态 |
| `same-page` | 当前主平台内标签处于关闭状态 |

成功响应实例：

```json
{
  "type": "scene-library:navigate-result",
  "protocolVersion": "1.0",
  "requestId": "d9d74fc4-e5df-420f-87ce-56d6b379ac47",
  "status": "accepted",
  "mode": "multi-tab"
}
```

失败响应实例：

```json
{
  "type": "scene-library:navigate-result",
  "protocolVersion": "1.0",
  "requestId": "d9d74fc4-e5df-420f-87ce-56d6b379ac47",
  "status": "failed",
  "message": "导航失败：模型详情路由不可用"
}
```

### 5.3 超时与重复点击

- 场景库等待结果的时间为 5 秒；
- 主平台应尽快回复，不要等待模型数据全部加载完成后再回复；
- 以 `router.push` Promise 完成作为 `accepted` 时点即可；
- 场景库在请求未完成时会禁用当前入口，避免同一按钮重复发送；
- 主平台仍应依赖现有路由/页签去重，不要自行新建重复页签。

### 6.3 增加协议类型与白名单

可先放在 `index.vue` 的 `<script setup lang="ts">` 中；如项目规范要求，可拆到同目录 `protocol.ts`。

```ts
// 若当前文件已从 vue-router 导入 useRouter，请合并为同一条 import。
import { isNavigationFailure } from 'vue-router';
import { useAppStore } from '/@/store/modules/app';

const SCENE_LIBRARY_ORIGIN = 'http://47.122.104.52:8081';
const ALLOWED_DETAIL_PATH = '/three-model/detail';
const ALLOWED_MODELS = new Map([
  ['2326', '水轮机总成'],
  ['2328', '污水泵KCM100HD'],
  ['2316', '桥式起重机'],
  ['2310', '拖车牵引车'],
]);

type NavigationMode = 'multi-tab' | 'same-page';
type NavigationStatus = 'accepted' | 'rejected' | 'failed';

interface SceneLibraryNavigateRequest {
  type: 'scene-library:navigate';
  protocolVersion: '1.0';
  requestId: string;
  source: 'scene-library';
  target: {
    path: '/three-model/detail';
    query: { id: string };
  };
  openMode?: 'host-default';
  modelName?: string;
}

interface SceneLibraryNavigateResult {
  type: 'scene-library:navigate-result';
  protocolVersion: '1.0';
  requestId: string;
  status: NavigationStatus;
  mode?: NavigationMode;
  message?: string;
}

const iframeRef = ref<HTMLIFrameElement | null>(null);
const appStore = useAppStore();
```

### 6.4 增加结果回传

```ts
function currentNavigationMode(): NavigationMode {
  const tabsVisible =
    appStore.getMultiTabsSetting.show &&
    !appStore.getLayoutHideMultiTabs;
  return tabsVisible ? 'multi-tab' : 'same-page';
}

function sendNavigationResult(
  targetWindow: Window,
  requestId: string,
  status: NavigationStatus,
  message?: string,
) {
  const result: SceneLibraryNavigateResult = {
    type: 'scene-library:navigate-result',
    protocolVersion: '1.0',
    requestId,
    status,
    ...(status === 'accepted' ? { mode: currentNavigationMode() } : {}),
    ...(message ? { message } : {}),
  };

  targetWindow.postMessage(result, SCENE_LIBRARY_ORIGIN);
}
```

`mode` 仅用于告知场景库主平台的实际模式，不用它决定导航方法。两种模式都执行同一个 `router.push`。

### 6.5 增加消息处理器

```ts
function handleSceneLibraryMessage(event: MessageEvent) {
  const iframeWindow = iframeRef.value?.contentWindow;

  // 不是当前宿主页 iframe 发出的消息：直接忽略。
  if (!iframeWindow || event.source !== iframeWindow) return;

  // Origin 必须精确相等，不得使用 includes/startsWith/*。
  if (event.origin !== SCENE_LIBRARY_ORIGIN) return;

  const data = event.data as Partial<SceneLibraryNavigateRequest> | null;

  // 其他消息类型不属于本协议，避免影响未来其他 iframe 通信。
  if (!data || data.type !== 'scene-library:navigate') return;

  const requestId = typeof data.requestId === 'string' ? data.requestId : '';
  if (!requestId) return;

  if (data.protocolVersion !== '1.0' || data.source !== 'scene-library') {
    sendNavigationResult(iframeWindow, requestId, 'rejected', '协议版本或来源标识非法');
    return;
  }

  const path = data.target?.path;
  const id = String(data.target?.query?.id ?? '');
  const expectedModelName = ALLOWED_MODELS.get(id);

  if (path !== ALLOWED_DETAIL_PATH) {
    sendNavigationResult(iframeWindow, requestId, 'rejected', '非法路由');
    return;
  }

  if (!expectedModelName) {
    sendNavigationResult(iframeWindow, requestId, 'rejected', '非法模型 ID');
    return;
  }

  // modelName 不参与路由拼接。若携带了该字段，则校验 ID/名称映射。
  if (data.modelName && data.modelName !== expectedModelName) {
    sendNavigationResult(iframeWindow, requestId, 'rejected', '模型 ID 与名称不匹配');
    return;
  }

  router
    .push({ path: ALLOWED_DETAIL_PATH, query: { id } })
    .then((failure) => {
      // Vue Router 4 的导航取消/中止可能会 resolve 为 NavigationFailure，
      // 而不是进入 catch，因此不能无条件回传 accepted。
      if (failure && isNavigationFailure(failure)) {
        console.error('[scene-library] model detail navigation was not completed', failure);
        sendNavigationResult(
          iframeWindow,
          requestId,
          'failed',
          `导航未完成：${failure.message || '路由守卫已取消导航'}`,
        );
        return;
      }
      sendNavigationResult(iframeWindow, requestId, 'accepted');
    })
    .catch((error: unknown) => {
      const message = error instanceof Error ? error.message : String(error);
      console.error('[scene-library] model detail navigation failed', error);
      sendNavigationResult(
        iframeWindow,
        requestId,
        'failed',
        `导航失败：${message || '未知错误'}`,
      );
    });
}
```

注意：

- 不要从消息中接收完整 URL 后直接跳转；
- 不要把 `path` 直接扩展为任意主平台路由；
- 不要信任仅有 `event.origin` 的消息，必须同时校验 `event.source === iframe.contentWindow`；
- 拒绝响应只发给已通过 iframe Window 与 Origin 校验的来源；
- 未知消息类型应忽略，不应报错或阻止其他功能。

### 6.6 合并现有生命周期

把现有：

```ts
onMounted(() => { startLoad(); });

onBeforeUnmount(() => {
  clearLoadTimer();
});
```

改为：

```ts
onMounted(() => {
  startLoad();
  window.addEventListener('message', handleSceneLibraryMessage);
});

onBeforeUnmount(() => {
  clearLoadTimer();
  window.removeEventListener('message', handleSceneLibraryMessage);
});
```

必须在卸载时移除同一个函数引用，否则重新进入场景库后可能形成重复监听和重复导航。

### 6.7 关于 `router.push` 的唯一正确用法

```ts
router.push({
  path: '/three-model/detail',
  query: { id },
});
```

不建议：

```ts
// 不要使用：会变成浏览器整页导航。
window.location.href = `/three-model/detail?id=${id}`;

// 不要使用：会打开新的浏览器标签。
window.open(`/three-model/detail?id=${id}`, '_blank');

// 不要使用：较容易绕开既有路由与标签去重逻辑。
multipleTabStore.addTab(...);
```

## 7. 安全要求

上线代码必须同时满足：

1. `event.source` 严格等于当前 iframe 的 `contentWindow`；
2. `event.origin` 严格等于 `http://47.122.104.52:8081`；
3. `type` 严格等于 `scene-library:navigate`；
4. `protocolVersion` 严格等于 `1.0`；
5. `source` 严格等于 `scene-library`；
6. `requestId` 必须是非空字符串；
7. `target.path` 只允许 `/three-model/detail`；
8. `target.query.id` 只允许 `2326/2328/2316/2310`；
9. 不执行消息中的任意 URL、JavaScript 或协议相对地址；
10. 导航异常需记录日志并回传 `failed`；
11. 卸载时必须移除监听；
12. 不得为了“兼容”而把 `targetOrigin` 设置为 `*`。

如场景库后续迁移域名、端口或 HTTPS，必须同步更新 Origin 白名单并重新联调，不得使用模糊匹配代替。

1. `3100` 是 Vite dev server、preview、Node 静态服务还是其他进程；
2. `80` 端口 Nginx 的 `root`/`alias` 指向哪个构建产物；
3. 场景库实际业务入口当前使用 `3100` 还是 `80`；
4. 需要发布一个环境还是两个环境；
5. 应由哪个 systemd/PM2/容器/发布脚本执行重启。

### 9.3 发布方式

必须优先使用主平台已有 CI/CD 或现有版本化发布脚本。若当前为手工发布，至少遵循：

1. 备份当前可运行产物或记录当前 release 软链接；
2. 在新版本目录构建，不在正在对外服务的目录里直接删除/覆盖；
3. 构建完成后检查产物中存在 `scene-library:navigate`、`scene-library:navigate-result`；
4. 原子切换到新产物；
5. 仅重启主平台前端相关进程，不影响模型库后端和其他服务；
6. Nginx 配置如无变更，不需要为本功能修改 Nginx；
7. 如确有 Nginx 变更，必须先 `nginx -t` 再平滑 reload；
8. 发布后立即执行第 10 节验收。

### 9.4 不同运行方式的注意事项

#### Vite 开发服务（3100）

- 源码变更可能由 HMR 加载，但线上交付不应仅以某个已打开浏览器的 HMR 成功作为发布依据；
- 应确认进程工作目录就是已修改的仓库；
- 应使用现有进程管理方式重启，而不是额外启动第二个 Vite 进程占用端口；
- 重启后验证 `3100` 端口、登录、场景库 iframe 和模型详情路由。

#### Nginx 80 端口静态产物

- 必须使用生产模式构建命令；
- 检查 `dist/_app.config.js` 中的场景库入口仍指向 `http://47.122.104.52:8081/cockpit/`；
- 确认 history 路由 fallback 仍正常，直接访问 `/three-model/detail?id=2326` 不能 404；
- 浏览器可能缓存旧 JS，应确认 HTML 不缓存、带 hash 的静态资源指向新版本；
- 发布后用无痕窗口或强制刷新重测。

## 11. 故障排查

### 11.1 仍提示“主平台未响应”

依次检查：

1. 已发布的 JS 产物是否包含 `scene-library:navigate`；
2. 宿主页 iframe 是否已增加 `ref="iframeRef"`；
3. `onMounted` 是否确实注册监听；
4. 监听是否因页面立即卸载而被清理；
5. `event.origin` 实际值是否为 `http://47.122.104.52:8081`；
6. `event.source` 是否与当前 iframe `contentWindow` 一致；
7. 响应是否使用原 `requestId`；
8. 浏览器是否仍加载旧的主平台 JS 缓存；
9. 是否只修改了仓库源码，但没有构建/发布到实际服务的端口。

联调期可临时在处理器入口记录：

```ts
console.debug('[scene-library] message received', {
  origin: event.origin,
  type: event.data?.type,
  requestId: event.data?.requestId,
});
```

请勿记录用户 Token、Cookie 或不相关业务数据；稳定后可移除调试日志。

### 11.2 收到消息但被拒绝

查看返回 `message`，检查：

- path 是否精确为 `/three-model/detail`；
- ID 是否为字符串形式的四个白名单 ID 之一；
- `modelName` 是否与 ID 对应；
- 是否误把开发主平台 Origin 当作场景库 Origin 校验。

注意：主平台接收到的 `event.origin` 是 iframe 的 Origin，即 `http://47.122.104.52:8081`，不是主平台自己的 `8.146.211.204`。

### 11.3 返回 accepted 但没有内标签

1. 确认右上角设置中“标签页”开关确实开启；
2. 确认 `appStore.getLayoutHideMultiTabs` 没有隐藏标签；
3. 确认不在全屏内容模式；
4. 检查 `/three-model/detail` 的 `meta.hideTab` 是否被生产后台菜单配置改写；
5. 检查 `MultipleTabs` 的路由变更监听是否正常；
6. 使用主平台自带的模型列表打开同一详情页，对比标签行为。

### 11.4 路由变了但模型内容没变

- 确认详情页监听 `route.query.id`；
- 确认不同 ID 切换时会重新加载数据；
- 确认 keepAlive 组件 key 使用 `route.fullPath`；
- 对比主平台模型列表内部切换不同模型时的既有行为。

## 12. 回滚方案

主平台回滚应使用其现有版本发布机制：

1. 恢复上一个主平台前端产物或 release 软链接；
2. 按现有方式重启前端进程或平滑切换静态目录；
3. 验证登录、首页、模型库、场景库和其他菜单；
4. 确认主平台未遗留重复 `message` 监听；
5. 记录回滚时间、原因和主平台版本。

回滚主平台后，场景库会再次显示“主平台未响应”，但不会回退到 `_blank` 或强制跳转，也不会影响场景库其他功能。

场景库自身已保留上一版本 `20260817-154326` 作为回滚点，但不应因主平台未完成适配而回滚场景库；正确处理是完成主平台的必要消息桥接。
