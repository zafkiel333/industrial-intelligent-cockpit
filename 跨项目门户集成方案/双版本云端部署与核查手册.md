# 场景库双服务器双版本部署与核查手册

> 日期：2026-08-17  
> 目标：本项目部署在“场景库服务器”，主平台部署在另一台“主平台服务器”。  
> 原则：两台服务器不共享目录；主平台服务器通过 Nginx 反向代理本项目的微应用和 API。

## 0. 最终访问链路

```text
独立版：浏览器 → https://<PROJECT_DOMAIN>/cockpit/

集成版：浏览器 → https://<MAIN_DOMAIN>/scene-library
                    ├─ /microapps/scene-library/ → 主平台 Nginx → 本项目服务器
                    └─ /scene-library-api/       → 主平台 Nginx → 本项目服务器 → Express
```

| 项目 | 地址 |
|---|---|
| 主平台页面 | `https://<MAIN_DOMAIN>/scene-library` |
| 独立版 | `https://<PROJECT_DOMAIN>/cockpit/` |
| 本项目微应用源站 | `https://<PROJECT_DOMAIN>/microapps/scene-library/` |
| 本项目 API 源站 | `https://<PROJECT_DOMAIN>/scene-library-api/` |
| 主平台代理后的微应用 | `https://<MAIN_DOMAIN>/microapps/scene-library/` |
| 主平台代理后的 API | `https://<MAIN_DOMAIN>/scene-library-api/` |
| Express 内部监听 | `127.0.0.1:3101` |

此方案下，浏览器访问集成版时始终使用主平台域名，因此不需要浏览器 CORS 配置。

## 1. 当前发布门禁

截至 2026-08-17，现网仍是旧的可用版本，本文没有执行任何线上修改。当前本地仓库实测仍有以下阻塞项：

- 缺少 `build:standalone` 和 `build:microapp`；
- 缺少 qiankun `bootstrap`、`mount`、`update`、`unmount` 生命周期；
- 缺少 `HOST`、`SCENE_DATA_DIRECTORY` 和 `GET /api/health`；
- `npx tsc --noEmit` 在 7 个 `three-types.ts` 文件报非法字符；
- Gemini 密钥仍由 Vite 注入浏览器代码。

以下检查全部通过后才能上传：

```powershell
npm pkg get scripts.build:standalone scripts.build:microapp
rg -n "export.*(bootstrap|mount|update|unmount)|__POWERED_BY_QIANKUN__" index.tsx App.tsx src
rg -n "process.env.HOST|SCENE_DATA_DIRECTORY|/api/health" server.ts
rg -n "VITE_PUBLIC_BASE|VITE_API_BASE|apiBase" vite.config.ts index.tsx App.tsx src
npx tsc --noEmit
rg -n "GEMINI_API_KEY|process.env.API_KEY|GoogleGenAI" vite.config.ts App.tsx src views components
```

作用：检查双构建、qiankun、后端部署能力、类型和前端密钥风险。

任何一项不满足时停止部署。

## 2. 本地构建两种版本

### 2.1 设置变量

```powershell
$ReleaseId = Get-Date -Format "yyyyMMddHHmmss"
$ProjectSshUser = "<PROJECT_SSH_USER>"
$ProjectServerIp = "<PROJECT_SERVER_IP>"
$ProjectDomain = "<PROJECT_DOMAIN>"
$MainDomain = "<MAIN_DOMAIN>"
$Package = "scene-library-release-$ReleaseId.tar.gz"
```

作用：设置版本号、两端域名和本项目服务器信息。

### 2.2 安装依赖并检查

```powershell
npm ci
npx tsc --noEmit
```

作用：按锁文件安装依赖并执行 TypeScript 检查。

### 2.3 构建独立版

```powershell
$env:VITE_PUBLIC_BASE = "/cockpit/"
$env:VITE_API_BASE = "/scene-library-api/"
npm run build:standalone
```

作用：生成本项目域名下运行的 `dist-standalone`。

### 2.4 构建集成微应用版

```powershell
$env:VITE_PUBLIC_BASE = "/microapps/scene-library/"
$env:VITE_API_BASE = "/scene-library-api/"
npm run build:microapp
```

作用：生成由主平台服务器反向代理加载的 `dist-microapp`。

### 2.5 检查产物

```powershell
if (-not (Test-Path .\dist-standalone\index.html)) { throw "缺少独立版入口" }
if (-not (Test-Path .\dist-microapp\index.html)) { throw "缺少微应用入口" }
rg -n "/cockpit/" .\dist-standalone\index.html
rg -n "/microapps/scene-library/" .\dist-microapp\index.html
rg -n "/api/" .\dist-microapp\assets
```

作用：确认两个入口及资源前缀正确，并检查微应用是否误用根 `/api/`。

如最后一条命中业务请求，改为 `/scene-library-api/` 后重新构建。

## 6. 配置本项目 Express

### 6.1 创建环境变量

```bash
sudo tee /etc/scene-library.env >/dev/null <<'EOF'
NODE_ENV=production
HOST=127.0.0.1
PORT=3101
VISUAL_MODEL_API_BASE_URL=http://8.146.211.204:3100/three-model-api
MODEL_BINARY_REFRESH_HOURS=36
MODEL_CACHE_DIRECTORY=/var/lib/scene-library/model-cache
SCENE_DATA_DIRECTORY=/var/lib/scene-library/data
EOF
sudo chown root:root /etc/scene-library.env
sudo chmod 600 /etc/scene-library.env
```

作用：配置 Express 监听、上游 API 和持久化目录。

### 6.2 创建 systemd 服务

```bash
sudo tee /etc/systemd/system/scene-library.service >/dev/null <<'EOF'
[Unit]
Description=Scene Library Express Backend
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=scene-library
Group=scene-library
WorkingDirectory=/opt/scene-library/current
EnvironmentFile=/etc/scene-library.env
ExecStart=/usr/bin/node /opt/scene-library/current/node_modules/tsx/dist/cli.mjs /opt/scene-library/current/server.ts
Restart=on-failure
RestartSec=5
TimeoutStopSec=30
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
```

作用：创建并加载本项目 Express 服务。

如果 `command -v node` 不是 `/usr/bin/node`，修改 `ExecStart` 的 Node 路径。

## 7. 配置本项目服务器 Nginx

### 7.1 创建路径配置

```bash
sudo tee /etc/nginx/snippets/scene-library.conf >/dev/null <<'EOF'
location = /cockpit {
    return 308 /cockpit/;
}

location ^~ /cockpit/assets/ {
    root /var/www;
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable" always;
}

location ^~ /cockpit/ {
    root /var/www;
    try_files $uri $uri/ /cockpit/index.html;
    add_header Cache-Control "no-cache" always;
}

location = /microapps/scene-library {
    return 308 /microapps/scene-library/;
}

location ^~ /microapps/scene-library/assets/ {
    root /var/www;
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable" always;
}

location ^~ /microapps/scene-library/ {
    root /var/www;
    try_files $uri $uri/ /microapps/scene-library/index.html;
    add_header Cache-Control "no-cache" always;
}

location = /scene-library-api {
    return 308 /scene-library-api/;
}

location ^~ /scene-library-api/ {
    client_max_body_size 100m;
    proxy_pass http://127.0.0.1:3101/api/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_send_timeout 180s;
    proxy_read_timeout 180s;
    proxy_request_buffering off;
    proxy_buffering off;
}
EOF
```

作用：在本项目服务器提供独立版、微应用源站和 API 源站。

### 7.2 引入本项目域名配置

```bash
sudo nginx -T 2>/dev/null | grep -n "server_name\|root "
export PROJECT_NGINX_CONF="/etc/nginx/sites-available/scene-library"
sudoedit "$PROJECT_NGINX_CONF"
```

作用：找到并打开本项目域名实际使用的 Nginx 配置。

在本项目域名的 `server {}` 内加入：

```nginx
include /etc/nginx/snippets/scene-library.conf;
```

### 7.3 检查配置

```bash
sudo nginx -t
```

作用：验证本项目服务器 Nginx；失败时不得 reload。


作用：启动新后端并启用本项目 Nginx 路径。

### 8.3 核查本项目服务器


## 10. 配置主平台服务器反向代理

以下命令登录“主平台服务器”执行，不要在本项目服务器执行。

### 10.1 检查主平台能访问本项目源站

```bash
export PROJECT_DOMAIN="<PROJECT_DOMAIN>"
export MAIN_DOMAIN="<MAIN_DOMAIN>"
curl -fsS "https://$PROJECT_DOMAIN/scene-library-api/health"
curl -fsSI "https://$PROJECT_DOMAIN/microapps/scene-library/"
```

作用：确认两台服务器网络和 HTTPS 连通。

### 10.2 创建代理配置

```bash
sudo tee /etc/nginx/snippets/scene-library-remote.conf >/dev/null <<'EOF'
location = /microapps/scene-library {
    return 308 /microapps/scene-library/;
}

location ^~ /microapps/scene-library/ {
    proxy_pass https://<PROJECT_DOMAIN>;
    proxy_ssl_server_name on;
    proxy_ssl_name <PROJECT_DOMAIN>;
    proxy_ssl_verify on;
    proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
    proxy_set_header Host <PROJECT_DOMAIN>;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_read_timeout 60s;
}

location = /scene-library-api {
    return 308 /scene-library-api/;
}

location ^~ /scene-library-api/ {
    client_max_body_size 100m;
    proxy_pass https://<PROJECT_DOMAIN>;
    proxy_ssl_server_name on;
    proxy_ssl_name <PROJECT_DOMAIN>;
    proxy_ssl_verify on;
    proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
    proxy_http_version 1.1;
    proxy_set_header Host <PROJECT_DOMAIN>;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_send_timeout 180s;
    proxy_read_timeout 180s;
    proxy_request_buffering off;
    proxy_buffering off;
}
EOF
sudo sed -i "s|<PROJECT_DOMAIN>|$PROJECT_DOMAIN|g" /etc/nginx/snippets/scene-library-remote.conf
```

作用：让主平台服务器跨服务器代理微应用和 API，浏览器仍保持同源。

`proxy_pass` 后没有 URI 尾部路径，原始 `/microapps/...` 和 `/scene-library-api/...` 会完整传给本项目服务器。

### 10.3 引入主平台配置

```bash
sudo nginx -T 2>/dev/null | grep -n "server_name\|root "
sudo nginx -T 2>/dev/null | grep -nE "location.*(/microapps/scene-library|/scene-library-api)" || true
export MAIN_NGINX_CONF="/etc/nginx/sites-available/main-platform"
sudoedit "$MAIN_NGINX_CONF"
```

作用：定位主平台域名配置并检查路径冲突。

在主平台域名的 `server {}` 内、通用 `location /` 前加入：

```nginx
include /etc/nginx/snippets/scene-library-remote.conf;
```

### 10.4 启用代理

```bash
test -f /etc/ssl/certs/ca-certificates.crt
sudo nginx -t && sudo systemctl reload nginx
```

作用：确认系统 CA 可用，检查成功后启用带证书校验的跨服务器代理。

## 11. 集成版本命令行核查

在主平台服务器执行：

```bash
curl -fsS "https://$MAIN_DOMAIN/scene-library-api/health"
curl -fsSI "https://$MAIN_DOMAIN/microapps/scene-library/"
curl -fsS "https://$MAIN_DOMAIN/microapps/scene-library/" | grep -oE '/microapps/scene-library/assets/[^" ]+' | head
```

作用：确认主平台域名下 API 返回 JSON、微应用返回 200、资源路径正确。

对比两台服务器返回内容：

```bash
curl -fsS "https://$PROJECT_DOMAIN/microapps/scene-library/" | sha256sum
curl -fsS "https://$MAIN_DOMAIN/microapps/scene-library/" | sha256sum
```

作用：确认主平台代理取得本项目服务器的同一份微应用入口。

如果主平台有 CSP，检查响应头：

```bash
curl -sI "https://$MAIN_DOMAIN/scene-library" | grep -i content-security-policy
```

作用：确认 CSP 没有阻止 qiankun 脚本执行；反向代理模式不需要增加跨域源。

## 12. 浏览器联合核查

### 12.1 独立版

打开：

```text
https://<PROJECT_DOMAIN>/cockpit/
```

核查：顶部栏、侧栏、页面切换、刷新、上传、下载、3D 和报告均正常。

打开：

```text

```

核查：

- 主平台导航、权限和标签页正常；
- 内容区由 qiankun 加载，不使用 iframe；

- `?view=<页面ID>`、刷新、前进和后退正常。

连续执行 5 次：

```text
进入场景库 → 打开3D页 → 离开场景库 → 再次进入
```

核查：只有一个子应用根节点、一个 Canvas，轮询和事件监听没有成倍增加。

## 14. 推荐发布顺序

1. 本地通过发布门禁并生成两个产物；
2. 新版本安装到本项目服务器独立目录；
3. 本项目服务器切换并验证源站；
4. 主平台服务器配置反向代理并验证；
5. 主平台发布包含 `/scene-library` 的新版本；
6. 完成独立版与集成版联合核查；
7. 观察两台服务器日志后结束发布。

主平台在第 5 步前仍使用旧版本，不受本项目服务器部署影响。

## 15. 回退

### 15.1 回退本项目版本

在本项目服务器执行：

```bash
ROLLBACK_RELEASE="$(readlink -f /opt/scene-library/previous)"
test -f "$ROLLBACK_RELEASE/server.ts" || exit 1
test -f "$ROLLBACK_RELEASE/dist-standalone/index.html" || exit 1
test -f "$ROLLBACK_RELEASE/dist-microapp/index.html" || exit 1
sudo ln -sfnT "$ROLLBACK_RELEASE" /opt/scene-library/current
sudo systemctl restart scene-library.service
curl -fsS http://127.0.0.1:3101/api/health
```

作用：同时回退独立版、微应用源站和 Express。

### 15.2 回退主平台集成

先按主平台现有流程回退主平台产物，再在主平台服务器执行：

```bash
export MAIN_NGINX_CONF="/etc/nginx/sites-available/main-platform"
sudoedit "$MAIN_NGINX_CONF"
sudo nginx -t && sudo systemctl reload nginx
```

作用：删除 `scene-library-remote.conf` 的 `include` 后撤销集成代理。

不要删除：

```text
/var/lib/scene-library/model-cache
/var/lib/scene-library/data
```

作用：保留模型缓存和用户上传数据。
