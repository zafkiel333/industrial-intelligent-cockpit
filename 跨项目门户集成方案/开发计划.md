## 0. 方案结论

采用以下方式：

**同一服务器分路径部署 + 主平台 Vue Router + qiankun 挂载 React 子应用 + Express 独立后端。**

简单理解：

1. 两个项目源码仍在各自代码库中，不复制、不合并；
2. 两个项目分别构建，产物放到同一服务器的不同目录；
3. 主平台增加“场景库”菜单和 `/scene-library` 路由；
4. 用户点击后，主平台不跳转到另一个完整网页，而是在自己的内容容器中挂载本项目 React 子应用；
5. 主平台顶部栏和全局导航保留，本项目显示紧凑版原导航和业务内容；
6. 本项目 Express 后端继续作为独立进程运行，由 Nginx 通过 `/scene-library-api/` 转发；
7. 本项目仍保留独立入口，名称和原有外壳不变；
8. 正常集成不使用 iframe。iframe 只作为重大兼容问题发生时的临时回退手段，不进入默认实现。

最终关系：

```text
同一台服务器 / 同一主域名
│
├─ /                         主平台 Vue 应用
├─ /scene-library            主平台内部路由，显示“场景库”
│    └─ qiankun 容器         挂载本项目 React 微应用
├─ /microapps/scene-library/ 本项目微应用构建产物
├─ /cockpit/                 本项目独立版构建产物（可选同域路径）
└─ /scene-library-api/       Nginx 转发到本项目 Express /api/
```

## 1. 为什么这样做

该方案同时满足：

- 主平台用户始终看到主平台顶部栏、导航、权限和标签页；
- “场景库”像主平台内置模块，不出现网页套网页的明显边界；
- Vue 主平台和 React 本项目不需要合并源码；
- 两个团队可以独立构建、发布和回退；
- 本项目原独立访问方式可以继续保留；
- 同域路径减少跨域、Cookie、HTTPS、模型下载和报告下载问题；
- 主平台已有 qiankun 基础设施，优先复用，不再引入第二套微前端框架。

需要明确：把两个项目放到同一服务器，只能解决部署和同域访问问题。要在保留主平台外壳的情况下切换到 React 页面，仍需要主平台通过 qiankun 挂载子应用。普通 `<a href>` 或 `location.href` 会重新加载整个页面，主平台导航也会消失。

## 5. 总体架构

### 5.1 浏览器端

```text
主平台 Vue Shell
├─ Vue Router：/scene-library?view=<页面ID>
├─ 权限、标签页、面包屑、加载与错误状态
└─ qiankun container
   └─ 本项目 React Micro App
      ├─ CompactSidebar（复用 MENU_ITEMS）
      ├─ AppCore（复用现有页面渲染）
      └─ integration bridge（路由、主题、状态）
```

### 5.2 服务器端

```text
Nginx
├─ 主平台静态文件
├─ 本项目微应用静态文件
├─ 本项目独立版静态文件
└─ /scene-library-api/ → 127.0.0.1:3101/api/

Express 3101
├─ 普通数据与上传 API
├─ 场景数据 API
├─ 外部模型 BFF
├─ 模型本地持久缓存
└─ 健康与版本信息
```

主平台后端不复制本项目 API，本项目 Express 也不读取主平台 Vue Store 或数据库内部结构。

## 6. 主平台需要完成的开发

### 6.1 菜单与路由

- 增加一级菜单“场景库”；
- 使用主平台现有权限机制；
- 菜单指向 `/scene-library`，不写本项目 IP；
- 路由打开主平台自己的容器组件；
- 保持其他菜单、模型管理和动态路由行为不变。

### 6.2 qiankun 容器

- 在容器页创建唯一挂载节点；
- 进入路由时加载 `/microapps/scene-library/`；
- 离开路由时执行子应用 `unmount`；
- 加载失败显示主平台错误卡、重试和独立打开；
- 避免重复 mount、重复事件和重复创建 WebGL Canvas；
- 容器使用 `min-width:0`、`min-height:0` 和明确滚动边界。

### 6.3 状态协调

- 首次进入把 `view`、主题、语言和能力作为 props 传给子应用；
- 子应用切页后，主平台用 `router.replace` 更新 `view`；
- 浏览器前进/后退时，把新 `view` 通知子应用；
- 不通过跨窗口 `postMessage` 通信；优先使用 qiankun props、回调或双方约定的轻量事件桥；
- 所有事件需要取消订阅，避免二次进入后重复触发。

### 6.4 权限与异常

- 未授权用户不加载微应用资源；
- 主平台停用场景库时只关闭菜单或功能开关；
- 子应用 API 或 3D 故障不应拖垮主平台其他模块；
- 微应用版本不兼容时显示明确错误并提供独立入口。

## 7. 本项目需要完成的开发

### 7.1 双运行模式

同一业务代码支持：

| 模式 | 启动方式 | 外壳 |
|---|---|---|
| standalone | 独立入口直接启动 | 原顶部栏、原导航、原内容 |
| microapp | qiankun 调用 `mount` | 紧凑导航、业务内容，不显示重复品牌顶栏 |

禁止维护两套业务页面或两份 `MENU_ITEMS`。

### 7.2 qiankun 生命周期

本项目需要提供：

- `bootstrap`：只做一次性、无页面副作用的初始化；
- `mount`：在主平台指定容器内创建 React 根节点；
- `update`：接收 `view`、主题和可见性变化；
- `unmount`：卸载 React、清理 3D、定时器、请求、订阅和事件。

独立启动时直接调用同一渲染核心，不能依赖 qiankun 才能运行。

### 7.3 紧凑原导航

- 继续使用 `MENU_ITEMS`、页面 ID、分类和父子层级；
- 菜单宽度支持 220px、200px 和折叠 52～56px；
- 长标题最多两行并提供完整提示；
- 每组默认显示 8 项，可展开剩余项目；
- 当前页面即使超出前 8 项也必须自动显示；
- 导航内部滚动，不把主平台页面无限拉长；
- 小屏支持覆盖式展开，避免持续挤压 3D 区域。

### 7.4 资源与 API

- 微应用静态资源使用 `/microapps/scene-library/` public base；
- 独立版使用 `/cockpit/` 或原独立域名对应 base；
- 浏览器 API 统一通过 API URL 生成器访问；
- 微应用默认使用 `/scene-library-api/`；
- 独立版按部署配置使用 `/api/` 或同域代理；
- FBX、GLB、字体、图片、动态 import、上传和报告必须全部验证。

### 7.5 样式和生命周期

- 清理或隔离会影响宿主的全局样式；
- Tailwind 运行时 CDN 不作为微应用长期生产方案，应改为构建期 CSS 或确保样式作用域隔离；
- React 只能挂载到 qiankun 提供的容器；
- 查询 DOM 时限定在本项目根节点；
- `unmount` 时释放 renderer、geometry、material、texture、OrbitControls、ResizeObserver、动画帧、计时器和可取消请求。

## 8. 主、子应用通信契约

建议由主平台向 `mount/update` 传入：

```ts
interface SceneLibraryHostProps {
  protocolVersion: '1.0';
  container: Element;
  viewId: string;
  apiBase: string;
  locale: 'zh-CN';
  theme: SceneLibraryTheme;
  visible: boolean;
  navigate: (viewId: string, title?: string) => void;
  reportStatus: (status: SceneLibraryStatus) => void;
}
```

原则：

- `container` 由 qiankun 提供，子应用不得挂载到宿主固定 ID；
- `navigate` 只传页面 ID 和普通标题，不传 HTML；
- `apiBase` 只允许同源相对路径；
- 不在 props、URL 或日志中传长期 Token；
- 协议版本不一致时停止挂载并提示升级；
- 若主平台实际 qiankun 版本不支持预期 `update` 行为，可使用已验证的共享状态/事件适配层，但对外字段和行为保持一致。

## 9. 构建和部署设计

### 9.1 构建产物

| 产物 | 示例目录 | 用途 |
|---|---|---|
| 主平台 | `/srv/www/main-platform/` | Vue 主应用 |
| 本项目微应用 | `/srv/www/microapps/scene-library/` | qiankun 加载 |
| 本项目独立版 | `/srv/www/cockpit/` | 保留独立访问 |
| 本项目服务端 | `/opt/scene-library/current/` | Express、源码和依赖 |
| 模型持久缓存 | `/var/lib/scene-library/model-cache/` | 发布时不覆盖 |
| 上传/场景数据 | `/var/lib/scene-library/data/` | 通过 `SCENE_DATA_DIRECTORY` 配置，发布时不覆盖 |

### 9.2 进程和转发

- Nginx 对外提供静态资源和 HTTPS；
- Express 监听 `127.0.0.1:3101` 或受防火墙保护的本机端口；
- systemd 管理 Express；
- `/scene-library-api/xxx` 转发为 Express `/api/xxx`；
- 微应用文件和主平台文件不能发布到同一物理目录；
- 带哈希的静态资源长缓存，HTML 和运行配置不长期缓存。

详细命令和 Nginx 示例见 [`本项目服务器端前后端部署指导.md`](./本项目服务器端前后端部署指导.md)。

## 10. 最小影响原则

主平台侧：

- 新增独立菜单、路由、容器和微应用注册；
- 不重写全局布局、登录、权限、标签页或已有微应用机制；
- 不修改 `/three-model` 现有页面；
- 配置只作用于 `industrial-intelligent-cockpit`。

本项目侧：

- 改造集中在应用入口、外壳、紧凑导航、API Base、构建和生命周期；
- 不批量改业务页面、诊断规则、模型接口或菜单 ID；
- standalone 继续使用原业务组件；
- 微应用样式必须限制在自己的根节点；
- 后端继续使用原 `/api/*` 路由，路径转换交给 Nginx。

代码改动继续使用日期注释，例如：

```ts
// 2026-08-13 新增：提供场景库微应用的 qiankun 挂载生命周期；
```

JSON 等不支持注释的文件只在修改日志记录，不写非法注释。

## 13. 风险和回退

| 风险 | 处理 |
|---|---|
| Tailwind 或全局 CSS 污染主平台 | 构建期 CSS、根节点作用域、qiankun 样式隔离并逐页回归 |
| 3D 离开页面后继续运行 | 完整实现 `unmount` 和业务资源清理 |
| 子路径资源 404 | 为 microapp 构建设置 public base，部署前检查产物引用 |
| `/api` 请求误入主平台后端 | 统一 API Base，并由 Nginx 使用独立 `/scene-library-api/` |
| 主、子版本不匹配 | 协议版本和健康接口校验，发布按兼容顺序执行 |
| 主平台被微应用异常影响 | Error Boundary、qiankun 错误处理、独立功能开关 |

回退顺序：

1. 关闭主平台“场景库”菜单或微应用功能开关；
2. 主平台其他模块不回退；
3. 微应用静态目录切回上一版本；
4. 如包含后端变更，再切换 Express 上一版本并重启；
5. 模型缓存和用户数据目录不删除；
6. 必要时临时把“场景库”改为独立入口链接，iframe 仅作为短期应急手段。
