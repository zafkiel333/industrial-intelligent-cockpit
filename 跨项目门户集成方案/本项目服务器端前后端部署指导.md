# 场景库服务器部署操作手册（简化版）

> 文档日期：2026-08-13  
> 适用人员：不了解本项目、但具备服务器 `sudo` 权限的部署人员  
> 适用环境：Ubuntu/Debian、Nginx、systemd、Node.js  
> 部署方式：主平台与本项目在同一服务器，代码和发布包互相独立

本文尽量按“从上到下复制命令”的方式编写。首次部署完成后，日常更新只需要执行第 11 节。

---

## 0. 最终部署结果

```text
https://你的域名/scene-library
  主平台中的“场景库”页面

https://你的域名/microapps/scene-library/
  qiankun 加载的 React 微应用

https://你的域名/cockpit/
  本项目独立访问页面

https://你的域名/scene-library-api/
  本项目 Express 接口
```

服务器固定使用以下位置：

| 用途 | 固定值 |
|---|---|
| 后端端口 | `127.0.0.1:3101` |
| 发布目录 | `/opt/scene-library/releases/` |
| 当前版本 | `/opt/scene-library/current` |
| 微应用静态入口 | `/var/www/microapps/scene-library` |
| 独立版静态入口 | `/var/www/cockpit` |
| 模型缓存 | `/var/lib/scene-library/model-cache` |
| 上传/场景数据 | `/var/lib/scene-library/data` |
| 环境变量 | `/etc/scene-library.env` |
| systemd 服务 | `scene-library.service` |
| Nginx 片段 | `/etc/nginx/snippets/scene-library.conf` |

## 1. 部署前只需要确认三件事

### 1.1 获取部署包

开发人员应交付一个文件：

```text
scene-library-release.tar.gz
```

部署包内至少应包含：

```text
dist-standalone/index.html
dist-microapp/index.html
src/
server.ts
package.json
package-lock.json
vite.config.ts
tsconfig.json
```

### 1.2 确认开发前置功能已经完成

以下功能必须由开发人员完成，部署人员不负责临时修改：

- `npm run build:standalone`；
- `npm run build:microapp`；
- qiankun 的 `bootstrap/mount/update/unmount`；
- `server.ts` 支持 `HOST=127.0.0.1`；
- `server.ts` 支持把上传数据放到 `SCENE_DATA_DIRECTORY`；
- `GET /api/health` 健康接口；
- 同服务器下，standalone 和 microapp 两个构建都使用 `/scene-library-api/` 访问后端。

如果部署包缺少这些功能，应退回开发人员处理，不要在服务器上临时改源码。

### 1.3 确认主平台 Nginx 配置文件

执行：

```bash
sudo nginx -T 2>/dev/null | grep -n "server_name\|root "
```

找到主平台所在的 `server` 配置文件。下文用下面这个示例路径表示：

```text
/etc/nginx/sites-available/main-platform
```

如果实际路径不同，第 8 节只需换成实际路径。

## 2. 在本地上传部署包

以下命令在存放 `scene-library-release.tar.gz` 的本地电脑执行。替换服务器用户名和 IP：

```bash
scp scene-library-release.tar.gz <SSH_USER>@<SERVER_IP>:/tmp/
```

上传完成后登录服务器：

```bash
ssh <SSH_USER>@<SERVER_IP>
```

后续命令全部在服务器执行。

---

## 3. 检查服务器环境

复制执行：

```bash
node --version
npm --version
nginx -v
systemctl --version | head -n 1
test -f /tmp/scene-library-release.tar.gz && echo "部署包已上传"
```

要求：

- Node.js 满足项目锁定的 Vite 8 要求：`^20.19.0` 或 `>=22.12.0`；
- 推荐直接使用已验证的 Node.js 22.12 以上版本；
- 能看到 Nginx 和 systemd 版本；
- 最后一行显示“部署包已上传”。

如果 Nginx 未安装，可执行：

```bash
sudo apt-get update
sudo apt-get install -y nginx curl ca-certificates
sudo systemctl enable --now nginx
```

如果 Node.js 版本不符合要求，请让服务器管理员安装符合版本要求的 Node.js 后再继续。不要直接使用 Ubuntu 仓库中的旧 Node.js。


## 5. 解压并安装本次版本

下面整段必须在同一个终端中执行：

```bash
SCENE_RELEASE_ID=$(date +%Y%m%d%H%M%S)
SCENE_RELEASE_DIR="/opt/scene-library/releases/$SCENE_RELEASE_ID"

sudo install -d -o scene-library -g scene-library "$SCENE_RELEASE_DIR"
sudo tar -xzf /tmp/scene-library-release.tar.gz -C "$SCENE_RELEASE_DIR"
sudo chown -R scene-library:scene-library "$SCENE_RELEASE_DIR"

test -f "$SCENE_RELEASE_DIR/server.ts"
test -f "$SCENE_RELEASE_DIR/package-lock.json"
test -f "$SCENE_RELEASE_DIR/dist-standalone/index.html"
test -f "$SCENE_RELEASE_DIR/dist-microapp/index.html"

sudo -u scene-library npm ci --prefix "$SCENE_RELEASE_DIR"

sudo -u scene-library ln -sfnT dist-standalone "$SCENE_RELEASE_DIR/dist"
sudo chmod -R u=rwX,go=rX "$SCENE_RELEASE_DIR"

echo "本次版本目录：$SCENE_RELEASE_DIR"
```

四个 `test -f` 命令只要有一个报错，就停止部署并检查压缩包结构。

## 6. 配置后端环境变量

整段复制执行：

```bash
sudo tee /etc/scene-library.env >/dev/null <<'EOF'
NODE_ENV=production
HOST=127.0.0.1
PORT=3101
VISUAL_MODEL_API_BASE_URL=http://8.146.211.204:3100/three-model-api
MODEL_BINARY_REFRESH_HOURS=36
MODEL_CACHE_DIRECTORY=/var/lib/scene-library/model-cache
SCENE_DATA_DIRECTORY=/var/lib/scene-library/data
EOF

sudo chown root:root /etc/scene-library.env
sudo chmod 600 /etc/scene-library.env
```

检查：

```bash
sudo grep -E '^(NODE_ENV|HOST|PORT|MODEL_BINARY_REFRESH_HOURS|MODEL_CACHE_DIRECTORY|SCENE_DATA_DIRECTORY)=' /etc/scene-library.env
```

如果外部模型 API 地址以后变化，只修改 `VISUAL_MODEL_API_BASE_URL`，然后重启后端。

## 7. 创建并启动 systemd 服务

先确认 Node 路径：

```bash
command -v node
```

下面配置默认 Node 位于 `/usr/bin/node`。如果上一步显示其他路径，需要把 `ExecStart` 开头改成实际路径。

复制创建服务：

```bash
sudo tee /etc/systemd/system/scene-library.service >/dev/null <<'EOF'
[Unit]
Description=Scene Library Express Backend
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=scene-library
Group=scene-library
WorkingDirectory=/opt/scene-library/current
EnvironmentFile=/etc/scene-library.env

# 2026-08-13 新增：独立运行场景库 Express 后端；
ExecStart=/usr/bin/node /opt/scene-library/current/node_modules/tsx/dist/cli.mjs /opt/scene-library/current/server.ts

Restart=on-failure
RestartSec=5
TimeoutStopSec=30
NoNewPrivileges=true
PrivateTmp=true
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
EOF
```

先找到第 5 节刚创建的最新版本，然后切换当前版本和静态目录：

```bash
SCENE_RELEASE_DIR=$(find /opt/scene-library/releases -mindepth 1 -maxdepth 1 -type d | sort | tail -n 1)

test -n "$SCENE_RELEASE_DIR"
test -f "$SCENE_RELEASE_DIR/server.ts"
test -f "$SCENE_RELEASE_DIR/dist-standalone/index.html"
test -f "$SCENE_RELEASE_DIR/dist-microapp/index.html"

sudo ln -sfnT "$SCENE_RELEASE_DIR" /opt/scene-library/current
sudo ln -sfnT /opt/scene-library/current/dist-standalone /var/www/cockpit
sudo ln -sfnT /opt/scene-library/current/dist-microapp /var/www/microapps/scene-library
```

启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now scene-library.service
sudo systemctl status scene-library.service --no-pager
```

看到 `active (running)` 后，验证本机后端：

```bash
curl -i http://127.0.0.1:3101/api/health
```

应返回 HTTP 200 和 JSON。否则查看日志：

```bash
sudo journalctl -u scene-library.service -n 100 --no-pager
```

## 8. 配置 Nginx

### 8.1 创建场景库 Nginx 片段

整段复制执行：

```bash
sudo tee /etc/nginx/snippets/scene-library.conf >/dev/null <<'EOF'
# 2026-08-13 新增：场景库微应用、独立页面和 Express API 路径；

location = /microapps/scene-library {
    return 308 /microapps/scene-library/;
}

location ^~ /microapps/scene-library/assets/ {
    root /var/www;
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable" always;
}

location ^~ /microapps/scene-library/ {
    root /var/www;
    try_files $uri $uri/ /microapps/scene-library/index.html;
    add_header Cache-Control "no-cache" always;
}

location = /cockpit {
    return 308 /cockpit/;
}

location ^~ /cockpit/assets/ {
    root /var/www;
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable" always;
}

location ^~ /cockpit/ {
    root /var/www;
    try_files $uri $uri/ /cockpit/index.html;
    add_header Cache-Control "no-cache" always;
}

location = /scene-library-api {
    return 308 /scene-library-api/;
}

location ^~ /scene-library-api/ {
    client_max_body_size 100m;
    proxy_pass http://127.0.0.1:3101/api/;
    proxy_http_version 1.1;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Request-ID $request_id;

    proxy_connect_timeout 10s;
    proxy_send_timeout 180s;
    proxy_read_timeout 180s;
    proxy_request_buffering off;
    proxy_buffering off;
}
EOF
```

### 8.2 在主平台 Nginx 中引入

打开第 1.3 节找到的主平台配置，例如：

```bash
sudo nano /etc/nginx/sites-available/main-platform
```

在主平台的 `server { ... }` 内部、原来的 `location / { ... }` 前加入一行：

```nginx
include /etc/nginx/snippets/scene-library.conf;
```

只加入一次。不要创建第二个相同域名、相同端口的 `server` 块，也不要删除主平台原有 `location /`。

保存后复制执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

只有 `nginx -t` 显示 successful，才算配置正确。

## 9. 验证部署

将 `<DOMAIN>` 替换成主平台实际域名：


### 11.2 在服务器安装并切换

整段复制执行：

```bash
SCENE_RELEASE_ID=$(date +%Y%m%d%H%M%S)
SCENE_RELEASE_DIR="/opt/scene-library/releases/$SCENE_RELEASE_ID"

sudo install -d -o scene-library -g scene-library "$SCENE_RELEASE_DIR"
sudo tar -xzf /tmp/scene-library-release.tar.gz -C "$SCENE_RELEASE_DIR"
sudo chown -R scene-library:scene-library "$SCENE_RELEASE_DIR"

test -f "$SCENE_RELEASE_DIR/server.ts"
test -f "$SCENE_RELEASE_DIR/dist-standalone/index.html"
test -f "$SCENE_RELEASE_DIR/dist-microapp/index.html"

sudo -u scene-library npm ci --prefix "$SCENE_RELEASE_DIR"
sudo -u scene-library ln -sfnT dist-standalone "$SCENE_RELEASE_DIR/dist"
sudo chmod -R u=rwX,go=rX "$SCENE_RELEASE_DIR"

echo "切换前版本：$(readlink -f /opt/scene-library/current)"
echo "即将切换到：$SCENE_RELEASE_DIR"

sudo ln -sfnT "$SCENE_RELEASE_DIR" /opt/scene-library/current
sudo systemctl restart scene-library.service

sudo systemctl status scene-library.service --no-pager
curl -i http://127.0.0.1:3101/api/health
```

由于 `/var/www/cockpit` 和 `/var/www/microapps/scene-library` 都指向 `current` 内部目录，切换 `current` 后不需要重新创建静态链接。

模型缓存和上传数据位于 `/var/lib/scene-library`，不会随版本切换丢失。

## 12. 回退上一版本

先列出版本：

```bash
ls -1 /opt/scene-library/releases
readlink -f /opt/scene-library/current
```

确认需要回退的目录后，将 `<OLD_RELEASE>` 替换为旧版本目录名：

```bash
test -f /opt/scene-library/releases/<OLD_RELEASE>/server.ts
sudo ln -sfnT /opt/scene-library/releases/<OLD_RELEASE> /opt/scene-library/current
sudo systemctl restart scene-library.service
sudo systemctl status scene-library.service --no-pager
curl -i http://127.0.0.1:3101/api/health
```

示例：

```bash
sudo ln -sfnT /opt/scene-library/releases/20260813153000 /opt/scene-library/current
sudo systemctl restart scene-library.service
```

回退时不要删除：

```text
/var/lib/scene-library/model-cache
/var/lib/scene-library/data
```

## 14. 常见问题

| 问题 | 优先检查 |
|---|---|
| 后端启动失败 | `journalctl -u scene-library.service -n 100` |
| `tsx` 找不到 | 是否在版本目录执行了完整 `npm ci` |
| 微应用 JS/CSS 404 | `dist-microapp` 的 public base 是否为 `/microapps/scene-library/` |
| API 404 | Nginx 是否引入 `scene-library.conf`，`proxy_pass` 是否保留 `/api/` 尾斜杠 |
| `/cockpit/` 打开后接口错误 | standalone 是否使用 `/scene-library-api/` |
| 进入两次出现两个模型 | qiankun `unmount` 是否释放 React Root 和 Three.js |
| 页面样式影响主平台 | 子应用是否存在 `body/html/*` 全局样式或 Tailwind CDN 污染 |
| FBX 返回 JSON | 查看 Express 日志、上游模型接口和响应 `Content-Type` |
| 更新后旧模型消失 | 检查 `MODEL_CACHE_DIRECTORY` 是否仍指向 `/var/lib/scene-library/model-cache` |
| 上传数据随版本消失 | 检查 `SCENE_DATA_DIRECTORY` 是否指向 `/var/lib/scene-library/data` |

## 15. 部署人员不要做的操作

- 不把两个项目源码合并到同一目录；
- 不把本项目 `dist` 覆盖到主平台 `dist`；
- 不在服务器临时修改 React/Vue 业务代码；
- 不将 Express 3101 端口开放到公网；
- 不删除 `/var/lib/scene-library`；
- 不在 `nginx -t` 失败时重启 Nginx；
- 不使用 `npm install` 替代 `npm ci`；
- 不只上传前端文件却忘记后端接口和依赖；
- 不在主平台菜单中配置本项目外部 IP，菜单应进入主平台 `/scene-library` 路由。
