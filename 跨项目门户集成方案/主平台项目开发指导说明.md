# C-Y-D-G 主平台“场景库”开发指导说明

> 文档日期：2026-08-13  
> 指导对象：主平台 Vue 前端、后端菜单/权限、网关和运维开发人员  
> 实施方式：qiankun 微前端；正常流程不使用 iframe  
> 配套说明：[`工业智能驾驶舱项目开发指导说明.md`](./工业智能驾驶舱项目开发指导说明.md)  
> 部署说明：[`本项目服务器端前后端部署指导.md`](./本项目服务器端前后端部署指导.md)

---

## 0. 开发原因和目标

需要把独立的“工业智能运维驾驶舱”作为主平台的一级业务模块使用。主平台对用户统一显示为“场景库”，但两个项目源码不合并，仍由各自团队独立构建和发布。

开发后应达到：

- 主平台增加“场景库”一级菜单；
- 点击后仍处于主平台页面，顶部栏、全局导航、标签页和权限体系保留；
- 主平台通过 qiankun 在内容区挂载 React 子应用；
- 子应用内部保留紧凑版原导航和全部业务页面；
- 两个项目部署在同一服务器的不同目录，并通过同一域名访问；
- 子应用错误、升级或停机不影响主平台其他模块；
- 本项目原独立入口继续可用。

普通 URL 外链会替换整个主平台页面，无法保留主平台导航。因此“路由跳转”必须是：主平台 Vue Router 先进入自己的容器路由，再由 qiankun 把子应用挂到容器中。

---

## 1. 子项目开发相关情况

子项目“工业智能运维驾驶舱”具备以下特征：

- React 19、TypeScript、Vite；
- Node.js + Express，入口为 `server.ts`；
- Three.js、React Three Fiber 和 FBX/GLB/GLTF；
- 使用 `MENU_ITEMS` 和 `activeTabId` 管理大量页面；
- 具有数据上传、诊断、预测、报告和外部模型 BFF；
- 将提供 standalone 和 microapp 两种构建；
- microapp 构建实现 qiankun `bootstrap/mount/update/unmount`；
- API 由主平台同域 Nginx 路径转发，主平台不复制 Express 业务；
- 子项目不会读取主平台 DOM、Pinia 或内部后端数据库。

主平台当前为 Vue 3、Vue Router、Pinia、Ant Design Vue、Vite，并已有 qiankun 相关基础设施。应优先接入现有微前端注册和错误处理机制，不重新搭建另一套框架。

## 2. 双方固定契约

| 项目 | 默认值 |
|---|---|
| 主平台显示名称 | `场景库` |
| 子项目独立名称 | `工业智能运维驾驶舱` |
| qiankun 应用名称 | `industrial-intelligent-cockpit` |
| 主平台路由 | `/scene-library` |
| 内部页面参数 | `view` |
| 默认页面 | `smart-ops` |
| 微应用入口 | `/microapps/scene-library/` |
| 独立入口 | `/cockpit/`，可按实际部署配置 |
| API 前缀 | `/scene-library-api/` |
| props 协议版本 | `1.0` |

路径与名称必须从集中配置读取。若实际服务器已有冲突，可整体调整路径，但主平台、子应用和 Nginx 必须同步改，禁止只改单方。

## 3. 主平台负责与不负责的内容

### 3.1 主平台负责

- 菜单、路由、权限和标签页；
- qiankun 注册、容器和装卸载；
- 加载、错误、重试和功能开关；
- `view` 地址同步；
- 向子应用传递主题、语言、API Base 和可见性；
- 同服务器静态路径和 API 反向代理；
- 登录、权限入口、审计和安全策略；
- 主平台范围内的发布和回退。

### 3.2 主平台不负责

- 不复制 React 源码和 `MENU_ITEMS`；
- 不复制 Express 接口、模型缓存或诊断逻辑；
- 不把子项目全部页面注册为主平台菜单；
- 不操作子应用内部 DOM；
- 不修改现有 `/three-model` 页面；
- 不为接入场景库重写主平台布局、权限或其他微应用机制；
- 不把当前公网 IP 硬编码为生产入口。

## 4. 主平台前端开发

### 4.1 菜单

新增一个一级菜单：

```text
显示名称：场景库
路由：/scene-library
类型：主平台内部业务路由
权限：复用主平台现有菜单权限
```

要求：

- 菜单点击使用 `router.push`，不是 `<a>` 外链；
- 菜单、标签页、默认标题和面包屑统一显示“场景库”；
- 不显示“工业智能运维驾驶舱”作为主平台一级名称；
- 图标、排序和国际化沿用主平台规范；
- 默认只增加一个入口，不复制子项目全部栏目。

### 4.2 Vue Router

新增独立路由模块，功能要求：

- path 为 `/scene-library`；
- query `view` 可选；
- `view` 只允许字母、数字、`-`、`_`，最大 128 字符；
- 缺少或格式错误时使用 `smart-ops`；
- 复用登录守卫、权限守卫、标签页和面包屑机制；
- 不改全局 404、keep-alive 和其他动态路由；
- 子应用内部页面变化只更新 query，不重复创建容器。

### 4.3 容器组件

新增一个局部容器组件，例如 `SceneLibraryHost.vue`。具体文件位置按主平台现有目录规范确定。

容器必须：

- 提供唯一、稳定的 qiankun 挂载节点；
- 进入路由时加载应用，离开时卸载；
- 防止并发加载导致重复实例；
- 使用 flex 布局并设置 `min-width:0`、`min-height:0`；
- 内容高度限制在主平台可用区域内；
- 显示主平台统一骨架屏；
- 加载失败显示错误卡、重新加载和独立打开；
- 重新加载只重建该微应用，不刷新整个主平台；
- 组件卸载时取消路由监听和所有子应用回调。

建议状态：

```text
idle → loading → mounted
               ↘ load-error → retry
mounted → unmounting → idle
```

不要依赖固定延时判断挂载成功，应以 qiankun 生命周期完成和子应用 ready 回调为准。

### 4.4 微应用注册

注册参数从主平台环境配置读取：

```ts
interface SceneLibraryIntegrationConfig {
  enabled: boolean;
  name: 'industrial-intelligent-cockpit';
  routePath: '/scene-library';
  entry: string;
  apiBase: string;
  standaloneUrl: string;
  protocolVersion: '1.0';
  loadTimeoutMs: number;
}
```

默认：

```text
entry         = /microapps/scene-library/
apiBase       = /scene-library-api/
standaloneUrl = /cockpit/
```

实施要求：

- 使用主平台现有的 `registerMicroApps` 或 `loadMicroApp` 封装；
- 若主平台需要按路由按需加载，优先使用其已有模式；
- 容器选择器只属于本页面；
- `enabled=false` 时隐藏菜单或显示维护页；
- 不修改其他微应用的沙箱、预加载和全局错误策略；
- 首期不预加载包含大型 3D 依赖的子应用，避免拖慢主平台首页。

代码示意仅表达职责，不要求照抄：

```ts
// 2026-08-13 新增：按主平台场景库路由挂载独立 React 微应用；
loadMicroApp({
  name: config.name,
  entry: config.entry,
  container: containerElement,
  props: createSceneLibraryProps(),
});
```

### 4.5 props 和页面同步

主平台传给子应用的契约：

```ts
interface SceneLibraryHostProps {
  protocolVersion: '1.0';
  container: Element;
  viewId: string;
  apiBase: string;
  locale: 'zh-CN';
  theme: SceneLibraryTheme;
  visible: boolean;
  navigate: (viewId: string, title?: string) => void;
  reportStatus: (status: SceneLibraryStatus) => void;
}
```

同步规则：

1. 首次进入读取 `route.query.view`；
2. 通过 mount props 传给子应用；
3. 子应用内部切页调用 `navigate`；
4. 主平台校验 ID 后使用 `router.replace` 更新 query；
5. 浏览器前进、后退导致 query 变化时，通过 qiankun `update` 或双方约定适配层通知子应用；
6. 新旧 ID 相同时不再发送，防止循环；
7. 子应用判断页面 ID 无效并回退后，主平台把地址规范为回退 ID。

如当前 qiankun 版本不支持可靠 `update`，可以使用主平台已有全局状态或单独事件桥，但只能传约定字段，且必须在容器卸载时取消订阅。不得让子应用直接读取 Pinia。

### 4.6 标题和状态

- 一级菜单和标签页项目名始终是“场景库”；
- 当前业务标题可显示为“场景库 / 当前页面标题”；
- 子应用标题必须去控制字符并限制长度；
- 子应用状态只影响场景库容器，不修改整个主平台健康状态；
- 内部单个 API 失败不能触发主平台全局崩溃页。

### 4.7 主题

主平台只传语义令牌，不传任意 CSS：

```ts
interface SceneLibraryTheme {
  primary: string;
  pageBackground: string;
  subtleBackground: string;
  cardBackground: string;
  border: string;
  textPrimary: string;
  textSecondary: string;
  success: string;
  warning: string;
  danger: string;
}
```

默认建议沿用当前浅蓝企业风格。主平台不使用全局选择器强行覆盖子应用；视觉适配由子应用把令牌映射到自身 CSS 变量。

## 5. 生命周期和稳定性

### 5.1 进入

- 确认用户有权限；
- 创建容器；
- 读取配置和 `view`；
- 加载微应用；
- mount 完成后隐藏骨架；
- ready 超时只提示，不立即杀死仍在加载的 3D 页面。

### 5.2 离开

- 先标记容器正在卸载，阻止重复操作；
- 调用 qiankun `unmount`；
- 等待子应用完成资源清理；
- 清除主平台局部事件、超时器和引用；
- 再移除容器 DOM。

### 5.3 主平台 keep-alive

默认建议离开路由就卸载，避免隐藏 WebGL 长时间占用 GPU。若主平台必须缓存：

- 通过 `visible=false` 通知子应用；
- 子应用确认暂停动画、轮询和重试；
- 恢复时传 `visible=true` 并进行一次轻量数据刷新；
- 不允许只隐藏 DOM 而让 3D 持续渲染。

## 6. 网关、权限和安全

### 6.1 同服务器路径

主平台运维需要确保：

```text
/microapps/scene-library/  → 本项目 microapp 静态目录
/scene-library-api/        → 本项目 Express /api/
/cockpit/                  → 本项目 standalone 静态目录（如启用）
```

主平台自身 `/` 和已有 API 规则不能被这些 location 覆盖。

### 6.2 权限

- 菜单和路由使用主平台现有权限守卫；
- 未授权时不下载微应用 JS；
- 不在 URL 或 props 中传长期 Token；
- 若有统一 SSO，使用主平台既有会话或后端签发的短期凭证；
- 没有已确定的 SSO 技术细节时只预留适配接口，不自行发明认证协议。

### 6.3 安全

- `apiBase` 只允许同源相对路径；
- 对子应用传入的回调和对象使用最小权限；
- 不把主平台 Store、路由实例或整个用户对象暴露给子应用；
- 主平台 CSP 允许自身微应用静态路径和必要资源；
- 不为微应用关闭主平台全局安全头；
- 对微应用加载错误做脱敏记录，不记录 Token、模型对象 key 和服务器绝对路径。

## 7. 最小影响要求

| 范围 | 实施要求 |
|---|---|
| 菜单 | 按现有机制新增一项，不重写全局导航 |
| 路由 | 新增独立模块，不修改已有业务路由 |
| 容器 | 新增局部组件，不把逻辑塞入全局 Layout |
| qiankun | 复用现有封装，不改其他微应用注册 |
| 样式 | scoped/module，禁止全局污染 |
| 权限 | 复用现有权限，不建立平行系统 |
| 网关 | 新增精确前缀，不更改主平台 `/` 和既有 API |
| 回退 | 可单独关闭场景库，不回退主平台其他模块 |

所有支持注释的代码修改按要求增加日期和功能说明：

```ts
// 2026-08-13 新增：注册主平台“场景库”微应用路由；
```

## 8. 主平台实施顺序

1. 确认 qiankun 版本、现有封装和 React 19 兼容性；
2. 用最小 React 测试页验证 mount、update、unmount；
3. 增加配置和关闭开关；
4. 增加“场景库”菜单、权限和 `/scene-library`；
5. 增加容器、加载、错误、重试和独立打开；
6. 接入真实微应用入口；
7. 完成 `view`、主题、标题、可见性和状态同步；
8. 配置同服务器路径和 API 代理；
9. 联调 3D、上传、报告和多次装卸载；
10. 灰度开放权限并观察日志。

---

## 9. 主平台验收

- [ ] 菜单、标签页和面包屑统一显示“场景库”；
- [ ] 点击菜单后主平台顶部栏和全局导航保持；
- [ ] 浏览器不整页跳到本项目独立地址；
- [ ] 正常流程中没有 iframe；
- [ ] 微应用可以加载、重试、卸载和再次挂载；
- [ ] `view` 刷新、前进和后退正确；
- [ ] 不发生重复 mount 和重复回调；
- [ ] 离开后 WebGL 和轮询停止；
- [ ] 未授权用户不加载微应用；
- [ ] 其他菜单、模型管理和其他微应用无回归；
- [ ] 微应用后端不可用时主平台其他接口正常；
- [ ] 功能开关可以单独关闭场景库。

## 10. 主平台交付物

- 菜单和权限配置；
- `/scene-library` 路由；
- qiankun 容器和注册配置；
- 主、子应用 props 类型或契约文件；
- 加载、错误和回退处理；
- 环境变量说明；
- Nginx 主平台侧配置调整；
- 测试记录和修改日志；
- 单独关闭“场景库”的回退说明。

只要遵守第 2、4.5 和第 6 节契约，主平台人员无需理解子项目全部 React 页面和 Express 业务。
