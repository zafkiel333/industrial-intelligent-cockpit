# 模型失效与全量资源审计

## 1. 截图页面的原因

截图中的 `eq-0 / 水轮机智能运维` 原绑定模型为 `2353 脉冲式水轮机`。主项目元数据接口仍返回模型名称、文件名和文件大小，但文件下载接口返回的二进制不以 FBX 的 `Kaydara FBX Binary` 或 ASCII FBX 标志开头，因此场景库 BFF 在文件校验阶段拒绝缓存并返回 502：

```text
MODEL_DOWNLOAD_FAILED
Remote endpoint did not return a valid FBX file
```

这不是页面缓存、Three.js 居中逻辑或场景库数据库损坏。重复模型 `6642` 和候选 `2334` 也具有相同的无效文件特征，不能作为回退资源。

处理结果：

| 页面 | 原模型 | 新模型 | 结果 |
|---|---:|---:|---|
| `eq-0 水轮机智能运维` | `2353 脉冲式水轮机` | `2363 轴流式水轮机` | 7.31 MiB，有效 FBX，缩略图和完整文件已核验 |

## 2. 同类问题扫描

新增 `npm run audit:model-assets`，逐项读取当前 106 个模型展示配置，检查：

- 模型元数据可访问；
- 存在 FBX/GLB/glTF 文件；
- 声明大小不超过场景库 50 MiB 安全上限；
- 下载接口首段字节与声明格式相符；
- 不输出上游对象存储 key。

首次扫描发现另一项同类失效：

| 页面 | 失效模型 | 替换模型 | 选择理由 |
|---|---:|---:|---|
| `turbine-blade-erosion 水轮机转轮叶片冲蚀预警` | `2286 冲击式水轮机叶片` | `2306 弗朗西斯水轮机转轮` | 8.28 MiB，转轮叶片连续、细节和金属层次清楚，适合冲蚀热区 |

为继续保证模型 ID 唯一，原使用 `2306` 的 `TurbineRunnerHoistingTraining` 改用 `7193 混流式转轮`。它与吊装对象直接匹配、轮廓清楚且只有 1.08 MiB。

最终结果：

```text
UPSTREAM_MODEL_ASSET_AUDIT total=106 valid=106 failures=0 concurrency=3
```

## 3. 后续使用方式

每次模型库更新、页面改绑或正式发布前执行：

```powershell
npm run audit:model-assets
npm run verify:model-library
npm run verify:https-integration
```

审计失败时先停用对应绑定并从候选池替换，不得通过删除文件头校验、放宽任意 URL 或继续返回旧 ID 的缓存来掩盖问题。上游恢复原模型后，也应先重新通过审计和实际渲染，再决定是否恢复绑定。
