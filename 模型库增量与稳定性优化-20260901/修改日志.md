# 修改日志

## 2026-09-09

- 状态：外部模型页面专业化文案与加载稳定性修复已在本地完成并通过验证，尚未执行云端发布。
- 根因一：`modelCatalog.ts` 将 `pageModelBindings.ts` 中用于模型筛选、替换和研发适配的 `note/adaptation` 直接赋给页面公开描述，导致 102 个扩展模型页可能显示文件校验、上游端点、替换原因等内部信息。
- 根因二：模型接口在已有同模型持久缓存时仍等待上游元数据；Bootstrap 同时受最长 10 秒的元数据和 Dashboard 请求阻塞；模型首次下载最多执行两次 30 秒请求，浏览器失败后再等待 30 秒重试，形成长时间加载和稍后自行恢复的现象。
- 根因三：上游设备已配置但测点值为 `null` 时，诊断快照仍被记录，证据生成对空值调用 `toFixed()`，造成诊断接口 500 并被轮询重复触发。
- 文案修复：扩展模型公开描述改为按页面业务与模型对象集中生成，内部 `note/adaptation` 仅保留为研发配置；页面、模型视窗、资源协同和通道抽屉不再展示原始错误码、下载失败原因、内部占位版本或“模拟”耗时标签。
- 状态表达：瞬时波动统一使用“运行数据同步中”“模型资源正在同步”“等待首次同步”等业务状态；有可用版本或最近数据时明确保持展示，不使用红色故障措辞暴露底层实现。
- 加载修复：同模型且模型 ID 已核准的内存/磁盘缓存直接返回，过期检查转为后台执行；旧清单在元数据指纹核验通过后自动补写模型 ID；同场景元数据请求合并，失败退避 8 秒；元数据与 Dashboard 默认超时收敛至 4.5 秒。
- 下载修复：首次模型下载改为默认单次 20 秒有界请求，浏览器准备上限改为 30 秒，失败后以 8 秒间隔进行最多 2 次有限重试；可通过 `MODEL_DOWNLOAD_TIMEOUT_MS`、`MODEL_DOWNLOAD_ATTEMPTS`、`MODEL_METADATA_TIMEOUT_MS`、`MODEL_DASHBOARD_TIMEOUT_MS` 调整。
- 数据回退：服务端保留最近一次可用 Dashboard，短时接口波动时继续返回最近数据；无历史数据时只返回空测点状态，不虚构实时数值。
- 诊断修复：空值测点不进入诊断历史；证据数值增加有限数回退，避免历史脏数据再次触发异常；前端仅在至少存在一个来源数值时请求诊断，消除空数据状态下的五秒重复请求。
- 图表稳定性：历史点不足两条时展示“等待运行数据形成趋势”，达到可绘制条件后再挂载响应式图表，并增加最小宽高约束，避免空图误导及页面切换时产生负尺寸告警。
- 新增约束：`verify:model-library` 检查 102 个公开描述不等于内部备注且不含内部实施词；新增 `verify:model-showcase-ui` 浏览器覆盖 6 个代表页面；新增 `verify:diagnostic-empty-values` 覆盖空值与恢复场景；加载校验增加缓存优先、请求合并、失败退避和超时边界断言。
- 验证：`npm run build`、`npm run verify:model-library`、`npm run verify:model-loading`、`npm run verify:diagnostic-empty-values`、`node scripts/verify-dashboard-isolation.mjs`、`npm run verify:model-showcase-ui` 均通过；浏览器 6 页未发现内部实施措辞、原始故障原因或占位版本泄露。
- 已知检查项：全项目 `npm run typecheck` 仍被 7 个既有维修计划 `three-types.ts` 的非法字符阻断，本轮未修改这些无关文件；Vite 生产构建通过。
