# 本项目本地开发与云端发布方法

## 1. 适用范围与边界

本文供新的开发会话在本地修改 `industrial-intelligent-cockpit`，并发布到场景库服务器 `47.122.104.52`。主平台服务器 `8.146.211.204` 属于另一团队：允许读取既有 HTTPS 模型 API，未经明确授权不得 SSH 登录、改代码或发布。

开始前应先阅读：

```text
外部模型仿真展示方案/
跨项目门户集成方案/
新版本云部署会话交接/README-新会话部署前必读.md
```

所有本轮文档应另建日期文件夹并维护 `修改日志.md`。不得在文档、命令历史或聊天中记录密码、私钥正文、Token 和完整生产环境文件。

## 2. 本地准备

```powershell
git status --short
git log -1 --oneline
npm ci
npm run typecheck:navigation
npm run verify:navigation
```

保留用户已有的未提交修改；不能使用 `git reset --hard` 或清理不明文件。模型 API 地址放在未提交的本地环境配置中，浏览器只访问场景库 `/scene-library-api/`，不能接触上游对象 key。

启动本地生产后端：

```powershell
$env:HOST='127.0.0.1'
$env:PORT='3103'
$env:APP_VERSION='local-验证标识'
npm start
```

常用入口：

```text
http://127.0.0.1:3103/cockpit/
http://127.0.0.1:3103/cockpit/?embedded=1&viewId=eq-0
http://127.0.0.1:3103/api/health
```

## 3. 模型库更新流程

1. 使用主项目分页列表 API 只读取得当前模型清单，按 `model_id` 与上次快照做差分；
2. 先按业务语义、缩略图、文件大小和细节筛选，不为凑数量强行配对；
3. 通过 `src/remoteModelShowcase/pageModelBindings.ts` 建立唯一 `viewId -> modelId` 映射；
4. 修改 `MODEL_ENABLED_CHILD_ORDER`，模型页前置，同时维持受保护页面位置；
5. 运行资源审计和实际模型下载；
6. 页面或模型目录变化时同步更新验证脚本的冻结数量；
7. 主项目详情跳转只允许固定 `/three-model/detail?id=<审核ID>`。

最低验证集：

```powershell
npm run audit:model-assets
npm run verify:model-library
npm run verify:model-loading
npm run verify:model-stability
npm run verify:https-integration
npm run typecheck:navigation
npm run verify:navigation
npm run build:all
```

还应执行 `npm run typecheck` 并记录结果。当前 7 个历史 `three-types.ts` 非法字符错误是已知基线，不能误报成本轮回归，也不能在无关发布中顺手扩大修改范围。

## 4. 提交、菜单和主平台交付包

先提交已经通过验证的运行代码，使菜单 manifest 能引用干净提交：

```powershell
git add -- <本轮文件>
git commit -m "准确描述本轮变化"
$ReleaseId=Get-Date -Format 'yyyyMMdd-HHmmss'
npm run generate:menu-manifest -- --menu-version=$ReleaseId
```

确认 manifest 的 `sourceDirty=false`、`sourceCommit`、20 个根节点、1,050 个节点和内容哈希。然后更新 `scripts/generate-host-navigation-delivery.ts` 的 Release、提交、菜单哈希和模型数，执行：

```powershell
npm run generate:host-navigation-delivery
```

把生成目录压缩为 ZIP，并单独提供 ZIP 的 `.sha256`。主项目团队至少需要 ZIP 与 `.sha256`；ZIP 内 manifest 用于顺序，allowlist 用于模型详情安全白名单，两者必须原子更新。

## 5. 创建场景库发布包

最终代码和文档提交后重新构建，再生成不可覆盖的 Release 包：

```powershell
npm run build:all
powershell -ExecutionPolicy Bypass -File scripts/create-release-package.ps1 -ReleaseId $ReleaseId
Get-FileHash -Algorithm SHA256 "scene-library-release-$ReleaseId.tar.gz"
tar -tzf "scene-library-release-$ReleaseId.tar.gz"
```

包中必须包含两套 dist、`server.ts`、`package.json`、锁文件和 `src/remoteModelShowcase/`；不得包含 `.git`、`node_modules`、`.env`、私钥或本地缓存。

## 6. 云端只安装、不切换

使用用户本机已有的场景库部署私钥，显式指定 `-i` 和 `IdentitiesOnly=yes`。只列文件名，不读取或输出私钥正文。

发布前只读核对：

```text
current / previous 实际指向
scene-library.service active/enabled/NRestarts
systemd ExecStart
127.0.0.1:3102 监听
3103 空闲
nginx -t
磁盘、内存和共享 data/model-cache
```

把包上传到 `/tmp` 后先比较本地/远端字节和 SHA-256。新目录必须是：

```text
/nlplabProj/scene-library/releases/<ReleaseId>
```

在不改变 `current` 的情况下解压，属主设为 `cockpit:cockpit`，用 `/nlplabProj/scene-library/shared/npm-cache` 执行 `npm ci`，并把新 Release 的 `data`、`model-cache` 链接到共享目录。

## 7. 3103 隔离预检

先读取生产 `ExecStart`，复用现场真实的 tsx CLI 启动方式，在 `127.0.0.1:3103` 启动新 Release。不要在 Linux 现场改用 Windows 兼容的 `scripts/run-tsx.mjs`。

至少验证：

```text
health.version 等于 ReleaseId
102/102 页面 Bootstrap
本轮新增/替换模型完整下载
连续和并发加载后 modelMemoryCache 不超过预算
standalone 与 microapp 入口存在
正式 3102 旧服务仍为 active
```

预检结束必须停止 3103，确认没有残留监听。

## 8. 原子切换与自动回滚

切换脚本使用 `set -Eeuo pipefail`，先保存旧 `current`、`previous` 和环境文件。顺序为：

1. `previous` 指向切换前真实 `current`；
2. 更新环境中的 `APP_VERSION`；
3. 原子替换 `current`；
4. 检查两个 www 链接仍跟随 current；
5. 重启 `scene-library.service`；
6. 验证 active、内部健康、Nginx、HTTPS/HTTP 入口和关键模型；
7. 任一步失败就恢复旧链接、旧环境并重启旧服务。

不得删除旧 Release 或共享缓存。完成后记录 `current/previous`、包 SHA-256、Git commit、服务状态、监听、内存、NRestarts、公网入口和回滚目标。

## 9. 发布后验收与交接

```text
https://47.122.104.52/cockpit/
https://47.122.104.52/microapps/scene-library/
https://47.122.104.52/microapps/scene-library/scene-library.js
https://47.122.104.52/scene-library-api/health
http://47.122.104.52:8081/cockpit/
```

运行公网 Bootstrap 和关键模型下载，确认 `NRestarts=0`、3102 只监听回环、3103 已停止。最后推送 Git，并把新主平台导航 ZIP、`.sha256` 以及主项目操作说明交给主平台团队；主平台缓存清理、构建、发布和回滚由其自行执行。
