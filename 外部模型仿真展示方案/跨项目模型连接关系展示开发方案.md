# 设备数字孪生资源协同展示开发方案

> 方案日期：2026-08-10  
> 当前状态：已按用户认可方案完成开发与四场景运行联调（2026-08-10）  
> 适用页面：水轮机、污水泵、桥式起重机、矿卡/拖车牵引车四个外部模型仿真页面  
> 上游项目默认展示名：`ICES-Union 3d2.0`  
> 当前项目展示名：`Industrial Intelligent Cockpit`（仓库：`industrial-intelligent-cockpit`）  
> 约束：业务数据和模型仍然只能通过 API 接入；参考详情页仅允许用户点击“查看资源详情”后人工浏览，业务代码不请求或抓取 HTML，不暴露上游对象存储 key

---

## 0. 方案结论

本方案不新增一个孤立的“说明页面”，而是在现有四个仿真页面中加入统一的跨项目连接展示，使用户能够直接理解：

1. 模型和原始可视化数据属于哪个项目；
2. 当前项目通过什么方式连接上游；
3. 哪些内容来自上游，哪些内容由当前项目加工生成；
4. 模型文件、Dashboard 数据和诊断结果当前分别处于什么状态；
5. 上游异常时，页面当前展示的是实时数据、缓存数据还是本地派生结论；
6. 两个项目之间不存在数据库直连，浏览器也不会直接访问上游对象存储。

核心展示关系：

```text
┌──────────────────────────────┐
│ 来源项目：ICES-Union 3d2.0   │
│ 模型文件 / 元数据 / Dashboard │
└──────────────┬───────────────┘
               │ HTTP REST API
               │ /three-model-api/api/*
               ▼
┌──────────────────────────────┐
│ 当前项目后端：BFF 连接层      │
│ 白名单 / 代理 / 校验 / 缓存   │
│ 状态采集 / 错误转换 / 诊断    │
└──────────────┬───────────────┘
               │ 本项目同源 API
               │ /api/model-showcase/*
               ▼
┌──────────────────────────────┐
│ 当前项目前端：仿真展示页面    │
│ 3D / 参数 / 趋势 / 预测 / 报告│
└──────────────────────────────┘
```

前端新增一张紧凑的“设备数字孪生资源协同”卡片和一个可展开的“设备资源协同状态”抽屉；后端新增连接状态注册表与只读状态接口。状态接口只读取本项目已经采集的运行信息，不因为前端查看协同状态而额外高频请求上游。

## 1. 需求目标与非目标

### 1.1 目标

- 在四页面显式展示来源项目、当前项目和 BFF 中间连接层；
- 显示模型、元数据、Dashboard、工况和数据一致性等链路；
- 明确原始数据与本项目派生数据的所有权和责任边界；
- 显示最近连接时间、响应耗时、缓存状态和最近错误；
- 上游部分异常时提供“降级连接”而不是简单显示全部离线；
- 与现有深色青蓝工业驾驶舱风格一致；
- 四页面共享同一套前后端组件和类型，不复制四份逻辑；
- 不破坏已经实现的模型运行期缓存、数据缓存、分析预测和报告下载。

### 1.2 非目标

- 不修改上游 `ICES-Union 3d2.0` 的模型或数据；
- 不建立两个项目数据库之间的直连；
- 不把 MinIO 对象 key 返回给前端；
- 不允许前端传入任意上游 URL；
- 不在前端直接请求 `8.146.211.204:3100`；
- 业务代码不请求或解析 `/three-model/detail` 参考页面；只允许用户通过固定按钮人工打开；
- 不展示密钥、内部堆栈、存储凭据或服务器文件路径；
- 不把本项目模拟诊断描述成上游项目提供的真实预测模型；
- 本阶段不新增独立一级菜单或第五个仿真页面。

## 2. 两个项目的职责边界

### 2.1 来源项目：ICES-Union 3d2.0

建议前端显示名称：

```text
ICES-Union 3d2.0
外部工业可视化模型服务
```

负责提供：

- 模型基本信息；
- 模型文件列表；
- FBX 模型二进制；
- Dashboard 当前快照；
- 正常、高负荷和故障工况；
- 数据一致性校验；
- 3D 相机、背景色、自动旋转等渲染建议；
- 模型名称、行业、文件名和文件大小等资源元数据。

来源项目不负责：

- 当前项目前端页面布局；
- 当前项目的运行期缓存；
- 当前项目构造的历史趋势；
- 当前项目模拟智能诊断系统；
- 当前项目生成的评估预测报告。

### 2.2 当前项目后端：Industrial Intelligent Cockpit BFF

负责：

- 将四个批准场景映射到四个上游模型 ID；
- 只通过上游 API 请求数据；
- 隐藏上游对象存储 key；
- 校验模型类型、大小、响应类型和文件头；
- 合并并发模型请求；
- 缓存已验证的模型二进制；
- 将上游错误转换为稳定的本地错误码；
- 保存最近连接尝试、成功时间、延迟、错误和缓存状态；
- 基于遥测窗口生成本项目模拟诊断结论；
- 向前端提供同源连接状态快照。

### 2.3 当前项目前端：四个仿真页面

负责：

- 显示两个项目及其连接关系；
- 通过本项目 BFF 获取所有信息；
- 显示 3D、实时参数、趋势、评估、预测和报告；
- 区分“上游原始数据”“本项目转发/缓存”“本项目派生结果”；
- 显示连接正常、部分降级、缓存可用和离线状态；
- 不展示内部诊断算法和上游对象 key。

## 3. 前端展示方案

### 3.1 页面整体位置

在现有页面标题区与“3D 模型 + 实时参数”区域之间新增一张共享资源协同组件：

```text
页面标题、工况按钮、更新时间
────────────────────────────────────────
新增：设备数字孪生资源协同
────────────────────────────────────────
3D 模型                         实时参数
趋势图

```

这样用户无需滚动到页面底部即可看到模型来源，又不会挤占 3D 主视窗。

### 3.2 设备数字孪生资源协同卡

桌面端横向展示三个节点：

```text
┌────────────────────┐      ┌────────────────────┐      ┌────────────────────┐
│ 模型资源平台        │ 接入 │ 安全接入服务        │ 协同 │ 业务应用端          │
│ 模型与运行数据      │ ───▶ │ 授权·校验·复用     │ ───▶ │ 监测·评估·预警     │
│ 设备资源编号 2326   │      │ 模型资源已就绪      │      │ 当前设备仿真场景    │
└────────────────────┘      └────────────────────┘      └────────────────────┘
```

移动端改为纵向节点，避免横向滚动。

每个节点显示：

#### 模型资源平台节点

- 项目名称：`ICES-Union 3d2.0`；
- 服务角色：设备三维模型与运行数据资源平台；
- 当前模型 ID；
- 上游真实模型名称；
- 服务状态：同步正常/部分服务受限/资源暂不可用。

#### 安全接入服务节点

- 接入方式：安全接口服务；
- 业务名称：模型数据安全接入服务；
- 模型资源状态：已就绪/等待首次加载；
- 最近可用时间；
- 当前协同状态。

#### 业务应用端节点

- 应用名称：工业智能驾驶舱；
- 当前设备仿真监测场景；
- 当前能力：三维可视化、运行监测、健康评估、故障预警、分析报告；
- 数据状态：同步正常/资源已就绪/部分服务受限。

### 3.3 链路状态颜色

| 内部状态 | 页面文案 | 颜色 | 业务含义 |
|---|---|---|---|
| `connected` | 资源同步正常 | 绿色/青色 | 核心设备资源最近同步成功 |
| `cached` | 资源已就绪 | 蓝色 | 已验证资源可直接用于当前业务场景 |
| `degraded` | 部分服务受限 | 黄色 | 部分服务异常，但已有资源或其他数据仍可使用 |
| `offline` | 资源暂不可用 | 红色 | 核心资源不可用且没有可展示的已就绪数据 |
| `unknown` | 等待首次同步 | 灰色 | 服务启动后尚未产生该类业务记录 |

连接线采用 CSS 渐变和轻微流动动画；降级时停止流动并显示断点，不使用自制 SVG。

在页面现有 `ID 2326` 标签附近增加两个短标签：

## 4. 后端设计

### 4.1 设计原则

- 连接状态来自现有真实请求，不虚构“在线”；
- 状态采集不能改变现有接口的业务响应；
- 查看连接状态不能额外触发模型下载；
- 同一场景状态在服务运行期间保留；
- 服务重启后状态从 `unknown` 重新积累；
- 上游地址只展示协议、主机和 API Base，不返回对象 key；
- 错误对前端使用稳定错误码，不返回堆栈；
- 连接状态是运行观测，不作为业务数据的唯一来源。

### 4.2 新增运行期连接状态注册表

建议在 `server.ts` 或独立文件 `src/remoteModelShowcase/connectionRegistry.ts` 中实现：

```ts
type ConnectionChannel =
  | 'metadata'
  | 'modelBinary'
  | 'dashboard'
  | 'scenario'
  | 'dataSync'
  | 'diagnosis';

interface ConnectionChannelState {
  channel: ConnectionChannel;
  owner: 'upstream' | 'local-derived';
  status: 'connected' | 'cached' | 'degraded' | 'offline' | 'unknown';
  lastAttemptAt: string | null;
  lastSuccessAt: string | null;
  latencyMs: number | null;
  httpStatus: number | null;
  errorCode: string | null;
  errorMessage: string | null;
  cacheState?: 'hit' | 'miss' | 'empty';
  bytes?: number;
}
```

每个 `sceneId` 保存一组通道状态：

```text
Map<ModelShowcaseSceneId, SceneConnectionState>
```

连接注册表只保留运行信息，不落盘，不存储模型文件副本，不保存上游对象 key。

### 4.3 在现有请求中采集状态

#### `fetchUpstreamJson`

调用方增加场景 ID 和通道类型，用于记录：

- 请求开始时间；
- 成功/失败；
- 响应耗时；
- 上游 HTTP 状态；
- 本地稳定错误码；
- 最近成功时间。

#### `downloadModelBinary`

记录：

- 上游下载成功时间；
- 下载耗时；
- 实际字节数；
- 文件格式校验结果；
- 后端运行期缓存 HIT/MISS；
- `MODEL_STORAGE_UNAVAILABLE` 等错误；
- 当前是否仍有可用缓存。

#### `runDiagnosis`

记录本项目派生通道：

- 最近诊断时间；
- 样本数；
- 是否已产生结论；
- 不把该通道状态归属于上游。

### 4.4 状态聚合规则

推荐总体状态计算：

```text
Dashboard 最近成功 + 模型当前可用
    → connected

Dashboard 最近成功 + 模型只从缓存可用
    → cached

Dashboard 或模型部分失败，但至少有一条业务主链/缓存可用
    → degraded

Dashboard 不可用 + 无旧数据 + 模型不可用 + 无缓存
    → offline

服务启动后尚未产生请求
    → unknown
```

模型已缓存时不应因“最近未访问上游文件接口”判为离线。状态中应同时显示：

- `availability=available`；
- `delivery=runtime-cache`；
- `upstreamLastSuccessAt=<时间>`。

### 4.5 新增本地只读接口

```http
GET /api/model-showcase/:sceneId/connection
Accept: application/json
```

该接口只读取连接状态注册表，不主动请求上游，因此前端可以每 10 秒轮询而不会增加上游负载。

### 4.6 与现有 Bootstrap 的关系

第一版不修改 `/bootstrap` 响应结构。原因：

- `/bootstrap` 负责业务初始化；
- `/connection` 负责运行观测；
- 连接状态会随模型加载和 Dashboard 轮询变化；
- 单独接口可以更新状态而不重复加载 Bootstrap；
- 避免连接状态字段影响现有页面初始化逻辑。


返回四个场景的简化状态，不包含每条通道详情。

### 4.8 上游项目可选增强

基础方案不要求修改来源项目。如果上游团队愿意配合，可选增加：


建议只返回：

- API 服务状态；
- 对象存储连接状态；
- 版本号；

- 不返回凭据、bucket 私有配置和内部异常堆栈。

该接口属于增强项，不作为当前项目实施的前置条件。

## 6. 状态与时间语义

为避免状态误导，前端必须区分以下时间：

| 时间 | 含义 |
|---|---|
| 最近尝试 | 本项目最后一次尝试访问该通道 |
| 最近成功 | 该通道最后一次成功取得有效结果 |
| 数据更新时间 | 当前页面 Dashboard 数据进入缓存的时间 |
| 上游 last_sync | 上游 Dashboard 自带的同步时间 |
| 模型缓存时间 | FBX 通过校验并写入 Node.js 缓存的时间 |
| 状态生成时间 | `/connection` 快照生成时间 |

不能把“当前有缓存”显示为“上游实时在线”。建议文案：

```text
模型可用 · 来源：本项目运行期缓存
上游文件最近成功：2026-08-10 00:27:38
```

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 状态“在线”定义不清 | 用户误以为所有通道实时正常 | 分通道状态，总体状态只做汇总 |
| 有缓存时上游已离线 | 缓存掩盖真实上游状态 | 同时显示可用来源与上游最近成功时间 |
| 连接状态轮询增加上游压力 | 影响外部服务 | `/connection` 只读本地注册表 |

| 错误信息泄露对象 key | 暴露存储结构 | 注册表只记录稳定错误码和清洗后的消息 |
| 新连接条占用首屏高度 | 3D 区域被挤压 | 使用紧凑节点，详情放抽屉 |
| 状态逻辑散落在组件 | 四页面表现不一致 | 统一 Hook、状态标签和聚合函数 |
