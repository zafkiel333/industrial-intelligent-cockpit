## 1. 关键架构决策

### 决策 1：所有模型和数据都通过 API 获取，绝不请求或解析详情页

用户给出的四个 `/three-model/detail?id=...` 链接只承担“告诉开发者应该使用哪个模型 ID”的参考作用。实际代码中：

- **不会**请求 `/three-model/detail`；
- **不会**抓取或解析详情页 HTML；
- **不会**从详情页 DOM 中提取模型地址或数据；
- 模型元数据、模型二进制、实时参数、工况和一致性结果，全部调用 `模型api接口说明文档.md` 规定的 `/three-model-api/api/...` 接口获取。

外部 API 使用 HTTP，模型文件较大，并且后续部署环境可能使用 HTTPS。为统一处理混合内容、错误、缓存和安全问题，采用 BFF（Backend for Frontend）模式：

- 浏览器只访问本项目的同源 `/api/model-showcase/*` 接口；
- `server.ts` 负责访问 `http://8.146.211.204:3100/three-model-api`；
- 后端统一处理超时、上游错误、响应格式、缓存、安全白名单和二进制流转发；
- 不把上游 `file_url` 作为可由浏览器任意提交的参数，避免形成通用代理或 SSRF 入口；
- 只允许本计划四个场景 ID、四个模型 ID和三种场景类型。

拟新增本地接口：

| 方法 | 本地路径 | 用途 | 对应上游接口 |
|---|---|---|---|
| `GET` | `/api/model-showcase/:sceneId/bootstrap` | 聚合模型基本信息、文件信息和首屏 Dashboard | 模型基本信息 + Dashboard |
| `GET` | `/api/model-showcase/:sceneId/model` | 流式转发该场景配置中的 FBX/GLB/GLTF 文件 | 模型文件下载 |
| `GET` | `/api/model-showcase/:sceneId/dashboard` | 获取最新运行快照，供轮询 | Dashboard |
| `POST` | `/api/model-showcase/:sceneId/scenario/:type` | 切换 `normal/high_load/fault` 工况 | 场景模板加载 |
| `POST` | `/api/model-showcase/:sceneId/data-sync` | 将当前值提交给上游做一致性校验 | 数据一致性校验 |
| `POST` | `/api/model-showcase/:sceneId/diagnosis` | 调用本项目的模拟智能诊断服务，读取已采集数据并返回结论 | 本地诊断推理模块，不调用详情页 |

本地接口与上游 API 的精确对应关系：

| 本地后端操作 | 上游 API（均位于 `/three-model-api` 下） | 是否请求详情页 |
|---|---|---|
| 查询模型基本信息 | `GET /api/v1/three-model/models?model_id=<modelId>` | 否 |
| 查询模型文件 | `GET /api/v1/three-model/models/files?model_id=<modelId>` | 否 |
| 下载模型二进制 | `GET /api/v1/three-model/models/files?file_url=<编码后的API返回值>` | 否 |
| 获取当前 Dashboard 快照 | `GET /api/visual-models/<modelId>/dashboard` | 否 |
| 获取指定工况快照 | `POST /api/visual-models/<modelId>/scenario/<type>` | 否 |
| 执行数据一致性校验 | `POST /api/visual-models/<modelId>/data-sync` | 否 |

后端约束：

- 上游 Base URL 使用环境变量 `VISUAL_MODEL_API_BASE_URL`，默认值为文档中的测试地址；
- JSON 请求默认 10 秒超时，模型文件请求默认 60 秒超时；
- Dashboard 短缓存不超过 1 秒，模型元数据缓存 5 分钟；
- 模型二进制由 Node 流式转发，不整文件读入内存；
- 响应增加合理的 `Cache-Control`，让浏览器复用不变的模型文件；
- 校验文件后缀仅允许 `.fbx`、`.glb`、`.gltf`，并设置最大允许文件体积；
- 上游故障统一映射成可识别的 `502/504`，不向前端泄露服务器堆栈；
- 客户端断开时取消上游请求。

### 决策 1.1：完整数据请求时序

#### A. 首次进入页面

```text
浏览器
  → GET 本项目 /api/model-showcase/<sceneId>/bootstrap
本项目 server.ts
  → GET 上游 API /api/v1/three-model/models?model_id=<modelId>
  → GET 上游 API /api/visual-models/<modelId>/dashboard
  ← 规范化并合并模型信息 + Dashboard
浏览器
  ← 用返回值初始化标题、状态条、参数卡、图表、评估和 Viewer 配置
```

`bootstrap` 是本项目自己提供的 JSON API，不是对详情页的包装或抓取。

#### B. 加载 3D 模型

```text
浏览器
  → GET 本项目 /api/model-showcase/<sceneId>/model
本项目 server.ts
  → GET 上游 API /api/v1/three-model/models/files?model_id=<modelId>
  → 从 API 响应中选择受支持的文件
  → GET 上游 API /api/v1/three-model/models/files?file_url=<API返回的file_url>
  ← 将模型二进制流式转发给浏览器
浏览器
  ← FBXLoader/GLTFLoader 渲染模型
```

前端只知道本项目的 `/model` 地址，不直接持有或拼接上游 `file_url`。

#### C. 动态数据刷新

默认实时模式：

```text
每 5 秒：浏览器 → 本项目 /dashboard
         本项目 → 上游 API /api/visual-models/<modelId>/dashboard
```

用户选择 `normal/high_load/fault` 工况后：

```text
立即请求且后续每 5 秒：浏览器 → 本项目 /scenario/<type>
                       本项目 → 上游 API /api/visual-models/<modelId>/scenario/<type>
```

这样切换到高负载或故障工况后，后续刷新仍保持该工况，不会被默认 Dashboard 快照覆盖。

#### D. 数据一致性校验

```text
用户点击“校验”
  → 前端从当前 API 快照整理 actual_values
  → POST 本项目 /data-sync
  → POST 上游 API /api/visual-models/<modelId>/data-sync
  ← 独立展示一致率、等级和逐字段差异
```

一致性校验不会修改设备运行数据，也不会替代健康评估。

#### E. 智能诊断与故障预测

每次 Dashboard/Scenario API 返回成功后，本项目后端会把规范化快照写入该场景的短期历史缓冲区。前端不负责计算诊断结论，只负责触发诊断并展示结果：

```text
上游 Dashboard/Scenario API
  → 本项目后端记录当前快照和最近 60 个采样点
前端定期或在工况切换后
  → POST 本项目 /api/model-showcase/<sceneId>/diagnosis
本项目模拟智能诊断服务
  → 读取当前值、正常范围、趋势、波动和设备专属故障知识
  → 执行诊断与预测推理
  ← 返回健康结论、风险等级、故障候选、概率、预测窗口和维护建议
前端
  ← 只展示预测结果，不展示诊断模型结构、参数、权重、算法或推理过程
```

该诊断服务在工程结构上按“独立模型服务”设计接口，但本次不训练、加载或调用真实机器学习模型。内部使用已有 API 数据构造设备相关的统计特征、趋势判断和组合诊断规则，生成稳定、合理且可重复的预测结论。以后接入真实模型服务时，只替换后端推理实现，前端结果结构保持不变。

### 决策 2：四页共用一套实现，页面差异由配置驱动

不复制四份大型页面。使用共享页面、共享 3D Viewer、共享数据 Hook 和每设备配置表：

- 页面包装组件只声明场景 ID；
- 公共页面根据场景目录读取标题、模型 ID、字段权重、故障模式和 3D 动画规则；
- 公共组件负责页面布局、加载态、错误态、轮询、趋势图、工况切换、评估报告和模型释放；
- 以后新增第五个远端模型时，原则上只增加一条目录配置和一个菜单入口。

### 决策 3：远端快照组成滚动时序，不伪装成真实历史数据

- 当前 API 的 Dashboard/Scenario 返回“当前快照”，没有返回历史时序数组；
- 首屏请求 `bootstrap`；默认模式成功后每 5 秒请求一次 `dashboard`；选择工况后改为每 5 秒请求对应的 `scenario/:type` API；
- 每次收到快照后，以本地接收时间作为时间戳，将字段值追加到长度为 60 的环形序列，约覆盖最近 5 分钟；
- 数值卡片在两次快照间使用插值动画平滑过渡，不额外改变真实返回值；
- API 返回什么值，当前数值卡和评估就使用什么值；不会再对 API 的 `value` 叠加 `Math.random()`；
- 工况切换立即调用 `scenario/:type`，成功后建立该工况的独立短期趋势，不等待下一个轮询周期；
- 页面隐藏时暂停轮询，恢复可见时立即刷新；
- 连续失败时指数退避，保留最后一次成功数据并明确标记“数据陈旧”，不静默伪造在线数据；
- 如果 API 未来返回带时间戳的时序数组，则直接按 API 时间顺序播放/循环，不再由前端采样快照拼接；
- 只有在 API 明确只给范围、没有给当前值或时序值时，才允许在范围内进行平滑、确定性的低幅模拟，并在 UI 标注“本地范围模拟”；
- 如果 API 请求失败，则不启用范围模拟来伪装在线状态，只显示最后成功值或离线状态。

### 决策 4：3D 模型使用 Three.js 官方加载器并正确清理资源

- 当前四个文件全部是 FBX，使用 `three/examples/jsm/loaders/FBXLoader.js`；
- Viewer 同时预留 GLB/GLTF 分支，便于后续模型格式变化；
- 相机位置、背景色和自动旋转优先读取 `render_config`；
- 模型加载后用包围盒自动居中和归一化缩放，页面配置可覆盖缩放、旋转和偏移；
- 显示加载进度、失败重试、重置视角、自动旋转开关和全屏操作；
- 组件卸载时取消动画帧、断开 ResizeObserver、释放 geometry/material/texture/renderer，并移除 Canvas；
- 不使用外部 Blob URL 时无需前端创建 Object URL；如果后续改为 Blob 缓存，必须同步 `URL.revokeObjectURL`。

`visual_binding` 是自然语言描述，不保证与 FBX 节点名称完全一致。实现时先对模型节点名称做精确/模糊匹配；匹配不到时使用顶层设备动画和 HUD 标注降级，不能因节点不存在导致页面崩溃。

### 决策 5：建立模拟智能诊断系统，前端只展示诊断与预测结论

本次上游提供基准值、正常范围、当前值、趋势和异常标记，但没有可直接调用的真实预测模型。按用户要求，项目内部建立一个行为上类似独立预测模型系统的“模拟智能诊断服务”：

- 后端服务读取当前快照与最近 60 个采样点，不由前端现场拼接诊断文案；
- 内部从数据构造偏离度、趋势斜率、移动均值、波动率、持续越界时长和多指标相关异常等特征；
- 按设备配置的故障知识和统计评分输出诊断及预测；
- 同一组输入必须得到稳定、可复现的结论，避免每次刷新随机更换故障类型；
- 结论连续多次达到阈值后再升级，恢复也需要连续正常样本，减少临界值附近反复跳变；
- 前端只展示结果，不展示“预测模型”本体，不展示网络结构、算法流程、特征权重、规则表达式或调参面板；
- 页面可显示“智能诊断结论”“故障预测”“维护建议”等结果性标题；
- 文档和代码注释会如实记录当前推理实现是模拟诊断引擎，便于以后替换为真实模型服务。

模拟诊断系统的内部处理流程：

1. 读取最新 API 快照、正常范围、上游异常标记和近期历史；
2. 计算各指标相对范围位置、越界程度、变化斜率和波动特征；
3. 结合设备专属故障模式进行多指标匹配；
4. 计算整体健康度、风险等级和故障候选概率；
5. 根据趋势延续速度生成未来 24 小时/72 小时风险和建议维护窗口；
6. 输出结构化诊断结果，由前端渲染成结论卡和报告；
7. `data-sync` 一致性结果单独展示，不混入健康结论，避免把“数据一致”误解释成“设备健康”。

拟返回的诊断结果结构：

```ts
interface DiagnosisResult {
  diagnosisId: string;
  generatedAt: string;
  dataWindow: { sampleCount: number; startAt?: string; endAt?: string };
  healthScore: number;
  riskLevel: 'healthy' | 'attention' | 'warning' | 'critical';
  conclusion: string;
  faultPredictions: Array<{
    faultCode: string;
    faultName: string;
    probability: number;
    horizon: '24h' | '72h' | '7d';
    expectedWindow: string;
    evidence: string[];
  }>;
  recommendations: string[];
  confidence: number;
}
```

前端实际展示 `healthScore`、`riskLevel`、`conclusion`、`faultPredictions`、`recommendations`、`confidence` 和生成时间；`diagnosisId` 只用于请求追踪，数据窗口可作为次要信息。模型版本、特征、规则和权重不在页面展示。

## 2. 四个页面的数据与诊断设计

### 2.1 水轮机多工况数字孪生仿真

- 核心字段：转速、轴承温度、主轴振动、水压、流量、输出功率；
- 3D 联动：转速驱动转轮旋转速度，振动驱动轻微轴向抖动，温度/异常状态驱动局部或整体告警色，流量使用粒子/流线 HUD 表达；
- 评估重点：水力稳定性、轴系健康、温升风险、运行效率；
- 预测故障：主轴不平衡、轴承过热、水力空化/流量异常、过载或功率衰减；
- 建议图表：转速/功率双轴趋势，压力/流量趋势，温度/振动健康带。

### 2.2 污水泵运行效能与故障仿真

- 核心字段：转速、泵体温度、振动、出口压力、流量、功率；
- 3D 联动：泵体旋转、振动幅度、温度颜色、压力表盘、管路流速；
- 评估重点：扬程/流量匹配、单位流量能耗、机械稳定性；
- 预测故障：气蚀、进口堵塞、叶轮磨损、轴承/密封异常、电机过载；
- 建议图表：压力-流量联合趋势、功率/流量效能趋势、温振联合风险图。

### 2.3 桥式起重机载荷安全数字孪生仿真

- 核心字段：负载重量、小车位置、大车运行速度、电机温度、振动；
- 3D 联动：吊钩升降或载荷标识、小车沿轨道移动、大车运动、驱动电机温升和振动告警；
- 评估重点：载荷利用率、运行冲击、驱动系统温升、结构振动；

### 2.4 矿卡牵引运输状态与故障仿真（待 Q1 确认）

## 3. 页面布局与视觉规范

四页沿用项目现有 `SciFiCard`、Rajdhani 字体和青蓝色驾驶舱视觉语言，不另起一套主题。

建议布局：

1. 页面标题区：设备名称、场景 ID、上游模型 ID、当前工况、在线/陈旧/离线状态；
2. 数字孪生同步条：最近同步时间、响应延迟、数据点数量、数据源；
3. 主区 12 栅格：左侧 8 栅格为 3D Viewer，右侧 4 栅格为实时指标和健康度；
4. 中部：2～3 张滚动趋势图以及正常范围带；
5. 底部：设备评估报告、故障预测、维护建议、一致性校验；
6. 工况控制：正常、高负载、故障三个按钮，颜色分别使用绿色、橙色、红色；
7. 加载/错误态：骨架屏、模型加载百分比、上游超时提示和重试按钮。

颜色语义继续使用：青蓝=信息，绿色=正常，橙色=关注，红色=故障，紫色=预测/推演。

### 3.1 API 数据到页面区域的映射

| API 数据 | 展示位置 | 展示方式 | 更新机制 |
|---|---|---|---|
| `twin_status` | 页面顶部孪生同步条 | ONLINE/OFFLINE、最近同步、延迟、数据点、数据源 | 每次 API 快照更新 |
| `equipment` | 设备概况卡 | 实际模型名称、设备状态、额定能力 | 首屏 + 工况切换 |
| `bindable_fields[].value` | 实时参数卡 | 当前值、单位、趋势箭头、异常颜色 | 每次 API 快照更新并做视觉插值 |
| `normal_min/normal_max` | 参数卡和趋势图 | 正常范围文字、图表安全带、越界标记 | 使用 API 返回范围，不自行猜测 |
| `trend` | 参数卡 | 上升/下降/稳定图标 | 以上游为主，同时可用短期序列复核 |
| `visual_binding` | 3D Viewer | 决定字段驱动旋转、位移、颜色、振动或 HUD 的目标 | 模型加载后建立绑定 |
| `render_config` | 3D Viewer | 相机初始位置、注视点、背景色、自动旋转 | 首屏初始化；用户可临时调整 |
| `model_config` | 模型信息卡 | 面数、材质数 | 首屏展示 |
| `scenario_templates` | 工况控制和对比卡 | 正常/高负载/故障基准值预览 | 首屏读取 |
| `acceptance` | 接口质量卡 | 响应耗时、是否达标、最大允许时间 | 每次 API 快照更新 |
| `data-sync` 响应 | 一致性校验面板 | 总一致率、等级、逐字段 expected/actual/diff | 用户点击校验后更新 |

### 3.2 动态数据的展示设计

#### 当前 API 快照

当前 Dashboard/Scenario 每次返回一组 `bindable_fields` 当前值。页面以同一份快照同步驱动：

1. 参数卡数字和状态；
2. 趋势图新增一个时间点；
3. 3D 动画目标值；
4. 健康度和风险贡献；
5. 故障预测与维护建议；
6. 孪生同步状态和接口响应指标。

上述区域不能各自生成独立随机值，避免出现“卡片正常、图表异常、3D 又是另一状态”的数据不一致。

#### API 时序数据（为接口后续扩展预留）

如果未来某接口返回 `[{time, value...}]` 类型的时序：

- 保留 API 原始时间戳和顺序；
- 按采样间隔逐点播放，播放到末尾可根据页面设置停止或循环；
- 图表展示完整/滑动窗口数据；
- 当前播放点同步驱动参数卡、3D 和评估；
- 页面只控制播放速度，不改写原始数值。

#### API 仅返回范围

如果某字段只有最小值/最大值而没有当前值：

- 用有边界的正弦/缓动轨迹生成连续值，不使用每帧无规则跳变；
- 正常模式在范围中部小幅变化；
- 高负载模式在上半区变化，但不越过正常上限；
- 故障模式按故障模板允许越界；
- 页面明确标记该字段为“本地范围模拟”；
- 一旦 API 开始返回真实 `value`，立即停止本地模拟并平滑切换到 API 值。

### 3.3 图表设计

- 水轮机：转速/功率、压力/流量、温度/振动三组趋势；
- 污水泵：压力-流量、功率-流量效能、温度/振动三组趋势；
- 起重机：载荷/速度、小车位置、电机温度/振动三组趋势；
- 矿卡页面：转速/功率、温度/振动、液压压力/燃油流量三组趋势；
- 每张趋势图显示正常范围带、最新值、单位和异常点；
- 默认保留 60 个 API 采样点，不为了填满图表而预先伪造历史数据；首次进入时从 1 个点逐步累积。

### 3.4 3D 数据联动设计

- 模型只通过模型下载 API 加载一次，数据轮询不会重新下载模型；
- 每个新快照只更新已有 Three.js 场景中的旋转速度、位置、材质颜色、振动幅度或 HUD；
- 3D 动画用当前值相对正常范围的归一化比例驱动，避免不同单位直接作为动画参数；
- `fault` 工况用红色轮廓/告警点表达，不能通过夸张位移破坏模型；
- 若 API 的 `visual_binding` 找不到对应 FBX 节点，则降级为整机轻量动画和标注，不影响数据卡与图表的真实性。

### 3.5 评估报告的数据来源

- 当前健康度：由后端模拟智能诊断服务读取最新 API 值、正常范围和近期历史后输出；
- 趋势风险：由诊断服务根据最近采集到的 API 快照序列计算；
- 故障候选：由诊断服务结合设备专属故障知识、当前异常字段和趋势组合输出；
- 一致性：直接展示 `data-sync` API 返回结果；
- 报告不得引用详情页文字作为实时数据，也不得把本地模拟值描述为传感器实测值。

前端只展示以下结论性信息：

- 综合健康分和风险等级；
- 一段设备诊断结论；
- 最可能的故障类型及概率；
- 预测时间范围/可能发生窗口；
- 建议检查项、维护动作和优先级；
- 结论生成时间与置信度。

前端不展示预测模型图、模型结构、算法名称、输入层/输出层、训练数据、特征权重、规则公式或推理流程。

- 每页显示后端诊断服务输出的健康分、风险等级、诊断结论、故障概率、预测窗口和维护建议；

## 11. FBX 模型定时更新优化计划（2026-08-12）

> 状态：`方案已记录，待用户批准后实施`。本节只规划模型更新机制，不改变 5 秒运行数据轮询、诊断、报告或页面配色。

### 11.1 现状与问题

- 模型元数据缓存为 5 分钟，但后端 `modelBinaryCache` 中的 FBX 二进制没有过期时间，首次成功后会一直复用到 Node.js 进程停止；
- 前端 `modelBufferCache` 以固定模型地址为键，成功加载的 `ArrayBuffer` 会保留到浏览器应用停止运行；
- 现有 5 秒数据轮询、10 秒连接状态轮询和“立即刷新”不检查模型新版本；30 秒模型重试仅在没有可用模型且加载失败时生效；
- 因此前端、后端即使能够读到新的模型元数据，也可能继续展示旧 FBX。服务重启和浏览器完整刷新目前是最可靠的强制更新方式。

### 11.2 更新策略

默认每 36 小时检查一次模型更新，处于用户要求的 1～2 天范围内，并允许通过环境变量 `MODEL_BINARY_REFRESH_HOURS` 调整为 24～48 小时。

1. 首次没有缓存时，同步下载并校验模型；
2. 缓存未到期时直接返回，不额外访问上游 FBX；
3. 缓存到期后继续向页面提供旧模型，同时在后台合并发起一次更新，避免页面空白和并发重复下载；
4. 使用 `model_id`、`file_id`、`file_url`、`file_size`、`update_time`、`edit_time` 构造元数据指纹，并对下载文件计算 SHA-256；
5. 上游出现新版本时只记录为“候选版本”，新文件完成格式、体积、哈希和可解析性校验后，才原子替换旧缓存并提升“当前可用版本”；内容未变化时只更新检查时间，不提升版本；
6. 上游覆盖同一路径但未更新元数据时，定期强制下载校验仍可通过文件哈希发现变化；
7. 更新失败时保留旧模型并标为“使用上次可用版本”，默认 6 小时后重试，不采用短周期反复下载；
8. 四个场景分别管理更新时间，并继续复用现有同场景并发请求合并机制；
9. 当前可用模型必须保存为服务器持久化的“最后成功版本”，保证 Node.js 重启、浏览器刷新或上游数据库/模型存储临时不可用时仍有模型可展示；
10. 手动更新与定时更新使用同一套校验和原子切换流程，不能绕过缓存安全检查。

### 11.3 后端改动

- 扩展模型元数据类型，保留 API 返回的 `update_time`、`edit_time`；
- 扩展二进制缓存记录，增加 `cachedAt`、`lastCheckedAt`、`nextRefreshAt`、`assetFingerprint`、`contentHash`、`activeVersion`、`candidateVersion`、更新状态和最近错误；
- 将模型获取改为“缓存优先、到期后台更新、成功后原子替换、失败保留旧文件”；
- 为模型响应增加 `ETag`、`Last-Modified`、`X-Model-Version`、`X-Model-Cached-At` 和 `X-Model-Next-Refresh`；
- 在连接状态接口中返回模型版本、上次更新、上次检查、下次检查、更新中和陈旧状态；
- 连接状态仍可每 10 秒读取，但只有达到 `nextRefreshAt` 时才允许触发一次非阻塞上游检查，不会每 10 秒下载模型；
- 将已校验模型及版本清单写入服务器持久缓存目录，使用临时文件校验后原子改名；服务启动时优先恢复最后成功版本，更新失败不得删除或覆盖该文件；
- 新增受限的 `POST /api/model-showcase/:sceneId/model/refresh` 手动检查接口，返回“检查中、已是最新、更新成功、更新失败并使用旧版本”等结果；同场景默认 10 分钟限频，并复用并发请求锁。

### 11.4 前端改动

- 在模型描述和连接状态类型中增加 `version`、`updatedAt`、`lastCheckedAt`、`nextRefreshAt` 和更新状态；
- 模型请求地址携带版本号，前端缓存键调整为“场景 ID + 模型版本”，版本变化后自动请求新文件；
- 版本变化后必须为新版本重新请求新的 `ArrayBuffer`，不得把旧版本缓存冒充为新版本；
- 使用“活动模型 + 候选模型”两阶段切换：旧 `ArrayBuffer` 和正在渲染的 Three.js 对象保持活动，新版本在后台独立下载、解析并完成首帧验证，成功后才接管显示并释放旧版本资源；
- 新版本请求、数据库访问、模型存储或解析失败时，不清空活动模型，也不进入全屏无模型状态；继续展示最后成功版本，并在模型视窗下方以小字标注“本次模型更新未成功，继续使用上次可用版本”，同时显示失败时间和精简原因；
- 如果浏览器重载后内存中没有旧 `ArrayBuffer`，则从本项目后端持久化的最后成功版本恢复；只有从未成功缓存过任何模型时才显示初次加载失败页；
- 页面展示模型版本、上次成功更新时间、上次检查时间、下次检查时间，以及“最新、更新中、使用旧版本、更新失败”等状态；
- 在模型视窗操作区增加“检查并更新模型”按钮，与运行数据刷新按钮分离。点击后显示检查进度，成功时自动切换，未变化时提示“当前已是最新版本”，失败时保留旧模型和小字提示；按钮遵守后端限频，检查期间禁用，避免重复下载大文件。
