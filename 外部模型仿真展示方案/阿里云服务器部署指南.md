## 1. 本次部署使用的固定配置

| 配置项 | 固定值 | 说明 |
| --- | --- | --- |
| 项目目录 | `/nlplabProj/cockpit` | 前端和后端统一存放位置 |
| 前端静态目录 | `/nlplabProj/cockpit/dist` | 本地构建好的 `dist` 解压位置 |
| Nginx 公网端口 | `8081` | 浏览器访问端口 |
| Node 后端端口 | `3101` | 只供本机 Nginx 代理使用 |
| Nginx 配置名 | `cockpit` | `/etc/nginx/sites-available/cockpit` |
| 环境变量文件 | `/etc/cockpit.env` | Node 生产环境配置 |
| systemd 服务名 | `cockpit` | `/etc/systemd/system/cockpit.service` |
| 外部模型 API | `http://8.146.211.204:3100/three-model-api` | `server.ts` 访问的上游服务 |

本文中仅以下内容需要按实际情况替换：

- `<ECS_PUBLIC_IP>`：阿里云 ECS 公网 IP；
- `<SSH_USER>`：SSH 用户，如 `root`；
- `<SSH_KEY_PATH>`：使用密钥登录时的本地私钥路径。

最终访问地址为：

```text
http://<ECS_PUBLIC_IP>:8081
```

## 2. 为什么不能只上传 dist

前四个外部模型仿真页面会请求：

```text
/api/model-showcase/:sceneId/bootstrap
/api/model-showcase/:sceneId/connection
/api/model-showcase/:sceneId/model
/api/model-showcase/:sceneId/dashboard
/api/model-showcase/:sceneId/scenario/:type
/api/model-showcase/:sceneId/data-sync
/api/model-showcase/:sceneId/diagnosis
```

这些接口全部定义在 `server.ts` 中。`dist` 只包含浏览器前端文件，不能提供这些接口。

因此服务器目录需要包含：

```text
/nlplabProj/cockpit/
├── dist/
├── src/
├── node_modules/
├── server.ts
├── package.json
└── package-lock.json
```

其中 `node_modules` 不从本地上传，而是在服务器上执行 `npm ci` 安装。

## 3. 修正现有 Nginx 配置的问题

当前配置中出现了两次：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

同一个 `server` 块不能存在两个完全相同的 `location /`，否则 `nginx -t` 会报告重复 location。

另外，API 路由应使用：

```nginx
location ^~ /api/
```

这样 `/api/*` 会优先转发到 Node 后端，不会被静态资源正则或 SPA 回退规则处理。

完整正确配置见第 11 节。

## 4. 本地准备部署 ZIP

以下命令在本地 Windows PowerShell 中执行。

### 4.1 准备前端 ZIP

本地完成构建后，项目根目录应存在：

```text
dist/index.html
dist/assets/
```

将 `dist` 内部文件压缩为固定名称 `cockpit-dist.zip`：

```powershell
Compress-Archive `
  -Path .\dist\* `
  -DestinationPath .\cockpit-dist.zip `
  -Force
```

说明：

- ZIP 根目录会直接包含 `index.html` 和 `assets`；
- 不会在 ZIP 内再嵌套一层 `dist`；
- `-Force` 表示覆盖本地旧 ZIP。

### 4.2 准备后端 ZIP

在项目根目录执行：

```powershell
tar -a -c -f cockpit-backend.zip `
  server.ts `
  package.json `
  package-lock.json `
  src
```

说明：

- 后端 ZIP 固定命名为 `cockpit-backend.zip`；
- 包含 `server.ts`、npm 依赖清单和完整 `src`；
- 不上传本地 `node_modules`；
- `src/remoteModelShowcase` 是外部模型接口的后端实现，必须上传；
- `src/data` 是上传数据和场景数据的运行目录，也应上传。

本地最终应得到：

```text
cockpit-dist.zip
cockpit-backend.zip
```

## 5. 上传两个 ZIP 到服务器

以下命令仍在本地 Windows PowerShell 中执行。

使用密码登录时：

```powershell
scp .\cockpit-dist.zip <SSH_USER>@<ECS_PUBLIC_IP>:/tmp/
scp .\cockpit-backend.zip <SSH_USER>@<ECS_PUBLIC_IP>:/tmp/
```

使用 SSH 私钥时：

```powershell

  .\cockpit-dist.zip `

scp -i "<SSH_KEY_PATH>" `
  .\cockpit-backend.zip `
  <SSH_USER>@<ECS_PUBLIC_IP>:/tmp/
```

上传后，服务器应存在：

```text
/tmp/cockpit-dist.zip
/tmp/cockpit-backend.zip
```

## 7. 从零安装服务器环境

### 7.1 更新软件源

```bash
sudo apt update
```

### 7.2 安装 Nginx、unzip 和基础工具

```bash
sudo apt install -y nginx unzip curl ca-certificates build-essential
```

各软件用途：

- `nginx`：提供静态页面并反向代理 `/api/`；
- `unzip`：解压上传的两个 ZIP；
- `curl`：测试前端、后端和外部 API；
- `ca-certificates`：提供 HTTPS 根证书；
- `build-essential`：用于可能存在的 npm 原生依赖编译。

启动并设置 Nginx 开机自启：

```bash
sudo systemctl enable --now nginx
```

### 7.3 安装 Node.js 22

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x -o /tmp/nodesource_setup.sh
sudo bash /tmp/nodesource_setup.sh
sudo apt install -y nodejs
```

验证版本：

```bash
node --version
npm --version
nginx -v
```

Node.js 应显示 `v22.x`。当前 Vite 8 要求 Node.js `20.19+` 或 `22.12+`。

## 9. 解压前端和后端文件

### 9.1 解压后端

```bash
sudo unzip -q -o \
  /tmp/cockpit-backend.zip \
  -d /nlplabProj/cockpit
```

### 9.2 解压前端 dist

```bash
sudo unzip -q -o \
  /tmp/cockpit-dist.zip \
  -d /nlplabProj/cockpit/dist
```

参数说明：

- `-q`：减少解压日志；
- `-o`：同名文件存在时覆盖；
- `-d`：指定固定解压目录。

### 9.3 设置目录权限

```bash
sudo chown -R cockpit:cockpit /nlplabProj/cockpit
sudo chmod -R u=rwX,go=rX /nlplabProj/cockpit
```

说明：

- Node 服务以 `cockpit` 用户运行，需要写入 `src/data` 和临时上传目录；
- Nginx 以 `www-data` 用户运行，通过 `go=rX` 获得静态文件读取权限。

### 9.4 检查解压结构

```bash
test -f /nlplabProj/cockpit/dist/index.html \
  && echo "dist 解压正确"

test -f /nlplabProj/cockpit/server.ts \
  && echo "server.ts 解压正确"

test -f /nlplabProj/cockpit/package.json \
  && echo "package.json 解压正确"

test -d /nlplabProj/cockpit/src/remoteModelShowcase \
  && echo "外部模型后端模块解压正确"
```

四条检查都应该有成功输出。

## 10. 安装项目运行依赖

## 12. 创建 systemd 后端服务

创建：

```bash
sudo nano /etc/systemd/system/cockpit.service
```

写入：

```ini
[Unit]
Description=Industrial Intelligent Cockpit Backend
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=cockpit
Group=cockpit
WorkingDirectory=/nlplabProj/cockpit
EnvironmentFile=/etc/cockpit.env

ExecStart=/usr/bin/node /nlplabProj/cockpit/node_modules/tsx/dist/cli.mjs /nlplabProj/cockpit/server.ts

Restart=on-failure
RestartSec=5
TimeoutStopSec=20
NoNewPrivileges=true
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

重新加载 systemd：

```bash
sudo systemctl daemon-reload
```

启动并设置开机自启：

```bash
sudo systemctl enable --now cockpit
```

检查状态：

```bash
sudo systemctl status cockpit --no-pager
```

正确状态应为：

```text
active (running)
```

查看后端日志：

```bash
sudo journalctl -u cockpit -n 100 --no-pager
```

## 14. 修改 Nginx 配置

### 14.1 确认没有其他配置占用 8081

```bash
sudo nginx -T 2>/dev/null | grep -n 'listen 8081'
```

如果旧配置文件已经监听 8081，应直接修改旧文件或禁用旧配置，不能保留两个相互竞争的 8081 站点。

本文统一使用：

```text
/etc/nginx/sites-available/cockpit
/etc/nginx/sites-enabled/cockpit
```

### 14.2 编辑 cockpit 配置

```bash
sudo nano /etc/nginx/sites-available/cockpit
```

将文件完整替换为：

```nginx
server {
    listen 8081;
    listen [::]:8081;

    server_name cockpit;

    root /nlplabProj/cockpit/dist;
    index index.html;

    # 限制上传请求大小。当前后端接口支持文件上传。
    client_max_body_size 100m;

    # API 必须交给运行在 3101 的 server.ts。
    # ^~ 可防止 API 请求进入后面的静态资源正则 location。
    location ^~ /api/ {
        proxy_pass http://127.0.0.1:3101;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_connect_timeout 10s;
        proxy_send_timeout 180s;
        proxy_read_timeout 180s;
        proxy_request_buffering off;
    }

    # 静态资源缓存。
    location ~* \.(?:js|css|png|jpg|jpeg|gif|svg|ico|webp|woff|woff2|ttf|glb|gltf|fbx|bin)$ {
        try_files $uri =404;
        expires 7d;
        access_log off;
        add_header Cache-Control "public";
    }

    # React/Vite 单页应用路由回退。
    # 整个 server 块中只能存在一个 location /。
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

该配置已经修正原配置中的两个问题：

1. 删除了重复的第二个 `location /`；
2. 将 API location 改为 `location ^~ /api/`。

### 14.3 启用 cockpit 配置

如果软链接尚不存在：

```bash
test -L /etc/nginx/sites-enabled/cockpit \
  || sudo ln -s \
    /etc/nginx/sites-available/cockpit \
    /etc/nginx/sites-enabled/cockpit
```

如果以前使用的是 `/etc/nginx/sites-enabled/project-a`，并且它也监听 8081，需要先确认它确实是本项目的旧配置，再禁用该软链接：

```bash
sudo ls -l /etc/nginx/sites-enabled/project-a
```

确认后执行：

```bash
sudo unlink /etc/nginx/sites-enabled/project-a
```

不要删除 `/etc/nginx/sites-available/project-a`，保留原文件便于回退。

### 14.4 检查并重新加载

```bash
sudo nginx -t
```

必须看到：

```text
syntax is ok
test is successful
```

然后执行：

```bash
sudo systemctl reload nginx
```

## 15. 配置防火墙和阿里云安全组

### 15.1 Ubuntu UFW

先确保 SSH 不会被阻断：

```bash
sudo ufw allow OpenSSH
```

只开放公网访问端口 8081：

```bash
sudo ufw allow 8081/tcp
sudo ufw enable
sudo ufw status numbered
```

不要开放 3101。3101 只允许 Nginx 从服务器本机访问。

### 15.2 阿里云安全组

在 ECS 安全组入方向添加：

| 协议 | 端口 | 来源 | 用途 |
| --- | --- | --- | --- |
| TCP | `8081` | `0.0.0.0/0` 或公司公网 IP | 驾驶舱页面 |
| TCP | `22` | 管理员公网 IP `/32` | SSH |

不要在阿里云安全组中开放 3101。

如果 ECS 安全组限制出方向，需要允许访问：

```text
目标：8.146.211.204/32
协议：TCP
端口：3100
```

### 18.4 常见现象

| 现象 | 原因 | 检查位置 |
| --- | --- | --- |
| API 返回 `text/html` | `/api/` 没有代理到 Node | Nginx `location ^~ /api/` |
| `502 Bad Gateway` | Node 没启动或 3101 不通 | `systemctl status cockpit` |
| `504 Gateway Timeout` | 外部模型 API 超时 | 上游 3100、白名单和出方向规则 |
| `413 Request Entity Too Large` | 上传超过 Nginx 限制 | `client_max_body_size` |
| 页面 403 | Nginx 无权读取 dist | `/nlplabProj` 和 `dist` 权限 |
| 页面刷新 404 | 缺少 SPA 回退 | `try_files ... /index.html` |

### 18.5 `npm ci` 报 `EUSAGE` 或锁文件不同步

如果出现：

```text
npm error code EUSAGE
npm ci can only install packages when your package.json and package-lock.json are in sync
```

表示服务器上的 `package.json` 与 `package-lock.json` 不是同一套依赖定义。不要在服务器上随意修改依赖版本，也不要删除锁文件后继续部署。

当前项目的本地 `package-lock.json` 已重新生成并通过 `npm ci --dry-run` 校验。只需从本地重新上传最新锁文件：

```powershell
scp .\package-lock.json \
  <SSH_USER>@<ECS_PUBLIC_IP>:/tmp/package-lock.json
```

在服务器上用最新锁文件替换部署目录中的旧文件：

```bash
sudo install \
  -o cockpit \
  -g cockpit \
  -m 644 \
  /tmp/package-lock.json \
  /nlplabProj/cockpit/package-lock.json
```

确认 `package.json` 和锁文件都存在：

```bash
cd /nlplabProj/cockpit
ls -l package.json package-lock.json
```

重新安装：

```bash
sudo -u cockpit -H npm ci
```

安装成功后检查 `tsx`：

```bash
test -f /nlplabProj/cockpit/node_modules/tsx/dist/cli.mjs \
  && echo "依赖安装成功"
```

然后启动或重启服务：

```bash
sudo systemctl restart cockpit
sudo systemctl status cockpit --no-pager
```
