# 系统响应日志与预测场景日志

日期：2026-09-10。当前范围：水轮机页面 `sim-visual-hydro-turbine`，模型 `2326`。

## 两类日志的边界

系统响应日志记录页面功能的响应性能，内容为功能名称、上下文、`T_start`、`T_end`、`Δt`和完成状态。它不记录设备是否正常、故障部位或处置建议，也不属于场景日志。

场景日志记录预测和实测核验形成的业务事件，内容为设备编号、预测范围、正常或异常状态、持续越界、疑似故障、重点部位、核验覆盖率和标签对照。它不记录上传耗时、接口耗时或页面渲染耗时。

页面顶部提供“场景日志”和“系统响应日志”两个独立入口。同一时间只展开一种日志，避免信息混杂。

## 系统响应日志

每次完成或中止的计时操作保存为一条结构化记录：

| 字段 | 含义 |
|---|---|
| `traceId` | 当前浏览器会话内的唯一响应编号 |
| `action` | 文件上传与解析、预测结果生成、验证结果展示等功能名称 |
| `context` | 设备编号、预测编号或所属任务上下文 |
| `start` | `T_start`，用户完成必要交互后开始处理的毫秒时间戳 |
| `end` | `T_end`，结果完成提交并取得浏览器绘制机会的毫秒时间戳 |
| `duration` | `T_end - T_start`，与页面显示值严格一致 |
| `status` | `completed`、`failed`或`cancelled` |
| `recordedAt` | 服务端完成日志写入的时间 |

日志展开后按一次操作分组，固定依次显示开始记录、结束记录、时延记录。`T_end`记录的下一行必须是对应的`Δt`，不得插入其他操作。处理中操作可先显示`T_start`；完成后补齐结束和时延。

就近时延条仍只显示所属功能最近一次结果，便于快速查看；独立系统响应日志保存并展示全部已记录操作，便于追溯。

删除、重置等管理操作不启动时延计时，也不写入系统响应日志。日志写入采用唯一编号去重，并在服务进程内缓存已写编号，避免日志增长后每次追加都全量扫描文件。

## 场景日志

预测记录保存后立即形成业务日志，已有预测记录在首次查询时补齐对应日志。验证数据保存后形成阶段性或完整核验日志；重复提交相同验证内容不会重复记账。

日志等级使用以下规则：

| 等级 | 颜色 | 使用条件 |
|---|---|---|
| 正常 | 绿色 | 预测状态正常，未来窗口内六项指标未形成持续越界；或正常标签核验一致 |
| 信息 | 蓝色 | 无实际标签的数值核验、异常预测与异常实测一致等一般业务记录 |
| 关注 | 黄色 | 发现趋势线索但未达到明确预警；或一般标签偏差，需要复核 |
| 预警 | 橙色 | 预测状态异常且达到预警或高风险，存在可定位的持续越界和疑似故障部位 |
| 严重预警 | 红色 | 风险等级为`critical`，并且存在严重持续越界；同时满足连续时长不少于60分钟或存在至少两项持续越界 |

红色严重预警不能由单点波动、普通数值偏差、文件异常或接口失败触发。预测日志使用“预测”“疑似”“建议复核”等措辞，不把预测结果描述为已经发生的现场故障。

预测日志至少写明预测窗口、持续越界项数、疑似故障、重点部位、最早预计时间和检查建议。正常预测同样写入日志，明确六项指标未形成持续越界及常规复核建议。核验日志写明预测tag、实际tag、是否一致、覆盖率和sMAPE；缺失实际tag时明确只核验数值误差。

## 存放位置

模型数据目录下使用独立文件，互不混写：

```text
<modelDataRoot>/logs/system-response-events.jsonl
<modelDataRoot>/logs/scene-prediction-events.jsonl
```

生产环境对应：

```text
/nlplabProj/scene-library/shared/data/model-showcase/sim-visual-hydro-turbine__model-2326/logs/system-response-events.jsonl
/nlplabProj/scene-library/shared/data/model-showcase/sim-visual-hydro-turbine__model-2326/logs/scene-prediction-events.jsonl
```

日志文件位于共享数据目录，不随代码Release切换而丢失。删除某次预测或设备数据不自动删除既有日志，日志用于保留当时已形成的业务结论和响应事实。

## 验收要求

- 两类日志入口独立，内容不串用。
- 每条完成响应均有`T_start`、`T_end`和`Δt`，且`end - start = duration`。
- `T_end`后紧跟对应的`Δt`记录。
- 正常与异常预测都能形成场景日志；红色只用于满足严重条件的预测。
- 场景日志能够区分预测结果和实测核验，并显示设备编号。
- 日志刷新后可从服务端文件恢复，重复请求不生成重复记录。
- 1600px和390px视口下日志可读且无横向溢出。
