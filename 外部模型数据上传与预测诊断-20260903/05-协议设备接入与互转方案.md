# Modbus 与 IEC 61850 设备接入及互转方案

> 状态：协议来源文件解析、统一点位、双向遥测转换和适配器写入接口已开发；尚未取得现场参数并连接实际设备  
> 目标：Modbus 与 IEC 61850 设备均可直接接入，并在明确点位映射后进行双向遥测数据转换

## 1. 已确认协议范围

Modbus 计划覆盖：

- Modbus TCP；
- Modbus RTU；
- 现场确有需要时兼容 Modbus ASCII；
- 作为客户端读取设备，以及作为服务器向 IEC 61850 侧发布转换后的点位数据。

IEC 61850 计划覆盖：

- IED、逻辑设备、逻辑节点、数据对象和数据属性寻址；
- MMS 读取和报告接收；
- 质量属性、源时间戳和功能约束；
- 作为 IEC 61850 数据源发布由 Modbus 转换而来的点位，具体能力依据选用协议库和设备工程配置验证。

两类协议均以实际设备连接为交付标准。开发和自动测试可以使用协议测试端，但不能用测试端结果代替具体设备或厂家认可网关的实机验收。

## 2. 总体架构

```text
Modbus TCP / RTU / ASCII 设备
             |
       Modbus Adapter
             |
             v
      Canonical Point Bus
       |      |       |
       |      |       +--> 页面当前数据、预测、诊断、下载
       |      +----------> 规范化持久存储
       +-----------------> Mapping / Conversion Engine
                                  |
                           IEC 61850 Adapter
                                  |
                           IEC 61850 设备或网关
```

不进行原始报文逐字节互转。两个适配器分别解析各自协议，统一转换为带语义的点位记录；转换引擎再依据映射表生成目标协议的数据对象或寄存器值。

当前页面已落地的文件接入路径为：

```text
CSV/XLSX/JSON 协议来源文件
    -> 来源解析器（Modbus 寄存器长表 / IEC 61850 对象长表）
    -> 导入预检与点位映射预览
    -> 用户确认
    -> 统一点位记录
    -> 当前数据、预测、诊断和下载
```

协议来源长表采用固定字段契约：Modbus 为 `timestamp,device_id,unit_id,function_code,address,raw_value,data_type,byte_order,scale,offset,unit,quality`；IEC 61850 为 `timestamp,device_id,ied,object_reference,functional_constraint,value,unit,quality`。允许额外扩展列，但固定列不能缺少或改名。

这条路径解决的是“设备或网关已经导出文件”的接入。它不等同于通过 TCP、串口或 MMS 建立实时设备连接；实时直连仍需按第 8 节准备现场参数并单独验收。

## 3. 统一点位模型

所有设备值先转为同一结构：

```json
{
  "sceneId": "sim-visual-hydro-turbine",
  "modelId": 2326,
  "deviceId": "HT-2326-01",
  "pointId": "vibration",
  "value": 2.14,
  "unit": "mm/s",
  "timestamp": "2026-09-03T00:00:05.000Z",
  "quality": "good",
  "origin": "modbus:line-1:unit-3",
  "sequence": 1082
}
```

页面、预测和诊断只消费该统一结构，不根据来源切换算法或展示形式。`origin` 仅用于内部追踪、去重、转换防环和故障排查，不用于在页面给样例数据增加“模拟/仿真”标识。

## 4. Modbus 兼容范围

每台 Modbus 设备单独配置：

- TCP 地址与端口，或串口、波特率、校验、数据位和停止位；
- 单元/从站 ID；
- 线圈、离散输入、输入寄存器和保持寄存器；
- 功能码、零基/一基地址、连续读取分组；
- `int16`、`uint16`、`int32`、`uint32`、`float32`、位域和字符串；
- 字节序、字序、缩放、偏移、单位和非法值；
- 轮询周期、超时、重试、断线退避和设备时区。

同一型号不同具体设备使用不同 `deviceId` 和连接配置，但仍归属于同一页面的 `modelId` 与当前数据。

## 5. IEC 61850 兼容范围

计划支持：

- IED、逻辑设备、逻辑节点、数据对象和数据属性寻址；
- MMS 读取与报告接收；
- 功能约束、质量属性和源时间戳保留；
- 由 SCL/点表导入映射草稿，再经人工核对发布；
- 作为网关向 IEC 61850 侧提供经批准的映射数据，具体服务器能力依据选用协议库确认。

GOOSE、SV 和控制命令对实时性、联锁和安全有额外要求，不在本轮遥测采集与值转换范围内。

## 6. 双向转换

支持两个数据方向：

```text
Modbus -> 统一点位 -> IEC 61850 数据对象
IEC 61850 -> 统一点位 -> Modbus 寄存器/线圈
```

每条转换映射至少定义：

| 项目 | 说明 |
|---|---|
| 源点位 | Modbus 寄存器地址或 IEC 61850 对象路径 |
| 目标点位 | 目标对象路径或寄存器地址 |
| 数据类型 | 有符号、无符号、浮点、布尔、枚举或字符串 |
| 换算 | 比例、偏移、单位转换和精度 |
| 质量 | 通信失败、越界、陈旧值和不确定值的映射 |
| 时间 | 源时间戳、接收时间及目标侧表示方式 |
| 更新策略 | 周期、变化触发、死区和最大静默时间 |
| 冲突规则 | 同一点位多来源时的优先级和拒绝条件 |

转换引擎必须具备：

- `origin + sequence` 防环，禁止 A 转 B 后再次作为新值转回 A；
- 类型溢出、精度损失和无对应质量码时拒绝或降级并记录；
- 映射版本化，修改映射后保留生效时间和版本号；
- 断线本地有限缓冲、恢复后按时间顺序补传，过期数据不冒充实时值；
- 每个设备独立连接状态、吞吐量、最后成功时间和错误摘要；
- 转换状态不影响原始数据继续保存和页面分析。

第一版双向转换限定为遥测数据和值发布。设备控制写入、保护动作和联锁命令必须另设安全需求与实机审批，不能由普通页面操作直接触发。

## 7. 配置结构

每个页面模型维护一份转换配置，并允许同型号设备实例覆盖连接参数：

```text
<sceneId>__model-<modelId>/
├─ protocol/
│  ├─ mapping.schema.json
│  ├─ mapping.v1.json
│  └─ devices/
│     ├─ HT-2326-01.json
│     └─ HT-2326-02.json
```

密码、证书私钥和真实设备地址不写入样例、前端、普通日志或 Git；配置文件只引用部署环境中的凭据键。

## 9. 页面文件接入验收

协议来源文件的验收至少包括：

1. Modbus 长表按寄存器地址聚合，比例、偏移、数据类型和字节序转换正确；
2. IEC 61850 长表按对象路径聚合，功能约束、质量和源时间戳保留；
3. 预检阶段不改变当前数据，确认后才形成批次并触发预测诊断；
4. 未映射点位可见，缺少必需点位的时间记录不进入预测；
5. 协议来源和原始文件可在批次记录中区分，按设备删除后不残留批次文件；
6. Modbus 和 IEC 61850 文件均可从页面下载对应 CSV、XLSX、JSON 样例。
7. IEC 61850 SCL 在确认前只位于临时导入目录，确认后永久保存到当前模型 `protocol/scl/`，并记录文件哈希；删除运行数据不连带删除 SCL。
8. 空值、非数值、明显越界、缺点和重复点位在预检中分类计数；复杂单位猜测和跨时间自动补点不执行。

## 10. 实机验收

协议“可使用”必须以真实设备或厂家认可的网关完成验收，不能只以模拟器通过代替：

1. 读取全部批准点位并与设备侧数值核对；
2. 校验类型、字节序、单位、精度、质量和时间戳；
3. 连续运行、断网、重启、设备离线和异常码恢复；
4. 验证两个方向的数据转换、映射精度和防环；
5. 验证多台同型号设备不会串用 `deviceId`；
6. 记录设备型号、固件、协议版本、映射版本和验收结果。
