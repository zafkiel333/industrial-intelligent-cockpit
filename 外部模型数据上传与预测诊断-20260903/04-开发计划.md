# 外部模型数据上传与预测诊断开发计划

> 计划版本：v0.3  
> 日期：2026-09-04  
> 当前状态：10 项需求已确认；4 页 P0 已完成开发、发布和自动化验收，待用户体验评审

## 1. 已确认需求

| 用户要求 | 规划实现 |
|---|---|
| 所有外部模型页最终具备数据传入 | 先改造 4 个原始页面试点，用户定稿后按批次推广至 106 页 |
| 一个页面只对应一个模型、一个 ID、一套数据 | 以 `sceneId + modelId` 建立唯一当前数据仓，不提供多活动数据集切换 |
| 同型号的不同实际设备分次传入 | 每次文件传入提供设备 ID 输入框，该标签写入本批次全部记录 |
| 上传和解析进度可视化 | 浏览器真实字节进度与服务端解析/校验进度使用两条独立进度条 |
| 覆盖、增加、重置、删除 | 导入前选择操作模式；危险操作先显示影响摘要及确认/取消弹窗 |
| 展示已有数据基本情况 | 展示数据总量、设备数、字段、时间范围、质量分布、导入批次和变更时间 |
| 所有数据后续处理一致 | 系统生成、文件上传、协议采集均进入同一规范化、预测、诊断和展示链路 |
| 页面不标注模拟等字样 | 不在页面、图表、结果或报告中显示“模拟/仿真数据”标识 |
| 连接两类协议设备 | 支持 Modbus 和 IEC 61850 设备直连采集 |
| 两类协议互相转换 | 使用统一点位模型和映射引擎实现 Modbus 与 IEC 61850 两个方向的数据转换与发布 |
| 预测算法符合实际场景 | 共用计算组件，每个模型分别配置字段、机理特征、阈值和故障规则 |
| 支持资料和结果下载 | 下载模型数据规范、数据样例、预测结果和分析报告 |
| 不做权限隔离 | 不增加角色权限；危险操作只使用明确的确认/取消交互保护 |
| 不限制大小、永久保存 | 不设业务容量和保留期上限；采用流式处理，只有磁盘/基础设施不足时明确失败 |

## 2. 核心设计

### 2.1 一页一模型一套当前数据

```text
页面 sceneId
  -> 固定 modelId
  -> 唯一 current dataVersion
       -> 一个或多个 device_id
       -> 一个或多个导入/采集批次
       -> 同一套预测、诊断、图表和报告
```

`device_id` 表示同型号下的具体设备实例，不创建新页面或新模型 ID。每次文件传入必须填写一个设备 ID，并应用于本批次全部记录；另一台设备通过后续传入填写另一标签。页面可以筛选某台设备或查看汇总，但所有数据仍属于该页面唯一数据仓。

### 2.2 来源不同，处理一致

文件上传、Modbus、IEC 61850、上游 Dashboard 和系统生成样例只在接入层不同。进入规范化点位后，统一执行：

```text
字段映射 -> 单位/时间/质量校验 -> 当前数据 -> 可视化
                                      -> 预测 -> 诊断 -> 报告
```

来源信息只保存在批次清单中用于追踪，不改变算法，不形成另一套页面状态，也不在用户界面添加“模拟/仿真”声明。

### 2.3 数据操作

| 操作 | 行为 | 交互保护 |
|---|---|---|
| 覆盖 | 解析成功后，以本批次有效记录替换输入设备 ID 的当前数据，其他设备不受影响 | 显示目标设备和替换影响；确认/取消 |
| 增加 | 将新记录合并到当前数据，支持新增 `device_id` | 选择冲突策略后执行 |
| 重置 | 恢复该模型随项目提供的初始样例 | 显示将移除的当前数据概况；确认/取消 |
| 删除批次 | 删除该批次对当前数据的贡献并重算结果 | 显示受影响设备、记录和时间范围；确认/取消 |
| 删除范围 | 按设备、时间或两者组合删除并重算 | 显示预估删除量；确认/取消 |
| 删除全部 | 清空页面当前数据，保留模型资料和可下载样例 | 强提醒；确认/取消，默认焦点为取消 |

增加模式使用 `device_id + timestamp` 作为记录冲突主键，并允许选择：保留已有值、使用新值、发现冲突取消。操作先在临时版本完成，解析、合并和分析成功后原子替换；失败不破坏当前数据。

### 2.4 已有数据概况

页面数据管理面板至少包括：

- 概况指标：总记录数、设备数、字段数、最早/最晚数据时间、最后导入时间、最近操作；
- 设备分布：每个 `device_id` 的记录数、时间覆盖和最后数据时间；
- 时间覆盖图：按设备显示数据区间、空档和重叠；
- 质量概况：有效、不确定、无效和缺失数量；
- 批次历史：导入时间、文件名、覆盖/增加方式、设备、有效/拒绝行、状态；
- 操作结果：重置、删除和协议采集造成的最近变更。

图表读取当前 `dataVersion` 的聚合摘要，不一次加载全部原始记录。

### 2.5 协议连接与互转

协议已确认为 Modbus 与 IEC 61850。Modbus 适配器覆盖 TCP、RTU，实际需要时增加 ASCII；IEC 61850 适配器覆盖 MMS 读取、报告和数据对象映射。两类适配器均以连接实际设备为交付目标，不以导出文件或测试模拟器替代实机验收。

双向转换路径为：

```text
Modbus 设备 <-> Modbus Adapter <-> Canonical Point Bus
                                     <-> Mapping Engine
                                     <-> IEC 61850 Adapter <-> IEC 61850 设备
```

转换基于点位映射，不转发原始报文；必须处理类型、地址/对象、字节序、单位、比例、质量、时间戳、更新周期、冲突和防环。第一版互转范围为遥测数据和值发布，普通页面不直接发出设备控制、保护或联锁命令。详见 `05-协议设备接入与互转方案.md`。

### 2.6 下载能力

每个页面提供四类下载：

1. 数据规范：可选 PDF、DOCX、JSON，包含字段、类型、单位、范围、必填项、设备 ID 和示例；
2. 数据样例：可选 CSV、XLSX、JSON，或一次下载包含三种格式的 ZIP；
3. 预测结果：可选 CSV、XLSX、JSON，包含当前 `dataVersion` 的时间、字段、预测值和区间；
4. 分析报告：可选 PDF、DOCX、JSON，包含数据概况、预测、诊断证据和算法版本。

页面只提供上述四个下载入口，不增加解析错误清单或其他下载项。每次下载先选择设备 ID 和文件格式，默认带出页面当前筛选设备；未筛选时带出该模型第一台已有设备。统一文件名为 `<模型ID>-<页面中文模型名>-设备ID-<设备ID>-<中文资料名>.<扩展名>`，ZIP 内文件使用同一规则。删除全部数据后，规范和样例仍可下载，但需填写用于内容和归档命名的设备 ID；预测结果和报告显示无可下载内容。

## 3. 分批推广计划

| 批次 | 页面范围 | 目的 | 推广条件 |
|---|---|---|---|
| P0 试点 | 4 个原始页：水轮机 `2326`、污水泵 `2328`、桥式起重机 `2316`、矿卡/牵引车 `2310` | 覆盖水轮、泵、起重、移动设备四种场景，验证完整交互和共用架构 | 用户逐页体验并确认上传、数据管理、图表、预测、报告和页面布局 |
| P1 扩展试点 | 从 102 个扩展页中选 10 页，补齐其余 10 个设备算法族 | 验证不同字段 schema 和模型专属算法 | P0 用户意见全部处理并形成冻结版 UI/API 契约 |
| P2～P5 | 剩余 92 页，按设备族分 4 批，每批 23 页 | 控制批量改造风险，逐批完成资料、样例和算法 | 上一批自动校验和人工抽查通过 |

P0 未经用户确认不得进入 P1。P0 反馈导致的数据结构、交互或接口变更应先在 4 页回归，再冻结为推广模板，避免在 106 页重复返工。

## 4. 分阶段实施

### Phase 0：需求基线和设备资料

- 将 10 项已确认要求固化为 v0.3 基线；
- 收集 Modbus 与 IEC 61850 设备的厂商、型号、接口、点位表、SCL 和通信参数；
- 核对 4 个 P0 模型现有字段、3D 联动和诊断接口；
- 形成 P0 页面数据管理区线框和操作状态表，提交用户确认后才编码。

完成门槛：两类设备具备可执行点位资料，P0 页面范围和交互基线明确。

### Phase 1：P0 模型资料与样例

- 为 4 个模型分别建立 schema、数据说明、算法说明和协议映射模板；
- 水轮机、污水泵、桥式起重机、矿卡分别设计符合实际应用的特征与故障规则；
- 为每个模型生成正常、渐进退化和故障数据，并将每种数据分别导出 CSV、XLSX、JSON；
- 样例使用与上传数据完全相同的导入和处理链；
- 生成可下载样例和说明文件。

完成门槛：4/4 模型资料完整，每模型 3 个样例文件通过各自 schema，三种格式解析结果一致。

### Phase 2：单数据仓、上传和生命周期 API

- 基于 `SCENE_DATA_DIRECTORY/model-showcase/` 实现每页面唯一当前数据仓；
- 实现分块上传、断点续传、两条进度、预览、覆盖、增加、冲突处理、重置和删除；
- 每次上传要求填写设备 ID，支持同模型不同设备、多批次、时间倒序输入、重复记录、缺失、错误单位和质量异常；
- 建立当前有效数据的批次清单和 `dataVersion`，不建立用户操作审计；
- 不设置文件大小、行数、批次数、保存期限和单模型容量上限，上传、解析、合并和预测采用流式或分块处理；
- 数据永久保存，只有用户主动删除才移除；磁盘不足时明确失败且不改变当前数据；
- 所有变更使用临时版本、并发锁和原子替换；
- 实现概况聚合、设备分布、时间覆盖和批次查询；
- 实现样例、说明、预测结果和报告下载接口。

完成门槛：并发导入、服务重启、失败回滚及所有数据操作均不损坏当前数据。

### Phase 3：P0 页面交互与可视化

- 在共用页面工具区增加上传图标按钮和数据管理入口；
- 上传弹窗提供必填设备 ID 输入框，再选择覆盖或增加，并显示文件、模型 ID 和冲突策略；
- 第一条进度展示已发送字节，第二条展示解析、校验、合并和分析进度；
- 展示数据概况、设备分布、时间覆盖、质量和批次历史；
- 覆盖、重置、删除均只弹出一次包含影响摘要的确认/取消弹窗；
- 历史值、实时值、预测区间和诊断结果读取同一个当前数据版本；
- 页面及报告不显示“模拟/仿真”数据标识；
- standalone、embedded 和 microapp 三种布局均验证窄屏和滚动。

完成门槛：4 个 P0 页面功能完整、布局稳定，用户能够明确了解已经传入哪些设备、多少数据及何时传入。

### Phase 4：P0 模型预测与报告

- 为 4 个模型分别实现预处理、场景特征、趋势预测和故障诊断；
- 水轮机使用水力/轴系耦合特征，泵使用压力-流量-功率关系；
- 起重机使用载荷、制动和位置跟踪特征，矿卡使用动力、液压和温振负荷残差；
- 数据不足或质量不满足要求时输出证据不足，不强行生成结论；
- 预测结果、诊断和 PDF 报告均绑定 `dataVersion` 与算法版本；
- 系统生成、上传和协议数据运行完全相同的算法路径。

完成门槛：4 个模型各类样例和边界数据结果合理，同一输入结果可复现。

### Phase 5：Modbus 与 IEC 61850 设备连接及互转

- 实现 Modbus TCP/RTU 连接、点位读取、断线恢复和设备实例配置；
- 实现 IEC 61850 MMS/报告连接、对象读取、质量与源时间戳映射；
- 实现统一点位模型、映射配置、两个转换方向、类型/单位/质量转换和防环；
- 先用双方协议测试端验证，再连接真实设备或厂家认可网关；
- 每台设备分别记录连接状态、最后数据时间和转换状态；
- 协议数据增量进入同一页面当前数据并触发同一预测流程。

完成门槛：Modbus 与 IEC 61850 真实设备均可采集，双向遥测转换通过点对点核对；实机结果单独记录。

### Phase 6：P0 用户评审与冻结

- 提供 4 个试点页供用户实际体验；
- 逐项记录数据操作、概况、图表、算法、下载、报告和协议反馈；
- 修订后在 4 页完成全量回归；
- 用户最终确认后冻结组件、API、schema 基线和视觉规范。

完成门槛：取得用户对 P0 的明确推广确认。未确认时停止在此阶段，不改造其余页面。

### Phase 7：P1～P5 推广

- P1 选择 10 个扩展页补齐全部 14 个算法族；
- 为每个模型单独确认字段、范围、样例、预测逻辑和故障规则；
- P2～P5 每批 23 页，按设备族复用组件但不复用不合适的业务参数；
- 每批执行目录、schema、样例、算法、页面绑定和跨模型隔离检查；
- 每批完成后更新修改日志和覆盖清单。

完成门槛：106/106 页面均具有独立资料、唯一当前数据和通过验证的预测配置。

### Phase 8：稳定性、发布与回滚

- 验证连续切换页面、并发解析、长时间协议采集和双向转换的内存与句柄；
- 执行现有模型资源、加载、HTTPS、导航、双构建和 106/106 审计门禁；
- 使用新 Release、3103 隔离预检、原子切换和自动回滚；
- 生产运行数据保留在 shared data，不打入 Release，不因代码回滚被删除；
- 更新本目录修改日志及独立云端执行记录。

完成门槛：技术验收、实机协议验收和浏览器业务验收均完成后才宣布上线。

## 6. 回归保护

- P0 只影响 4 个批准页面，其余 102 页在用户确认前保持原状；
- 106 个模型绑定和模型详情白名单不减少，资源审计继续为 106/106；
- `eq-18` 原数据页面和菜单位置不变；
- `eq-unit1-model` 位置不变，原始 4 页顺序不变；
- 菜单根节点和唯一节点数量不因本功能增加页面而变化；
- 模型内存缓存继续受 8 项/128 MiB 预算控制；
- 浏览器模型 ArrayBuffer 缓存继续受限并释放 WebGL context；
- 数据解析与协议任务不得触发模型二进制预热；
- 运行数据不得进入模型二进制缓存或 Release；
- 代码回滚不得删除 shared data。

| 6 | 大小、保留和删除 | 不设业务大小上限，永久保存；删除只弹出一次确认/取消弹窗 |

| 10 | 下载内容 | 只提供数据规范、数据样例、预测结果和分析报告 |

3. 可用于实机联调的设备、网关或厂家测试环境。
