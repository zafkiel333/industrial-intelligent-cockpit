# 外部模型数据格式与存储规范

> 状态：设计稿，尚未实施  
> 目标：让文件上传、设备协议和系统生成样例进入同一个可验证的数据模型，并在规范化后采用完全一致的处理与展示

## 1. 数据来源分层

| 来源 | `sourceType` | 用途 |
|---|---|---|
| 用户上传 CSV/XLSX/JSON | `upload` | 历史数据导入、分析和预测 |
| Modbus TCP | `modbus-tcp` | 设备或网关实时采集 |
| Modbus RTU/ASCII | `modbus-serial` | 串口设备或串口网关采集 |
| IEC 61850 | `iec61850` | IEC 61850 设备实时采集 |
| 主项目 Dashboard | `upstream-dashboard` | 现有运行数据输入 |
| 本项目生成样例 | `generated` | 无实际数据阶段的初始数据与下载样例 |

来源只用于内部追踪、故障排查和导入记录。所有数据经过字段映射、单位换算、时间归一化和质量校验后，进入同一套当前数据、图表、预测与诊断流程；页面不因来源显示“模拟/仿真”标识，也不采用不同算法。

## 2. 推荐存放位置

统一复用现有 `SCENE_DATA_DIRECTORY`，不把生产上传数据绑定在版本化 Release 中：

```text
本地默认：<仓库>/src/data/model-showcase/
生产环境：/nlplabProj/scene-library/shared/data/model-showcase/
```

每个页面模型使用独立目录，目录键同时包含受审核的 `sceneId` 和 `modelId`。一个目录只维护一套当前规范化数据；不同时间导入的文件和不同具体设备作为批次与 `device_id` 写入该套数据，不建立多个可切换的活动数据集：

```text
<SCENE_DATA_DIRECTORY>/model-showcase/
└─ <sceneId>__model-<modelId>/
   ├─ README.md
   ├─ schema.json
   ├─ algorithm.md
   ├─ protocol/
   │  ├─ mapping.schema.json
   │  ├─ mapping.v1.json
   │  └─ devices/
   ├─ samples/
   │  ├─ normal.csv / normal.xlsx / normal.json
   │  ├─ degrading.csv / degrading.xlsx / degrading.json
   │  └─ fault.csv / fault.xlsx / fault.json
   ├─ batches/
   │  └─ <batchId>/
   │     ├─ raw/<fileId>.<ext>
   │     ├─ accepted.jsonl
   │     ├─ rejected.jsonl
   │     └─ manifest.json
   ├─ current/
   │  ├─ manifest.json
   │  └─ data/YYYY/MM/DD/<小时>.jsonl
   ├─ live/
   │  └─ YYYY/MM/DD/<小时>.jsonl
   └─ analysis/
      ├─ latest.json
      └─ history/<analysisId>.json
```

示例：

```text
src/data/model-showcase/sim-visual-hydro-turbine__model-2326/
src/data/model-showcase/eq-0__model-2363/
src/data/model-showcase/eq-16__model-8736/
```

`README.md`、`schema.json`、协议映射模板、三种格式的样例和 `algorithm.md` 属于可版本控制的模型资料；`batches/`、`current/`、`live/` 和 `analysis/` 属于运行数据，生产环境必须位于 shared data，默认不提交 Git。运行数据不设置自动过期或定期清理，只有用户明确删除时才移除。发布脚本后续需要明确包含资料模板，但不得把生产上传文件打入 Release 包。

## 3. 输入文件格式

### 3.1 推荐 CSV

UTF-8、逗号分隔、第一行为稳定字段名：

```csv
timestamp,device_id,quality,rpm,temperature,vibration,pressure,flow_rate,power_output
2026-09-03T08:00:00.000+08:00,HT-2326-01,good,300.2,67.8,2.1,0.51,15.2,89.7
```

固定列：

| 字段 | 必需 | 规则 |
|---|---|---|
| `timestamp` | 是 | ISO 8601，必须带时区；解析后统一保存为 UTC |
| `device_id` | 文件中可选 | 每次传入时由用户在必填输入框填写；1～128 个字母、数字、`-`、`_`、`.` |
| `quality` | 否 | `good`、`uncertain`、`bad`，缺失时为 `good` |
| 指标列 | 是 | 使用该模型 `schema.json` 中的 canonical field 名称 |

### 3.2 XLSX

- 工作表 `telemetry`：列名与 CSV 完全一致；
- 可选工作表 `metadata`：键值形式记录设备、来源、时区和备注；
- 不再要求 `_1/_2/...` 表头；
- 不执行公式、宏或外部链接；公式单元格只接受已保存的数值结果；
- 只支持 `.xlsx`，不支持旧 `.xls`。

### 3.3 JSON

```json
{
  "schemaVersion": "1.0",
  "sceneId": "sim-visual-hydro-turbine",
  "modelId": 2326,
  "deviceId": "HT-2326-01",
  "sourceType": "upload",
  "timezone": "Asia/Shanghai",
  "records": [
    {
      "timestamp": "2026-09-03T08:00:00.000+08:00",
      "quality": "good",
      "values": {
        "rpm": 300.2,
        "temperature": 67.8,
        "vibration": 2.1,
        "pressure": 0.51,
        "flow_rate": 15.2,
        "power_output": 89.7
      }
    }
  ]
}
```

### 3.4 兼容输入布局

上传前先预览并允许用户确认字段映射，计划兼容：

| 情况 | 处理方式 |
|---|---|
| 单设备宽表 | 每行一个时间点，指标各占一列；导入界面的设备 ID 应用于本批次全部记录 |
| 文件自带设备 ID | 若文件包含 `device_id`，必须与导入界面填写值一致，否则先提示并停止导入 |
| 长表 | 使用 `timestamp,point,value,unit,quality`，解析后补入本次填写的设备 ID |
| 多文件批次 | 一次选择多个同模型、同设备文件，先逐文件校验，再以一个批次执行覆盖或增加 |
| XLSX 多工作表 | 优先识别 `telemetry`；其他工作表由用户勾选，表头兼容时合并 |
| JSON 数组/包络 | 支持本规范包络对象或记录数组；必须能确定模型、设备与时间 |
| 时间差异 | 推荐 ISO 8601；映射界面可明确选择 Unix 秒、毫秒或指定本地格式与时区 |
| 字段别名 | 根据每模型 schema 的 alias 提议映射，用户确认后保存为该批次映射 |
| 单位差异 | 仅对 schema 明确定义的换算执行转换，未知单位拒绝而不是猜测 |
| 列顺序/额外列 | 不依赖列顺序；额外列预览后可忽略或映射，不静默进入算法 |

每次文件传入必须先填写设备 ID，该值作为本批次设备标签写入清单和全部规范化记录。同一型号的另一台具体设备通过下一次传入填写不同设备 ID 实现。空文件、损坏文件、合并单元格表头、密码保护工作簿、宏、外部链接、混合模型 ID 和无法识别时间必须返回具体错误。上传格式严格限定为 CSV、XLSX 和 JSON；压缩包、旧 XLS、数据库文件和其他格式不在本轮范围内。

## 4. 规范化记录

解析后的 JSONL 每行一条：

```json
{"timestamp":"2026-09-03T00:00:00.000Z","sequence":1,"deviceId":"HT-2326-01","sourceType":"upload","quality":"good","values":{"rpm":300.2,"temperature":67.8,"vibration":2.1,"pressure":0.51,"flow_rate":15.2,"power_output":89.7}}
```

每个导入批次的 `manifest.json` 至少记录：

```json
{
  "schemaVersion": "1.0",
  "batchId": "batch_待由服务端生成",
  "sceneId": "sim-visual-hydro-turbine",
  "modelId": 2326,
  "sourceType": "upload",
  "operation": "append",
  "status": "ready",
  "files": [
    {
      "originalFileName": "运行数据.xlsx",
      "storedFileName": "file_01.xlsx",
      "sha256": "待计算"
    }
  ],
  "rowCount": 0,
  "acceptedRows": 0,
  "rejectedRows": 0,
  "startedAt": "待生成",
  "completedAt": "待生成"
}
```

页面当前数据的 `current/manifest.json` 另外记录当前 `dataVersion`、总行数、设备数量、设备 ID、字段、时间范围、批次数、最后变更时间和最近一次操作。页面只读取该套当前数据；批次目录用于展示传入文件、传入时间和按批次删除，不作为多数据集切换入口。

## 5. 每模型 Schema

每个 `schema.json` 必须独立定义，不能让 102 个扩展页永久共用当前六项通用字段：

```json
{
  "schemaVersion": "1.0",
  "sceneId": "sim-visual-hydro-turbine",
  "modelId": 2326,
  "profileId": "hydro-unit-v1",
  "sampleIntervalSeconds": 5,
  "fields": [
    {
      "name": "vibration",
      "label": "主轴振动",
      "unit": "mm/s",
      "type": "number",
      "required": true,
      "validMin": 0,
      "validMax": 30,
      "normalMin": 0,
      "normalMax": 4.5,
      "riskDirection": "high"
    }
  ]
}
```

字段必须具有名称、中文标签、单位、类型、合法范围、正常范围、风险方向、缺失处理规则和协议映射。范围需来源于模型业务设定或以后获得的设备资料；没有依据的范围必须标记为仿真假设。

## 6. 协议来源文件导入格式

页面上传弹窗支持三类数据来源：通用表格、Modbus、IEC 61850。三类文件都可以使用 CSV、XLSX 或 JSON 承载；选择 Modbus 或 IEC 61850 后，系统按来源协议的点位标识解析长表，再把同一时间的全部必需点位聚合为一条模型记录。文件上传完成后先进入导入预检，展示来源、映射、时间范围、质量、拒绝/未映射点位和预计数据影响；用户确认后才写入当前数据。

### 6.1 Modbus 运行数据文件

每行表示一个寄存器点值。字段名称固定如下，允许增加扩展列，但不得删除或改名：

```text
timestamp,device_id,unit_id,function_code,address,raw_value,data_type,byte_order,scale,offset,unit,quality
```

`address` 按模型映射识别（例如水轮机转速为 `40001`）；`raw_value` 支持单值，也支持两个 16 位寄存器组成的 `float32/int32/uint32` 值，`byte_order` 支持 `ABCD`、`BADC`、`CDAB`、`DCBA`；解析后应用 `value = raw_value * scale + offset`，再进入模型字段。`unit_id`、`function_code`、`data_type` 和质量字段会保留在原始批次中。

### 6.2 IEC 61850 运行数据文件

每行表示一个 IEC 61850 数据对象点值。字段名称固定如下，允许增加扩展列，但不得删除或改名：

```text
timestamp,device_id,ied,object_reference,functional_constraint,value,unit,quality
```

`object_reference` 按逻辑设备/逻辑节点/数据属性路径识别，例如 `LD0/MMXU1.RotSpd.mag.f`；`functional_constraint` 推荐使用 `MX`。同一 `timestamp` 的完整对象集合聚合后进入模型字段，质量值和源时间戳随记录保留。

### 6.3 IEC 61850 SCL 辅助文件

上传 IEC 61850 运行数据时可以同时选择 `.icd`、`.cid`、`.scd`、`.ssd` 或 `.xml` 文件。页面与服务端会检查 XML、IED、逻辑设备和数据对象，用于确认设备模型与点位映射。用户确认导入前，SCL 仅保存在导入临时目录；确认成功后，按批次名称永久保存到当前模型的 `protocol/scl/` 目录，并在批次清单中记录原文件名、相对路径、大小和 SHA-256。SCL 不作为历史测量记录直接写入数据集，删除运行记录、删除批次或重置当前数据不会自动删除已归档 SCL。

协议样例由每个模型的“下载当前来源样例”按钮生成，也保存于该模型 `reference/` 目录的 `modbus-sample.*` 和 `iec61850-sample.*` 文件中。

### 6.4 明显异常处理

本轮只处理可确定、无需业务推断的异常：

| 异常 | 处理 |
|---|---|
| 固定字段缺少或改名 | 整个文件预检失败，明确列出缺少字段 |
| 字段首尾空白、中文/英文小数分隔符、质量值大小写 | 自动规范化，并在预检中计数 |
| 时间戳为空或格式无法解析 | 拒绝该行/时间记录 |
| 值为空、非数值、`NaN`、无穷大 | 剔除该点；导致必需点位不全时拒绝该时间记录 |
| 数值明显超出该模型合理范围 | 剔除该点；不自动猜测单位或替换为边界值 |
| 同一时间同一点位重复 | 采用文件中最后一个值，并在预检中计数 |
| 同一时间缺少模型必需点位 | 拒绝该完整时间记录，不进入预测诊断 |
| 未配置点位 | 忽略并列入“未映射点位” |

预检必须显示自动规范化数、无效值数、缺点记录数、重复点位数、拒绝记录数和未映射点位。复杂的单位推断、跨时间插值、自动补点、错列修复和业务规则冲突不在本轮范围内，避免系统擅自改变数据含义。

## 7. Modbus 映射

Modbus 协议本身提供线圈、离散输入和寄存器等数据模型，并不携带本项目的业务字段名。每台设备必须配置映射：

```json
{
  "adapter": "modbus-tcp",
  "host": "由部署环境配置，不提交密码",
  "port": 502,
  "unitId": 1,
  "pollIntervalMs": 1000,
  "points": [
    {
      "field": "vibration",
      "functionCode": 4,
      "address": 100,
      "dataType": "float32",
      "byteOrder": "ABCD",
      "scale": 1,
      "unit": "mm/s"
    }
  ]
}
```

需要明确 TCP/RTU、站号、功能码、零基或一基地址、字节序、数据类型、缩放、单位、采样周期和异常码处理。协议客户端只能运行在服务器或受控采集网关，浏览器不得直接连接 PLC。

## 8. IEC 61850 映射与协议互转

IEC 61850 已确认。每个数据点至少需要：

```json
{
  "adapter": "iec61850",
  "ied": "IED_NAME",
  "logicalDevice": "LD0",
  "logicalNode": "MMXU1",
  "dataObject": "A.phsA",
  "dataAttribute": "cVal.mag.f",
  "functionalConstraint": "MX",
  "field": "phase_a_current",
  "unit": "A"
}
```

计划优先支持 MMS 读取、报告或网关规范化输出。质量属性和源时间戳必须随值保留。协议互转不直接复制报文，而是通过统一点位模型，将 Modbus 寄存器与 IEC 61850 数据对象进行双向字段、类型、单位、质量和时间映射。详细方案见 `05-协议设备接入与互转方案.md`。

## 9. 上传和解析状态

上传与解析使用独立状态，确保页面能显示两条真实进度：

```text
selected
  -> uploading（浏览器已发送总字节 / 本批次文件总字节，并显示当前文件）
  -> uploaded（本批次原始文件已原子落盘并计算 SHA-256）
  -> parsing（已处理行 / 总行，或无法预知总行时显示不确定进度）
  -> validating（字段、单位、时间和质量校验）
  -> merging（按覆盖/增加及冲突策略生成候选当前版本）
  -> analyzing（预测、诊断和概况聚合）
  -> ready / failed
```

建议接口契约：

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/model-showcase/:sceneId/data/imports` | 提交设备 ID、覆盖/增加模式和文件清单，创建可续传导入任务 |
| `PUT` | `/api/model-showcase/:sceneId/data/imports/:batchId/files/:fileId/chunks/:index` | 分块上传；重复块按哈希幂等处理 |
| `POST` | `/api/model-showcase/:sceneId/data/imports/:batchId/complete` | 完成文件接收并启动解析、校验、合并和分析 |
| `GET` | `/api/model-showcase/:sceneId/data/imports/:batchId/status` | 查询已接收分块、上传、解析、校验和分析进度，支持断点续传 |
| `DELETE` | `/api/model-showcase/:sceneId/data/imports/:batchId` | 取消未完成任务并清理其临时文件 |
| `GET` | `/api/model-showcase/:sceneId/data/overview` | 查询当前数据基本情况和可视化摘要 |
| `GET` | `/api/model-showcase/:sceneId/data/batches` | 查询导入时间、操作、设备、行数和状态 |
| `GET` | `/api/model-showcase/:sceneId/data/series` | 按设备、字段、时间范围分页或降采样读取当前数据 |
| `POST` | `/api/model-showcase/:sceneId/data/reset` | 经页面确认后恢复该模型初始样例 |
| `DELETE` | `/api/model-showcase/:sceneId/data` | 经页面确认后按批次、设备、时间范围或全部删除 |
| `GET` | `/api/model-showcase/:sceneId/downloads/samples?deviceId=...&format=...` | 下载 CSV、XLSX、JSON 样例或三格式 ZIP |
| `GET` | `/api/model-showcase/:sceneId/downloads/specification?deviceId=...&format=...` | 下载 PDF、DOCX 或 JSON 数据规范 |
| `GET` | `/api/model-showcase/:sceneId/downloads/prediction?deviceId=...&format=...` | 下载 CSV、XLSX 或 JSON 预测结果 |
| `GET` | `/api/model-showcase/:sceneId/downloads/report?deviceId=...&format=...` | 下载 PDF、DOCX 或 JSON 分析报告 |

`overview` 返回总量、设备数、字段数、时间范围、最后导入时间、质量分布和批次数，并提供按设备的时间覆盖聚合。页面用概况指标、时间覆盖条、质量分布图和批次表展示，不通过读取全部原始行临时计算。

四类下载均要求 `deviceId`，由页面默认带出当前筛选设备，并允许下载前修改。服务端统一输出 RFC 5987 UTF-8 文件名：`<模型ID>-<页面中文模型名>-设备ID-<设备ID>-<中文资料名>.<扩展名>`；设备 ID 中不适用于 Windows 文件名的符号会替换为连字符。ZIP 内三个样例文件沿用相同中文命名，样例内容中的 `device_id` 与文件名设备 ID 一致。

| 下载类型 | 可选格式 |
|---|---|
| 数据规范 | PDF、DOCX、JSON |
| 数据样例 | CSV、XLSX、JSON、ZIP（包含前三种） |
| 预测结果 | CSV、XLSX、JSON |
| 分析报告 | PDF、DOCX、JSON |

## 9. 校验与运行保护

不设置业务层文件大小、行数、批次数、保存期限或单模型容量上限。为避免“大文件不限额”演变为一次性内存加载，实施时必须：

- 上传采用分块、断点续传并按流写入临时文件，不把完整文件缓存在服务端内存；
- 上传分块并流式落盘；P0 的 CSV/JSON/XLSX 在文件落盘后由进程内解析器处理，不设置业务容量上限，但实际可用规模受 Node 内存、XLSX 格式和磁盘容量约束；推广前按目标文件规模做压力测试并按结果引入工作线程或流式解析器；
- 合并、排序和预测使用磁盘分区及有限内存窗口，不要求全部当前数据常驻内存；
- 反向代理、Node 请求超时和临时目录配置支持长时间传输；
- 接收前和处理中持续检查目标磁盘可用空间，并保留部署配置的安全余量；磁盘不足时明确失败且不改变当前数据；
- 页面对超大任务显示已传字节、已解析行数、处理速率和预计剩余时间，无法估计时使用不确定进度；
- 保存无期限，不设置 TTL、自动归档删除或按数量淘汰；
- 只接受审核目录中的 106 个 `sceneId`；
- 服务端生成文件名，原名只写清单，不参与路径拼接；
- MIME、扩展名和文件内容联合校验；
- 上传先写临时文件，校验完成后原子移动；
- 重复 SHA-256 时提示已有批次及导入时间，由用户取消或继续；继续增加时仍按记录主键去重；
- 时间必须可解析，重复时间按明确策略处理；
- 超出合法范围、缺失过多、时间倒序和质量为 `bad` 的数据不能静默进入预测；
- API 错误不返回服务器绝对路径、协议密码、对象 key 或堆栈；
- 清除数据不能删除其他场景、共享模型缓存或资料样例。

## 10. 数据生命周期

每个页面只有一套当前数据，使用 `dataVersion` 进行并发控制。导入、重置和删除均先在临时版本完成校验和分析，再原子替换 `current/`；失败时保留原当前数据。

操作语义：

| 操作 | 规则 |
|---|---|
| 覆盖 `replace` | 用本次有效记录替换输入 `device_id` 的当前数据，页面内其他设备保留；确认弹窗显示目标设备和影响范围 |
| 增加 `append` | 将本次记录加入当前数据；允许同型号不同 `device_id`，按 `device_id + timestamp` 识别冲突 |
| 冲突处理 | 增加时可选“保留已有”“以新值更新冲突记录”或“发现冲突即取消”，选择写入批次清单 |
| 重置 | 恢复该模型随项目提供的初始样例，删除现有当前数据前显示确认/取消弹窗 |
| 删除 | 可按批次、设备、时间范围删除，也可删除全部当前数据；弹窗预估影响后才允许确认 |

页面不设置登录、权限隔离或操作审计。覆盖、重置和删除等危险操作只询问一次：弹窗提供明确的影响摘要、`取消` 和 `确认` 按钮，默认焦点置于取消；用户取消时不产生任何数据变更。批次清单只服务于展示当前已有数据的文件、设备、行数和传入时间，不作为用户行为审计系统。

原始批次、当前数据和分析结果均无自动到期时间。用户删除批次或范围时，相应数据按确认范围实际删除；删除全部时清空运行数据，但保留可下载规范和三种格式样例。代码 Release 回滚不得自动回滚或删除 shared data。每次当前数据变化后重新计算概况、预测和诊断，确保数据图、预测图、诊断与报告始终指向同一个 `dataVersion`。
