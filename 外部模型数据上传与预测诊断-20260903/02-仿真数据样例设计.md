# 外部模型系统生成数据样例设计

> 状态：设计稿，尚未生成 106 份正式样例  
> 原则：系统生成数据与上传、协议数据只有入口来源不同，规范化后的处理、展示、预测和诊断完全一致

## 1. 每个模型的最终样例交付

当前 106 个模型均需建立独立目录，并至少包含：

```text
README.md             模型、页面、数据来源和使用说明
schema.json                字段、单位、范围、质量和协议映射
algorithm.md               预测目标、特征、阈值、公式和限制
samples/normal.csv         正常工况 CSV
samples/normal.xlsx        正常工况 XLSX
samples/normal.json        正常工况 JSON
samples/degrading.csv      渐进退化工况 CSV
samples/degrading.xlsx     渐进退化工况 XLSX
samples/degrading.json     渐进退化工况 JSON
samples/fault.csv          故障工况 CSV
samples/fault.xlsx         故障工况 XLSX
samples/fault.json         故障工况 JSON
```

每种工况使用同一批记录导出为 CSV、XLSX、JSON 三种等价格式，三者解析后的规范化数据哈希必须一致。每份样例建议覆盖不少于 1,000 个时间点，并使用固定随机种子，以便测试可重复。样例应包含正常、波动、缺失、质量异常、渐进退化和故障越界，但不能用纯随机噪声替代设备关系。样例进入页面当前数据后不显示“模拟”“仿真”或特殊结果标识，也不走单独算法分支；来源只保存在内部批次记录中。

## 2. 设备族与建议数据特征

106 个模型先按设备机理归入预测配置族，再为具体模型覆盖字段和阈值：

| 配置族 | 典型对象 | 核心字段 | 主要故障 |
|---|---|---|---|
| `hydro-unit-v1` | 水轮机、发电机组、主轴、转轮 | 转速、功率、流量、压力、振动、温度 | 水力失稳、空蚀、轴系不平衡、温升、出力衰减 |
| `pump-fluid-v1` | 离心泵、潜水泵、泵站 | 压力、流量、功率、转速、振动、温度 | 气蚀、堵塞、叶轮磨损、密封泄漏、轴承故障 |
| `valve-hydraulic-v1` | 阀门、液压站、执行机构 | 开度、压力、流量、响应时间、泄漏、油温 | 卡涩、内泄、响应迟滞、压力异常 |
| `rotating-v1` | 风机、压缩机、电机、轴承 | 转速、振动、温度、电流、功率 | 不平衡、不对中、松动、过热、润滑退化 |
| `lifting-v1` | 起重机、启闭机、吊装设备 | 载荷、速度、位置、电流、制动、振动、温度 | 超载、制动退化、定位偏差、钢丝绳风险 |
| `mobile-mining-v1` | 矿卡、挖掘机、装载机、钻机 | 转速、温度、油压、载荷、速度、振动、油耗 | 发动机过热、液压异常、传动故障、结构疲劳 |
| `mineral-process-v1` | 破碎机、球磨机、筛沙机 | 电流、给料量、振动、轴承温度、粒度、转速 | 堵料、衬板磨损、轴承故障、不平衡、过载 |
| `marine-v1` | 货轮、拖轮、螺旋桨、靠泊系统 | 航速、转速、油耗、轴振、排温、纵横摇、载荷 | 推进效率下降、轴系故障、过热、靠泊风险 |
| `electrical-v1` | 变压器、输电塔、断路器 | 电流、电压、负载、油温、局放、泄漏、动作时间 | 过热、绝缘退化、渗漏、机械特性异常 |
| `water-structure-v1` | 大坝、闸门、水工建筑 | 水位、渗压、位移、应力、振动、开度、流量 | 渗流异常、结构变形、疲劳、启闭卡阻 |
| `hvac-v1` | 冷水机、风机盘管、冷却塔 | 温压、流量、电流、振动、制冷量、能效 | 冷媒异常、压缩机退化、结冰、不平衡 |
| `robot-v1` | 机械臂、伺服系统 | 关节电流、温度、位置误差、振动、扭矩 | 关节磨损、伺服退化、定位精度下降 |
| `structural-visual-v1` | 螺栓、焊缝、船体、轮胎 | 裂纹、位移、应力、磨损、置信度、温度 | 疲劳裂纹、松动、破损、磨损超限 |
| `instrument-v1` | 流量传感器、航标 | 测量值、漂移、供电、信号质量、通信延迟 | 漂移、断线、供电不足、通信异常 |

维修教学和计划页面仍应按其中央设备归入上述设备族；预测只针对设备状态，不把人工工单进度伪装成传感器数据。

## 3. 水轮机样例

```csv
timestamp,device_id,quality,rpm,temperature,vibration,pressure,flow_rate,power_output
2026-09-03T08:00:00+08:00,HT-2326-01,good,299.8,67.2,2.10,0.50,15.0,89.5
2026-09-03T08:00:05+08:00,HT-2326-01,good,300.1,67.3,2.14,0.51,15.1,89.8
2026-09-03T08:00:10+08:00,HT-2326-01,good,300.0,67.5,2.22,0.50,15.0,89.6
2026-09-03T08:00:15+08:00,HT-2326-01,uncertain,299.7,68.0,2.48,0.48,14.6,87.9
```

退化样例应让功率和流量基本稳定，但振动、温度残差和压力脉动逐步增加，用于验证轴系或水力不稳定预测。

## 6. 样例生成规则

每个模型样例按以下阶段生成：

```text
0%～60%：稳定基线 + 低幅周期波动 + 合理测量噪声
60%～85%：一个或两个故障相关字段缓慢漂移，保持物理耦合
85%～100%：越过关注/告警阈值，加入少量 uncertain/bad 质量点
```

生成器必须：

- 使用确定性种子 `sceneId + modelId + sampleVersion`；
- 在技术资料中记录生成参数和生成器版本；
- 保持量纲和采样间隔一致；
- 不用未来数据计算当前特征；
- 不将缺失值全部向前填充，连续缺失超过阈值应停止预测；
- 为每个故障样例附带测试期望文件，仅用于自动验证，不在页面运行和生产推理时读取答案；
- 生成正常、单故障和复合故障三类数据；
- 对同一设备族共享生成机理，但允许每个模型独立覆盖额定值、范围和故障参数。

系统生成样例必须分别生成 CSV、XLSX 和 JSON，并通过与用户上传文件相同的导入 API 写入当前数据。不得在页面组件、图表、预测接口或报告模板中为样例数据复制另一套处理逻辑。

## 7. 逐模型资料验收

正式开发阶段必须由脚本从 `MODEL_SHOWCASE_CATALOG` 读取全部 106 个场景并验证：

- 每个 `sceneId` 恰有一个数据目录；
- 目录中的 `modelId` 与运行目录一致；
- schema、算法说明和九个样例文件均存在；
- CSV 表头、XLSX `telemetry` 工作表和 JSON 字段均与 schema 一致；
- 同一工况的 CSV、XLSX、JSON 解析后内容一致；
- 样例可完成解析、预测和诊断；
- 目录之间没有共享上传文件或活动数据集；
- `eq-18` 不被误纳入外部模型数据目录。
