## 当前结论

1. 当前要复用的不是普通场景页的“模型库”外链占位按钮，而是仿真分析前四页已经落地的“主项目模型 API → 场景库 BFF → Three.js 页面内展示”链路。
2. 已有页面由同一个 `RemoteModelSimulationView` 配置驱动，适合扩展更多模型，但当前模型类型、宿主跳转白名单、菜单、页面路由和专项验证脚本仍包含“四模型”硬编码。
3. 当前主平台集成事实是 iframe 独立版入口加 `embedded=1&viewId=<页面ID>`；仓库仍保留微应用构建能力，但 2026-08-17 的 qiankun 方案不是当前运行事实。
4. 最后一次有文档证据的场景库线上版本为 `20260821-154225`；该信息尚未在本轮连接服务器复核，因此只能作为“最后已知基线”。
5. 下一阶段需要先取得模型清单并核实每个模型是否同时具备元数据、可下载三维文件和 Dashboard/工况接口，再决定是完整复用既有数字孪生页面，还是采用仅模型展示的降级模板。
6. 主项目原始 API 文档已经补读：它覆盖 `model_category=39` 列表查询、模型基本信息、文件列表/下载、AI 元数据、Dashboard、场景模板和数据一致性共七类接口；扩展时应以原始契约为输入，同时以当前 HTTPS 现场实测修正文档中的旧 HTTP 地址。
7. 2026-08-26 已从 HTTPS API 取得完整列表：共 1,140 个唯一模型 ID，列表中全部标记至少一个文件；完整清单见 CSV。主项目通用 API 不需要为普通新增页面改造，但大文件、主平台菜单和模型详情宿主白名单仍需分别处理。
8. 配对范围已由 74 页继续扩展为 99 页：A 级首选 23 页、B 级扩展 57 页、C 级改造 19 页；页面与模型 ID 均不重复，文件约 0.04～42.53 MiB，AI 元数据与 Dashboard 已实测可用。连同仿真分析既有四页，预计模型库展示页约 103 页；工业智能运维仍有 6 页因没有合理模型而暂缓。
9. 现有“1号机组异常预测分析”（`eq-18`）已从接入清单中移除，必须保持原位置和原数据展示逻辑；模型 `6691` 改由新增独立页面 `eq-unit1-model` 承接。
10. 各栏目内部将模型接入页前置，未接入页后移且保持原相对顺序；`eq-18` 固定为工业智能运维第 19 位，仿真分析前四页固定为第 1～4 位。
11. 推荐保留现有 `viewId` 和业务看板，在页面内增加配置驱动的 3D 模型模式；默认关闭新模型的主平台资源详情跳转。若宿主需同步新增页面和排序，只需更新菜单 manifest，不需要主项目修改模型 API。

## 维护规则

- 新需求、模型清单、设计决策、代码变更、测试结果和部署证据均写入本目录。
- `修改日志.md` 按时间倒序追加，不覆盖历史，不把“本地完成”写成“云端已上线”。
- 旧目录只作为历史资料来源；本次工作不在旧目录继续追加混杂记录。
- 每个模型都必须通过固定模型 ID 与固定详情路径接入，不允许浏览器提交任意模型文件地址或对象存储 key。
- 未取得上游实测证据前，不把文档中的旧文件大小、字段或在线状态当成新模型事实。
