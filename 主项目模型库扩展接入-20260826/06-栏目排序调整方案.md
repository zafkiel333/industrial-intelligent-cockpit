# 模型库接入页面栏目排序调整方案

> 方案日期：2026-08-27  
> 当前状态：已按本方案实施并发布；正式菜单版本 `20260827-142935`
> 关联配对：[`04-页面与模型配对方案.md`](./04-页面与模型配对方案.md)

## 1. 排序目标与硬约束

1. 顶级栏目顺序保持不变，只调整各栏目内部的子页面顺序。
2. 已接入或本轮计划接入主项目模型库的页面形成栏目“模型展示前置区”；未接入页面整体后移，并保持它们原有相对顺序。
3. “1号机组异常预测分析”（`eq-18`）锁定在工业智能运维第 19 位，页面代码、数据、标题和入口均不修改。
4. 新增“1号水轮发电机组模型展示”（`eq-unit1-model`）放在 `eq-18` 之后，即工业智能运维第 20 位。它是受保护约束产生的唯一不前置模型页。
5. 仿真分析现有前四页锁定在第 1～4 位，顺序和页面不变；其他模型接入页从第 5 位起前置。
6. 同一个页面只保留一个菜单入口；排序不能改动 `viewId`，不能以复制入口的方式实现前置。

## 5. 开发落点与验证

1. 在 `constants.tsx` 中只重排数组项，并新增 `eq-unit1-model`；不能改动其他页面 ID。
2. 为 `eq-unit1-model` 新增独立路由和页面组件，不引用 `eq-18` 的本地 Excel、预测状态或页面组件。
3. 更新 `App.tsx` 的显式页面解析、场景库菜单 manifest 生成结果和主平台交付清单。
4. 扩展导航专项验证，断言 `eq-18` 为工业智能运维第 19 位、`eq-unit1-model` 为第 20 位、仿真四页为第 1～4 位。
5. 对每个有模型页的栏目断言“所有前置 viewId 连续出现且早于未接入页”；未接入页之间的相对顺序必须与当前版本一致。
6. 菜单顺序调整会改变生成的 manifest 内容哈希；只有重新生成、验收并交付主平台后，宿主侧列表才能同步新顺序和新增页面。该动作不涉及主项目模型 API 修改。

## 6. 验收判定

- `eq-18` 仍可按原入口打开，界面、数据上传、预测计算和展示结果不变；
- `eq-unit1-model` 可独立打开并显示模型 `6691`，页面明确标识其 Dashboard 为模拟数据；
- 仿真分析前四页位置、标题、viewId 和功能全部不变；
- 其他有模型页在各自栏目前置，未接入页无丢失、无重复、相对顺序不乱；
- standalone 与 `embedded=1&viewId=...` 两种入口的菜单定位一致；
- 新 manifest 与本方案中的顺序完全一致。
