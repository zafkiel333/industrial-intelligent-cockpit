## 4. 是否可以不改主项目直接开发

答案分为两层。

### 4.1 模型 API 与场景库页面开发：可以

对于已经存在于 `model_category=39`、具有受支持模型文件且满足我方资源限制的模型，主项目后端已经提供通用接口：

- 模型基本信息；
- 文件列表与下载；
- AI 元数据；
- Dashboard；
- 三类场景；
- 数据一致性。

这些接口都按模型 ID 参数化。场景库可以单方面完成 BFF 白名单、模型目录、页面配置、Three.js 展示、遥测、趋势、诊断和报告开发，不需要主项目为每个新模型新增 API。

### 4.2 完整主平台集成：部分仍需要主项目配合

| 目标 | 是否需要主项目配合 | 原因 |
|---|---|---|
| 场景库独立入口展示新模型 | 不需要 | 场景库自身代码、菜单和部署即可完成 |
| 在已有场景库页面内增加“模型总览/选择器” | 不需要 | 可复用主平台已有的场景库入口，在场景库内部选择模型 |
| 通过直接 `viewId` 打开新页面 | API/页面开发不需要 | URL 可由场景库识别；但主平台没有菜单入口时用户不易到达 |
| 把每个新页面加入主平台统一导航 | 通常需要 | 主平台需要导入/更新场景库菜单清单或菜单配置 |
| 新模型的“查看资源详情”使用主平台内标签 | 按最后已知实现需要 | 主平台消息处理器原先只允许四个模型 ID，需要扩展宿主白名单 |
| 只展示模型而不提供主平台详情跳转 | 不需要 | 场景库可隐藏/禁用该入口，或仅在独立模式提供固定详情地址 |
| 主项目 API 增加新接口 | 通常不需要 | 现有通用接口已按模型 ID 工作 |

因此，“无需主项目端配合”可以实现完整的场景库侧页面开发与独立展示；若验收目标还包括主平台逐页菜单和内标签模型详情跳转，则仍需主平台做很小但不可省略的配置/白名单更新。

## 5. 推荐的零主项目改动方案

如果明确要求主项目完全不改，建议采用：

1. 保留主平台现有“场景库/仿真分析”入口；
2. 在场景库现有可达页面内新增“外部模型资源总览”；
3. 总览按行业、名称和 ID 搜索 1,140 个候选模型；
4. 用户选定模型后在同一个场景库页面内打开配置驱动的模型展示；
5. 对符合条件的模型展示 Three.js、参数、趋势、场景和诊断；
6. 对超大或不支持文件显示明确兼容状态，不发起危险下载；
7. 新模型默认不发送主平台模型详情导航消息，避免宿主四模型白名单拒绝；
8. 用户最终确定常用模型后，再把它们固化为独立菜单页面。

这种方式可以在主平台不修改菜单和消息白名单的情况下完成实际展示，同时避免一次性为 1,140 个模型创建 1,140 个静态页面。

## 6. 不能直接认定全部可接入的原因

列表中的 `file_num=1` 只表示存在文件记录，不代表：

- 文件一定是 FBX/GLB/GLTF；
- 文件大小一定不超过 50 MiB；
- 对象存储下载一定成功；
- 文件头、网格、材质和贴图能被当前 Three.js 链路解析；
- AI 生成的通用字段与具体设备业务相符；
- 模型坐标、朝向、缩放和部件动画无需调整。

因此下一步应以用户选定的模型清单为范围逐个检查，而不是对 1,140 个模型同时下载或直接生成页面。
