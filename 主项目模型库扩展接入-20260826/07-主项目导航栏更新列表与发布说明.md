1. 保留主项目现有一级入口“场景库”。
2. 以 `viewId` 作为节点唯一键，将该入口下面的整个场景库菜单子树原子替换为清单的 `items`；不要按标题或数组下标合并。
3. 严格按每个节点的 `order` 升序显示；同层级不得再次按名称、创建时间或主项目旧序号排序。
4. 不得因为主项目没有同名 Vue/React 组件而过滤叶子节点。叶子页由场景库通过 iframe 自己解析。
5. 叶子页 URL 统一为：

   ```text
   https://47.122.104.52/cockpit/?embedded=1&viewId=<URL编码后的viewId>
   ```

6. 菜单缓存键、接口 ETag 或本地存储版本必须切到 `20260827-142935`；更新后使旧菜单缓存失效。
7. 发布前校验根节点 20、总节点 1,050、唯一 `viewId` 1,050，并核对内容哈希。任一数量或哈希不一致都不得切换主项目菜单。

## 5. 模型详情跳转白名单

模型在场景库页面内加载不需要主项目修改模型 API；99 个模型的基本信息、Dashboard、工况和文件接口均继续复用现有 HTTPS API。

但嵌入主项目后，“查看模型详情”使用 `scene-library:navigate` 消息。场景库 Release `20260827-155745` 继承了经审核目录中的 103 模型本地白名单。若主项目宿主仍只允许 `2326/2328/2316/2310`，新增页面的模型展示仍正常，但详情跳转会被宿主拒绝。

场景库运行版 `20260827-155745` 中，模型绑定入口只显示本轮新开发的三维模型页面，不再出现“模型展示 / 原业务页”切换栏；本轮加载优化也不改变菜单节点、`viewId`、顺序或 manifest 内容，主项目无需因此重新生成菜单，只需继续使用本文件所列正式 manifest。

主项目需要在保持以下安全约束的前提下，把宿主允许 ID 更新为“既有四模型 + `04-页面与模型配对方案.md` 中 99 个唯一模型 ID”：

- 只接受 `type=scene-library:navigate`、`protocolVersion=1.0`；
- `event.origin`、`event.source` 和 `requestId` 继续校验；
- `target.path` 只能为 `/three-model/detail`；
- `query.id` 必须属于这 103 个模型；
- 不接受场景库传入任意完整 URL、文件 URL 或对象存储 key。

这是主项目宿主导航安全配置更新，不是模型 API 改造。若本轮只更新栏目菜单，也应明确记录“新增模型详情跳转暂未开放”，不能误报为完整联调完成。
