## 2. 主项目更新方法

1. 保留主项目现有一级入口“场景库”。
2. 校验正式 manifest 的版本、节点数、内容哈希和文件哈希后，原子替换主平台本地旧快照；不要跨公网在浏览器启动时临时请求 manifest。
3. 对 20 个 manifest 根节点执行“目录 + 首页 + 原 children”转换：目录只展开；首页排第一并沿用根节点原 `viewId`；原 children 完整保留。
4. 菜单唯一键分别使用 `scene-library-group-<viewId>`、`scene-library-home-<viewId>`、`scene-library-view-<viewId>` 或主平台等价规则；不得用中文“首页”作为唯一键。
5. 严格按每个节点的 `order` 升序显示；同层级不得再次按名称、创建时间或主项目旧序号排序。
6. 不得因为主项目没有同名 Vue/React 组件而过滤叶子节点。所有场景子菜单都进入主平台同一个 `/scene-library` 宿主页，只改变 query。
7. 主平台路由统一为：

   ```text
   /scene-library?viewId=<URL编码后的viewId>
   ```

8. iframe 生产地址优先使用主平台现有同源代理：

   ```text
   /cockpit/?embedded=1&viewId=<URL编码后的viewId>
   ```

   不使用同源代理时，才使用场景库 HTTPS 直连：

   ```text
   https://47.122.104.52/cockpit/?embedded=1&viewId=<URL编码后的viewId>
   ```

9. iframe URL 必须使用 `new URL(entry, window.location.href)` 和 `searchParams` 生成，并让 `route.query.viewId` 变化触发 `src`/`key` 更新；不得手工拼接 query。
10. 消息来源必须从最终 `frameSrc` 动态计算。使用同源 `/cockpit/` 时实际 Origin 是主平台自身；使用场景库直连时才是 `https://47.122.104.52`。
11. 菜单缓存键、接口 ETag 或本地存储版本必须切到 `20260827-142935`；更新后使旧菜单缓存失效。
12. 发布前同时校验：manifest 根节点 20、总节点 1,050、唯一 `viewId` 1,050；转换后场景库子树 1,070 条、连同主平台总入口 1,071 条。
13. 保留上一份主项目菜单、模型白名单和前端产物作为同一回滚组；切换失败时整体恢复，不进行部分节点回退。

## 5. 模型详情跳转白名单

模型在场景库页面内加载不需要主项目修改模型 API；99 个模型的基本信息、Dashboard、工况和文件接口均继续复用现有 HTTPS API。

主项目需要在保持以下安全约束的前提下，把宿主允许 ID 更新为“既有四模型 + `04-页面与模型配对方案.md` 中 99 个唯一模型 ID”：

- 只接受 `type=scene-library:navigate`、`protocolVersion=1.0`；

- 不接受场景库传入任意完整 URL、文件 URL 或对象存储 key。

这是主项目宿主导航安全配置更新，不是模型 API 改造。若本轮只更新栏目菜单，也应明确记录“新增模型详情跳转暂未开放”，不能误报为完整联调完成。

```text
src/views/sceneLibrary/scene-library-menu.manifest.json
src/views/sceneLibrary/config.ts
src/router/menus/modules/sceneLibrary.ts
src/views/sceneLibrary/index.vue
相关 VITE_GLOB_SCENE_LIBRARY_ENTRY / CSP / Nginx 配置
```

具体要求：

1. 用本文件第 1 节正式 manifest 完整替换旧文件；
2. `config.ts` 继续从 manifest 生成 `isKnownViewId`，不要手写另一套 1,050 ID 白名单；
3. 菜单模块继续生成 20 个首页；当前 manifest 最大深度为 2，现有 `toLeaf` 可覆盖当前数据，但建议改为递归转换以兼容未来更深层级；
4. `index.vue` 保留现有 query、URL API、iframe key、动态 Origin、窗口来源和协议校验；
5. 将 `ALLOWED_MODELS` 从 4 个扩展为 103 个审核映射，仍只允许 `/three-model/detail`；
6. 使用主平台正式生产构建和可回滚静态产物发布，菜单数据/清单与代码在同一变更窗口切换。

## 9. 发布顺序与回滚

场景库兼容版本已经先行上线，主平台按以下顺序执行：

```text
备份主平台旧前端产物、旧 manifest、菜单/权限数据和白名单
→ 导入正式 manifest 并生成 20 个首页
→ 更新 103 模型白名单

→ 测试环境核对数量、query、iframe、Origin 和模型详情

→ 按第 6 节联合验收
```

失败时必须一起恢复主平台前端产物、旧 manifest、菜单/权限数据和旧白名单。无需回滚场景库 `20260827-155745`，除非场景库独立入口自身也出现故障。
