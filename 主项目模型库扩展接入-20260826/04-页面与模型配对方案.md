# 页面与模型配对方案

> 首版时间：2026-08-26 17:10（Asia/Shanghai）  
> 扩展时间：2026-08-27（Asia/Shanghai）  
> 当前状态：供确认，尚未进入业务代码开发  
> 配对原则：一页一模型、模型 ID 不重复；允许同设备族、关键子系统或同工况适配，但必须写明页面修改；当前文件不超过 50 MiB
> 保护约束：现有“1号机组异常预测分析”（`eq-18`）不做任何模型接入改造；另建独立模型展示页承接 1 号机组模型

## 1. 本轮盘点范围与结论

- 页面基线：场景库菜单清单共 1,049 个节点，其中“工业智能运维”包含 19 个页面。
- 模型基线：主项目 `model_category=39` 共 1,140 个模型。
- 扩展后建议接入 **99 个页面、99 个唯一模型**：
  - A 级首选：23 页，其中 1 页是新增的独立“1号水轮发电机组模型展示”页；
  - B 级扩展：57 页，属于同设备、同部件或同工况，主要做标题、热点和指标映射调整；
  - C 级改造：19 页，以关键子系统代表整套设备，需要调整中央对象、部分指标与文案，但仍处于同一设备链路；
  - 工业智能运维还有 6 个页面因缺少合理模型而继续暂缓。
- 99 个入选模型均为 FBX，文件约 0.04～42.53 MiB，未超过场景库 BFF 当前 50 MiB 限制。
- 99 个模型的基本信息、AI 元数据和 Dashboard 均已通过 HTTPS API 只读核对；Dashboard 返回 4～6 个可绑定字段。
- 三轮累计人工查看 88 张主项目 `model_picture` 缩略图，比较外观、完整度和页面语义。这里属于**静态视觉预选**；FBX 实际材质、朝向、缩放和交互流畅度必须在开发 Phase 0 中逐个加载复核。
- 仿真分析前四个既有样例不计入上述 99 个新增/改造配对；连同既有四页，预计共有约 **103 个模型库展示页**。

## 5. 实施边界

1. 本表不复用既有四个样例模型 `2326`、`2328`、`2316`、`2310`，目的是实际扩展模型覆盖，而不是换页面重复展示同一资源。
2. 推荐保留现有页面 `viewId` 和业务入口，在页面内增加“3D 模型模式/模型展示区”，复用前四页的加载、场景切换、遥测、趋势、诊断、报告与一致性逻辑；不建议把现有业务页整体替换为同一套模板。
3. 页面指标只有在原有业务语义与模型对象一致时复用。主项目 Dashboard 当前是模拟数据，页面必须继续显示“模拟数据”标识。
4. 本轮采用固定 `page viewId -> model_id` 配置，不允许前端传入任意文件 URL 或对象存储 key。
5. 除 `eq-unit1-model` 外均复用现有 `viewId`；新增的一号机组模型页只读取主项目模拟模型数据，不得改动 `eq-18` 的组件、数据文件、路由位置或展示逻辑。
6. 页面排序按 [`06-栏目排序调整方案.md`](./06-栏目排序调整方案.md) 实施：只调整栏目内子页面顺序，顶级栏目顺序不变；`eq-18` 和仿真分析前四页是受保护位置。
7. 默认不发送新模型 ID 的主平台内标签详情消息；若要求主平台同步新增页面和栏目排序，需要重新生成并交付菜单 manifest，但不需要修改主项目模型 API。
8. 若后续要求“查看资源详情”仍由主平台打开内标签，主平台需要按实际开发批次增加对应模型 ID；这不属于模型 API 改造。

扩展后如启用主平台资源详情内标签，宿主允许列表应按最终批次逐步增加，不建议一次放开全部 99 个 ID。
