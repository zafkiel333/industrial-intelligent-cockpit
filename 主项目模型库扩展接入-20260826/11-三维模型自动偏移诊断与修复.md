# 三维模型自动偏移诊断与修复

> 处理日期：2026-08-28（Asia/Shanghai）
> 用户现象：部分模型初始位于视窗中心，随后以较快速度持续偏移
> 影响范围：共用 `RemoteModelViewer` 的 103 个模型展示页；仅偏心建模原点且具备转速字段的模型容易明显触发

## 1. 结论

模型文件没有在运行中自行改变坐标，问题也不是 OrbitControls 的相机 target 随机漂移。根因位于场景库共用查看器的模型归一化与旋转顺序：

1. 旧代码根据包围盒中心修改来源模型根节点的 `position`，使第一帧看起来居中；
2. 遥测动画随后直接修改同一个来源根节点的 `rotation.y`；
3. 部分 FBX 的建模原点距离实际几何中心很远，根节点旋转会让几何体绕远处原点公转；
4. 页面具有 `rpm` 字段时每帧都会累加角度，因此模型会从中心快速甩向一侧；
5. 旧旋转增量按“每帧”计算，120 Hz 屏幕的速度约为 60 Hz 屏幕的两倍，进一步放大现象。

截图中的工业污水处理模型属于典型触发方式：第一帧已被包围盒位移到中心，但设备几何中心并不是来源根节点的旋转枢轴。

## 2. 修复方式

新增 `src/remoteModelShowcase/modelViewerTransform.ts`，统一执行：

1. 验证来源模型具有有效 Mesh 和非空包围盒；
2. 按最大边缩放到视窗标准尺寸；
3. 将来源对象的几何中心移动到局部原点；
4. 把来源对象放入新的 `remote-model-centered-pivot` Group；
5. 后续振动和转速动画只作用在中心枢轴上，不再旋转来源 FBX 根节点；
6. 使用真实 `deltaSeconds` 推进视觉旋转，并限制后台恢复时的最大单帧增量；
7. 每圈对角度取模，避免长时间运行形成过大的浮点角度。

这项修改作用于通用查看器，不需要逐页写 103 份模型偏移补丁，也不改变模型 API、Dashboard、菜单顺序、模型配对或主平台集成协议。

## 3. 自动化回归

新增命令：

```text
npm run verify:model-stability
```

回归脚本构造一个建模原点与实际网格相距很远的偏心模型，并验证：

```text
MODEL_VIEWER_STABILITY_VERIFY_OK centerDrift<1e-6 rotation30=0.360000 rotation120=0.360000
```

- 枢轴旋转至 0°、约 25.7°、90°、180° 和 315° 时，包围盒中心偏移均小于 `1e-6`；
- 同一模型在 30 Hz 与 120 Hz 下运行一秒后的角度完全一致；
- 模型加载、103 页模型库、20 根/1,050 节点导航、HTTPS 集成以及 standalone/microapp 双构建继续通过。

## 4. 验收建议

上线后优先抽查具有转速字段且外形较大的模型：

1. 首次加载后静置至少 30 秒，模型中心不得形成持续单向位移；
2. 暂停/恢复相机自动旋转，模型几何中心应继续稳定；
3. 拖动相机后点击重置，OrbitControls target 应回到模型中心；
4. 60 Hz 和高刷新率显示器上的模型旋转速度应基本一致；
5. 小幅振动仍可保留，但振幅上限只有 `0.018` 个场景单位，不应表现为整体漂移。
