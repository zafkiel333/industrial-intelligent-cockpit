# 主平台端开发调整指导

> 目标读者：主平台 Vue 3 / Jeecg / Vue Router 开发与运维人员。  
> 当前前提：主平台 `src/views/sceneLibrary/index.vue` 使用 iframe 加载场景库独立版。

## 1. 最终菜单结构

主平台只新增或保留一个本项目一级菜单：

```text
场景库
```

场景库原根菜单作为它的二级菜单，原子项继续向下：

```text
场景库（一级）
├─ 工业智能运维（二级，viewId=smart-ops）
│  ├─ 首页（主平台合成的三级菜单，viewId=smart-ops）
│  ├─ 水轮机智能运维（三级，viewId=eq-0）
│  └─ ……
├─ 工业产品知识库（二级，viewId=product-kb）
├─ 运行驾驶舱（二级，viewId=cockpit）
├─ 仿真分析（二级，viewId=simulation）
└─ ……
```

不得把“工业智能运维”等提升为主平台一级菜单，也不得把所有叶子页面压平成“场景库”的直接子项。

> 2026-08-20 联调补充：主平台菜单组件把存在 children 的节点当作纯展开目录，无法直接进入父节点自身首页。现已确定由主平台给全部 20 个二级分类统一增加“首页”子菜单，二级分类只负责展开，“首页”沿用分类原 `viewId`。完整转换代码、唯一键、权限、发布和验收要求见 `07-主平台分类首页子菜单整改说明.md`；如本文件旧示例与该补充说明不一致，以 07 文件为准。

## 2. 菜单数据接入

场景库团队将提供：

```text
scene-library-menu.manifest.json
```

主平台可根据自身机制选择：

1. 转换成 Jeecg 后台菜单导入数据；
2. 构建时转换成 Vue 静态菜单/路由配置；
3. 由主平台后端读取并落库。

不建议浏览器每次启动都跨公网实时请求场景库 manifest 后再拼主菜单，因为这会让主平台菜单可用性依赖场景库源站，并增加权限、缓存和启动时序问题。

推荐做法是“发布前导入/同步”：

```text
场景库 manifest
    ↓ 校验 schemaVersion/menuVersion
主平台导入脚本或后台管理
    ↓
主平台自己的菜单数据库/配置
```

这样菜单运行时仍由主平台完全管理。

---

## 3. 主平台菜单项需要保存什么

除主平台已有字段外，每个场景菜单至少要能找到：

| 字段 | 说明 |
|---|---|
| `title` | 菜单显示名称 |
| `viewId` | 场景库稳定页面标识 |
| `parent` | 父菜单 |
| `order` | 同级排序 |
| `permission` | 主平台权限标识或规则 |
| `enabled` | 是否启用 |

可以把 `viewId` 放入菜单 URL query：

```text
/scene-library?viewId=eq-0
```

不要把 React 文件路径或组件名保存到主平台菜单中。

## 4. 路由处理

现有场景库宿主页继续复用：

```text
src/views/sceneLibrary/index.vue
```

所有场景子菜单都进入 `/scene-library`，只改变 query：

```text
/scene-library?viewId=smart-ops
/scene-library?viewId=eq-0
/scene-library?viewId=sim-visual-hydro-turbine
```

主平台应使用 Vue Router 对象导航，例如：

```ts
router.push({
  path: '/scene-library',
  query: { viewId },
});
```

不要使用字符串拼接，不使用 `window.open`。

生产环境若由 Jeecg 后台动态菜单生成路由，应确保刷新上述 URL 后仍能命中场景库宿主页，而不是 404 或被重定向到错误菜单。

## 5. iframe 地址生成

原逻辑大意为：

```ts
const frameSrc = computed(
  () => glob.sceneLibraryEntry || 'https://47.122.104.52/cockpit/',
);
```

建议改为使用标准 URL API：

```ts
const route = useRoute();

const requestedViewId = computed(() => {
  const raw = Array.isArray(route.query.viewId)
    ? route.query.viewId[0]
    : route.query.viewId;
  return typeof raw === 'string' ? raw.trim() : '';
});

const frameSrc = computed(() => {
  const entry = glob.sceneLibraryEntry || 'https://47.122.104.52/cockpit/';
  const url = new URL(entry, window.location.href);
  url.searchParams.set('embedded', '1');
  if (requestedViewId.value) {
    url.searchParams.set('viewId', requestedViewId.value);
  }
  return url.toString();
});
```

正式代码还应增加主平台自己的 `viewId` 白名单或菜单来源校验。只有当前用户可见且属于场景库菜单树的 ID 才能传入 iframe。

## 6. iframe 重载行为

第一版中 `frameSrc` 随 `viewId` 改变，所以切换菜单会重新加载 iframe。

优点：

- 逻辑简单；
- 页面状态和 URL 一致；
- 刷新可恢复；
- 不存在“消息先到、iframe 尚未加载”的时序问题；
- 页面卸载能释放 WebGL、轮询和事件。

代价：

- 3D 页面或大型页面重新初始化；
- 页面未保存的临时状态会丢失。

第一版请先按此方案联调。只有性能验收不通过时，双方再定义主平台到 iframe 的切页消息，不要提前扩大实现。

## 7. 内标签策略

主平台需要在开发前选择一种行为。

### 推荐第一版：复用一个场景库标签

```text
顶部内标签：场景库
左侧菜单：显示当前具体页面
iframe：随 viewId 切换
```

优点是标签数量可控，最符合“场景库是唯一一级入口”。

如果主平台现有标签系统按 `fullPath` 区分 query，可能自动把不同 `viewId` 当成不同标签。主平台需在宿主页/菜单配置中确认并适配，而不是让场景库操作标签数组。

### 可选：每个场景页面独立标签

如果业务明确要求同时打开多个场景，可以让不同 `viewId` 形成不同 fullPath，并将标签标题设为 manifest 中的 `title`。

该选择属于主平台 UI 策略，URL 协议不变。

内标签总开关仍按主平台现有机制处理：

- 开启：由主平台标签组件展示；
- 关闭：同一浏览器页中普通路由切换；
- 场景库不读取该开关。

## 8. 权限设计

主平台必须确认权限粒度：

### 方案 A：只控制总入口

用户有“场景库”权限，就能看到全部子菜单。

适合第一阶段快速迁移，但权限较粗。

### 方案 B：控制到二级分类

例如分别控制“仿真分析”“运行驾驶舱”。

工作量与效果较平衡，推荐多数场景采用。

### 方案 C：控制到每个叶子页面

最细，但菜单和权限数据量很大，需要批量导入工具，不能人工逐条维护。

无论采用哪种，直接输入一个未授权 `viewId` 时，主平台都应在进入宿主页前拒绝或回退到用户有权访问的默认页。隐藏菜单不能替代路由权限校验。

## 9. 与现有模型详情导航兼容

主平台已有或正在接入：

```text
scene-library:navigate
```

该监听必须保留。它负责把场景库中的“查看资源详情”导航到：

```text
/three-model/detail?id=<模型ID>
```

本次 URL `viewId` 只负责主平台菜单定位场景库内部页面，不替换上述协议。

主平台宿主页同时承担：

```text
主平台 → iframe：通过 src query 指定场景页面
iframe → 主平台：通过 postMessage 请求模型详情导航
```

## 10. 错误处理

主平台应处理：

- 菜单缺少 `viewId`：不进入空白 iframe，记录配置错误；
- `viewId` 不在当前 manifest/权限集合：拒绝或回退；
- iframe 超时：保留现有加载失败和重试界面；
- 场景库源站不可达：显示现有错误态；
- query 为数组、空白或超长：规范化后拒绝；
- manifest 版本不兼容：阻止导入并报告差异；
- 用户登录失效：按主平台现有守卫处理。

不要把场景库服务错误误报成“用户无权限”，也不要把权限拒绝误报成“iframe 加载失败”。

---

## 11. 主平台部署内容

主平台侧可能包含两类发布：

1. Vue 代码发布：宿主页、路由或标签标题适配；
2. 菜单/权限数据发布：Jeecg 后台菜单导入或配置变更。

必须记录两者版本和执行顺序。只发布前端代码但不导入菜单，用户看不到入口；只导入菜单但不发布宿主页参数逻辑，iframe 仍显示旧导航或总是进入默认页。

主平台按自身既有流程构建、备份、发布和回滚，场景库团队不操作主平台服务器。
