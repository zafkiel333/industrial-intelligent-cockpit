# 主平台分类首页子菜单整改说明

> 文档日期：2026-08-20
> 适用范围：主平台“场景库”菜单及其 iframe 宿主页
> 场景库线上版本：`20260820-173922`
> 整改状态：方案已确定，等待主平台开发、发布和联合验收
> 优先级：高；当前主平台中带子菜单的分类首页无法进入

## 1. 本次确定采用的方案

主平台在“场景库”的每一个二级分类下面，统一增加一个名为“首页”的页面导航。

二级分类本身只负责展开和收起，不再直接承担页面跳转。“首页”子菜单负责把该分类原有的 `viewId` 传给场景库，因此主平台会比原设计多执行一次菜单层级导航。

```text
场景库（主平台一级菜单）
└─ 工业智能运维（二级分类，只负责展开）
   ├─ 首页（新增三级菜单，viewId=smart-ops）
   ├─ 水轮机智能运维（原三级菜单，viewId=eq-0）
   ├─ 发电机智能运维（原三级菜单，viewId=eq-1）
   └─ ……
```

该规则应用于全部 20 个二级分类，不区分它原来是否存在子页面：

- 原来有子页面：新增“首页”作为第一个子菜单，后面继续保留原子页面；
- 原来没有子页面：也新增一个“首页”，分类展开后只显示这一个子菜单；
- 所有分类的菜单交互保持一致，避免一部分分类可点击、另一部分分类只能展开。

## 2. 为什么需要整改

场景库原导航允许一个菜单节点同时具备两种能力：

1. 它自己对应一个分类首页；
2. 它还包含若干下级页面。

例如：

```text
工业智能运维
├─ 自己的首页：viewId=smart-ops
├─ 水轮机智能运维：viewId=eq-0
└─ ……
```

主平台当前菜单组件把存在 `children` 的节点识别为纯目录或 `SubMenu`：

- 点击父级标题只执行展开/收起；
- 不执行父级保存的页面路由；
- 因此 `smart-ops`、`simulation` 等分类首页无法被选中；
- 没有 `children` 的节点会被当作普通菜单，所以反而能够进入自身页面。

现网已经验证：

- `embedded=1` 能正确隐藏场景库自身导航；
- `viewId=eq-0` 等页面标识能够正确定位；
- 主平台向 iframe 传递页面标识的基本路由链路正常；
- 故障只发生在“带子项的父菜单无法同时导航”这一菜单交互模型上。

所以，本次不修改场景库页面路由，也不回滚场景库版本，而是在主平台菜单转换阶段增加显式“首页”子菜单。

## 3. 整改后的完整层级规则

### 3.1 固定层级

```text
第一级：场景库
第二级：场景库原有的 20 个根分类
第三级第一个：新增“首页”
第三级其余项：该分类原有 children
```

如果原 children 下面仍有更深层级，应继续递归保留，不得压平。

### 3.2 首页菜单显示名称

左侧菜单统一显示：

```text
首页
```

为了避免主平台内标签中出现多个无法区分的“首页”，建议内标签标题使用：

```text
<分类名称>首页
```

例如：

- 菜单文字：`首页`；
- 内标签标题：`工业智能运维首页`；
- 页面 `viewId`：`smart-ops`。

### 3.3 排序

新增“首页”必须位于该分类全部子菜单之前：

```text
首页 → 原第一个子页面 → 原第二个子页面 → ……
```

若主平台使用数字排序值，建议：首页使用 `0`，原 children 按 manifest 的 `order` 保持不变。

## 5. 主平台需要具体修改什么

### 5.1 修改菜单导入或转换逻辑

正式文件 `scene-library-menu.manifest.json` 中，每个 `items` 根节点仍同时包含：

- 分类自身的 `viewId`；
- 分类标题 `title`；
- 原有 `children`。

主平台导入时需要把根节点转换成“目录 + 首页叶子 + 原 children”，不要求场景库修改 manifest 格式。

转换前：

```json
{
  "viewId": "smart-ops",
  "title": "工业智能运维",
  "order": 10,
  "enabled": true,
  "children": [
    {
      "viewId": "eq-0",
      "title": "水轮机智能运维",
      "order": 10,
      "enabled": true,
      "children": []
    }
  ]
}
```

转换后，主平台内部菜单结构表达的含义应为：

```json
{
  "menuKey": "scene-library-group-smart-ops",
  "title": "工业智能运维",
  "type": "directory",
  "children": [
    {
      "menuKey": "scene-library-home-smart-ops",
      "title": "首页",
      "tabTitle": "工业智能运维首页",
      "viewId": "smart-ops",
      "route": "/scene-library?viewId=smart-ops",
      "order": 0
    },
    {
      "menuKey": "scene-library-view-eq-0",
      "title": "水轮机智能运维",
      "viewId": "eq-0",
      "route": "/scene-library?viewId=eq-0",
      "order": 10
    }
  ]
}
```

这里的 `menuKey`、`type`、`tabTitle` 是说明含义的示例字段。主平台应替换成自身 Jeecg/Vue 菜单表或静态菜单实际使用的字段，不能直接假定字段名完全一致。

### 5.2 推荐的转换代码

以下 TypeScript 是逻辑参考，不要求主平台原样复制：

```ts
interface ManifestNode {
  viewId: string;
  title: string;
  order: number;
  enabled: boolean;
  children: ManifestNode[];
}

function buildSceneRoute(viewId: string) {
  return {
    path: '/scene-library',
    query: { viewId },
  };
}

function convertOrdinaryNode(node: ManifestNode): HostMenuNode {
  return {
    key: `scene-library-view-${node.viewId}`,
    title: node.title,
    order: node.order,
    enabled: node.enabled,
    route: buildSceneRoute(node.viewId),
    children: node.children.map(convertOrdinaryNode),
  };
}

function convertRootCategory(node: ManifestNode): HostMenuNode {
  const homeNode: HostMenuNode = {
    key: `scene-library-home-${node.viewId}`,
    title: '首页',
    tabTitle: `${node.title}首页`,
    order: 0,
    enabled: node.enabled,
    route: buildSceneRoute(node.viewId),
    children: [],
  };

  return {
    key: `scene-library-group-${node.viewId}`,
    title: node.title,
    order: node.order,
    enabled: node.enabled,
    // 该节点只负责展开，不绑定场景页面路由
    children: [homeNode, ...node.children.map(convertOrdinaryNode)],
  };
}

const sceneLibraryChildren = manifest.items.map(convertRootCategory);
```

关键要求：

- 只对 `manifest.items` 中的 20 个根分类注入“首页”；
- 不要递归地给所有普通叶子再增加“首页”；
- 根分类转成目录后，原 `viewId` 不能丢失，而是转交给新增的首页节点；
- 原 children 仍按原数据递归转换；
- 不得修改、截断或根据 `viewId` 前缀猜测 children；
- 禁止把 1029 个原页面压平到“场景库”一级下面。

### 5.3 菜单唯一键和路由名称

20 个新增菜单虽然显示名称都叫“首页”，但主平台内部唯一键必须不同。

建议格式：

```text
目录键：scene-library-group-<viewId>
首页键：scene-library-home-<viewId>
页面键：scene-library-view-<viewId>
```

例如：

```text
scene-library-group-smart-ops
scene-library-home-smart-ops
scene-library-view-eq-0
```

不得只使用文字“首页”作为菜单键、路由名或权限码，否则 20 个首页会发生覆盖、缓存串页或权限冲突。

如果主平台动态路由要求每条菜单拥有唯一 `name`，也必须根据分类 `viewId` 生成唯一名称。

### 5.4 权限处理

新增首页原则上继承对应二级分类的可见权限：

```text
用户能看到“工业智能运维”
→ 用户也应能看到其“首页”
```

如果主平台需要为每条菜单生成独立权限码，建议：

```text
scene-library:smart-ops:home
scene-library:simulation:home
```

不要因为首页是新增的合成菜单而让它默认无权限或只对管理员可见。

### 5.5 点击首页时的主平台路由

点击“工业智能运维 → 首页”时：

```ts
router.push({
  path: '/scene-library',
  query: { viewId: 'smart-ops' },
});
```

点击“仿真分析 → 首页”时：

```ts
router.push({
  path: '/scene-library',
  query: { viewId: 'simulation' },
});
```

不要使用：

- `window.open`；
- 新浏览器标签页；
- `/scene-library/smart-ops` 这类未经双方约定的新路径；
- 把中文标题作为 `viewId`；
- 点击父分类后偷偷回退到上一次打开的页面。

### 5.6 iframe 地址必须跟随 query 更新

主平台宿主页继续使用同一个 iframe，并根据当前路由 query 生成地址：

```text
https://47.122.104.52/cockpit/?embedded=1&viewId=smart-ops
```

参考代码：

```ts
const frameSrc = computed(() => {
  const url = new URL(sceneLibraryEntry);
  url.searchParams.set('embedded', '1');
  url.searchParams.set('viewId', normalizedViewId.value);
  return url.toString();
});
```

由于所有页面都复用 `/scene-library`，主平台不能只监听 `route.path`；必须让 `route.query.viewId` 的变化触发 iframe 地址更新。

如果主平台使用 iframe `key` 强制刷新，建议 key 至少包含 `viewId`：

```vue
<iframe :key="viewId" :src="frameSrc" />
```

是否必须重建 iframe 应以主平台现有实现为准，但最终页面必须与当前 query 一致。

## 6. 不需要修改的内容

本次整改不需要：

- 修改场景库 `App.tsx`、`index.tsx` 或业务页面；
- 修改场景库 `viewId`；
- 重新生成另一套业务页面路由；
- 改用 qiankun；
- 增加 iframe 套 iframe；
- 增加主平台到场景库的 `postMessage` 切页协议；
- 回滚场景库线上 Release `20260820-173922`；
- 重新部署场景库服务器；
- 修改现有模型详情跳转消息协议。

正式 manifest 仍是：

```text
scene-library-menu.manifest.json
```

主平台只在导入或转换时生成额外的 20 个“首页”菜单节点，不能把这些主平台合成节点反向写成新的场景库 `viewId`。

## 7. 主平台开发与发布步骤

### 第一步：备份

- 备份当前主平台“场景库”菜单数据或静态配置；
- 记录当前主平台代码版本、菜单数据版本和回滚方式；
- 不操作场景库服务器。

### 第二步：修改转换逻辑或菜单数据

- 对正式 manifest 的 20 个根分类逐一生成目录节点；
- 在每个目录下第一个位置生成“首页”；
- 首页使用根分类原 `viewId`；
- 追加原 children；
- 为目录、首页和普通页面生成互不冲突的唯一键；
- 配置首页权限继承。

### 第三步：本地或测试环境检查

- 数量应新增 20 个主平台合成首页节点；
- 20 个分类展开后都应首先看到“首页”；
- 原 1029 个下级页面不能减少；
- 菜单标题、排序和层级应与 manifest 一致；
- 点击首页后浏览器主路由 query 应等于分类 `viewId`；
- iframe 地址应同时包含 `embedded=1` 和相同 `viewId`。

### 第四步：发布主平台

根据主平台实际实现，可能需要发布两部分：

1. 菜单数据或菜单导入结果；
2. 若转换、query 监听或 iframe 生成逻辑有代码变化，则发布主平台前端代码。

发布后如主平台对菜单、权限或动态路由有缓存，应按主平台既有流程刷新缓存并重新登录验证。

### 第五步：联合验收

场景库当前版本保持不动，双方只验证主平台新菜单与现有场景库页面的组合结果。

## 9. 常见错误及判断方式

### 错误一：20 个首页共用同一个菜单键

表现：点击不同首页总是回到同一个分类，或者内标签互相覆盖。

处理：菜单键、路由名和权限码必须包含分类 `viewId`。

### 错误二：首页使用新造的场景库 viewId

错误示例：

```text
viewId=home-smart-ops
```

场景库不认识这个 ID，会回退默认页。正确值必须是：

```text
viewId=smart-ops
```

### 错误三：只增加菜单文字，没有配置路由

表现：能看到“首页”，点击后页面不变化。

处理：首页必须执行 `/scene-library?viewId=<分类原viewId>`。

### 错误四：只监听 path，不监听 query

表现：地址栏的 `viewId` 已变化，但 iframe 仍显示上一页。

处理：iframe `src` 的计算必须依赖 `route.query.viewId`。

### 错误五：把首页插入 manifest 的每一级

表现：普通叶子下面又出现无意义的“首页”，菜单数量异常膨胀。

处理：本次只给 `manifest.items` 的 20 个根分类增加首页。

### 错误六：把页面业务报错当成导航报错

例如仿真页面已经显示正确标题和 `viewId`，但内容提示“外部模型服务暂不可用”。这说明导航已经成功，后续应排查外部模型服务，不应再次改菜单路由。

## 10. 回滚方式

如果主平台发布后出现菜单或权限异常：

1. 恢复主平台发布前的菜单数据或静态菜单配置；
2. 如同时发布了主平台前端代码，恢复其上一版本；
3. 刷新主平台菜单、权限和动态路由缓存；
4. 验证主平台原功能恢复；
5. 不回滚场景库 Release，除非另有证据证明场景库自身出现独立故障。
