# 双平台菜单清单与页面定位协议

> 协议目的：让主平台菜单能够稳定定位场景库页面。  
> 协议版本：`1.0`  
> 传输方式：第一版使用 URL query；已有模型详情跳转继续使用独立 `postMessage` 协议。

## 1. 术语

| 术语 | 含义 |
|---|---|
| host | 主平台 Vue 应用 |
| scene library | iframe 中的场景库 React 应用 |
| `viewId` | 场景库页面的稳定唯一标识 |
| menu manifest | 场景库导出的纯 JSON 菜单树 |
| embedded mode | 不显示场景库全局导航的嵌入模式 |

---

## 2. 菜单层级协议

manifest 的 `items` 只描述场景库原菜单树，不包含主平台一级节点“场景库”。

主平台导入时负责包一层：

```text
主平台生成：场景库
              └─ manifest.items
```

这样可以避免 manifest 中同时出现主平台路由信息与场景库页面信息。

原菜单树父子结构必须原样保留。

---

## 3. manifest 文件格式

建议文件名：

```text
scene-library-menu.manifest.json
```

建议结构：

```json
{
  "schemaVersion": "1.0",
  "menuVersion": "20260820-<构建时间>",
  "generatedAt": "2026-08-20T00:00:00+08:00",
  "sourceCommit": "<完整Git提交SHA>",
  "defaultViewId": "smart-ops",
  "items": [
    {
      "viewId": "smart-ops",
      "title": "工业智能运维",
      "order": 10,
      "enabled": true,
      "children": [
        {
          "viewId": "eq-0",
          "title": "水轮机智能运维",
          "order": 10,
          "enabled": true,
          "children": []
        }
      ]
    }
  ]
}
```

### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `schemaVersion` | string | 是 | JSON 结构版本；第一版固定 `1.0` |
| `menuVersion` | string | 是 | 本次菜单快照版本 |
| `generatedAt` | ISO 8601 string | 是 | 生成时间，带时区 |
| `sourceCommit` | string | 建议 | 对应 Git commit；dirty 构建需另外标注 |
| `defaultViewId` | string | 是 | 缺省页面 |
| `items` | array | 是 | 原场景库根菜单数组 |

### 菜单节点字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `viewId` | string | 是 | 全树唯一页面标识 |
| `title` | string | 是 | 中文菜单名称 |
| `order` | integer | 是 | 同级排序 |
| `enabled` | boolean | 是 | 是否建议导入启用 |
| `children` | array | 是 | 子节点；叶子使用空数组 |
| `permissionHint` | string | 否 | 权限分组建议，不是最终主平台权限码 |
| `iconHint` | string | 否 | 图标语义建议，不传 React 图标 |

第一版不传文件路径、React 组件名、iframe URL 和主平台路由。

---

## 4. `viewId` 规则

`viewId` 是双方最关键的稳定键。

规则：

- 全菜单树唯一；
- 区分大小写；
- 推荐只使用 `[A-Za-z0-9_-]`；
- 推荐最大 128 字符；
- 一旦生产使用，不因中文名称修改而随意改变；
- 不包含 `/`、`?`、`#`、空格和 HTML；
- 不使用 React 组件路径；
- 删除页面时先在新 manifest 中禁用，再协调主平台移除；
- 如必须重命名，至少提供一个发布周期的 old → new 映射。

主平台必须把它当作不透明标识，不根据前缀猜权限或组件。

---

## 5. 主平台页面 URL

规范形式：

```text
/scene-library?viewId=<URL编码后的viewId>
```

示例：

```text
/scene-library?viewId=smart-ops
/scene-library?viewId=eq-0
/scene-library?viewId=sim-visual-hydro-turbine
```

主平台应使用：

```ts
router.push({ path: '/scene-library', query: { viewId } });
```

---

## 6. iframe URL

规范形式：

```text
<SCENE_LIBRARY_ENTRY>?embedded=1&viewId=<URL编码后的viewId>
```

当前联调源站示例：

```text
http://47.122.104.52:8081/cockpit/?embedded=1&viewId=smart-ops
```

参数定义：

| 参数 | 必填 | 值 | 行为 |
|---|---:|---|---|
| `embedded` | 是 | `1` | 隐藏场景库全局 Sidebar 和顶部平台栏 |
| `viewId` | 建议 | 合法 ID | 打开对应页面；缺失时进入默认页 |

其他 `embedded` 值均按非嵌入处理，避免 `embedded=false` 被 JavaScript 当成真值。

双方必须使用 URL API，不手工拼接 `&`，以便兼容入口已有 query 的情况。

---

## 7. 校验和失败行为

### 主平台发送前

检查：

- ID 来自已导入 manifest；
- 菜单已启用；
- 当前用户有权限；
- 类型为单个字符串；
- 长度和字符合法。

### 场景库接收后

再次检查：

- `isKnownViewId(viewId)` 为真；
- ID 不被解释为文件路径；
- 对应页面可进入。

### 失败处理

第一版建议：

```text
缺少 viewId → 打开 defaultViewId
未知 viewId → 记录警告，打开 defaultViewId，显示轻量提示
无权限      → 主平台拒绝，不加载未授权 viewId
iframe 失败  → 主平台显示现有加载失败与重试界面
```

不得对未知 ID 动态 import 任意路径。

---

## 8. 页面刷新与前进后退

主平台 URL 中保留 `viewId`，因此：

- F5 刷新可恢复；
- 复制链接可复现；
- 浏览器前进/后退由 Vue Router 恢复 query；
- iframe src 由当前 route 重新计算。

主平台不要仅把 `viewId` 存在临时 Pinia 状态而不写 URL，否则刷新后会丢失当前页面。

---

## 9. 现有模型详情消息协议继续保留

已有方向：

```text
场景库 iframe → 主平台
```

请求类型：

```text
scene-library:navigate
```

响应类型：

```text
scene-library:navigate-result
```

其用途仍限定为从指定场景页导航到主平台 `/three-model/detail`。安全检查仍包括：

- `event.source` 是当前 iframe；
- `event.origin` 命中白名单；
- 协议版本正确；
- path 命中白名单；
- 模型 ID 合法；
- 主平台权限守卫通过。

本次不增加 `scene-library:set-view`，不修改原请求结构。

## 10. 版本兼容

| 场景库 | 主平台 | 预期结果 |
|---|---|---|
| 旧版 | 旧版 | 原导航和内容正常 |
| 新版 | 旧版 | 无参数访问，仍显示原导航，兼容 |
| 新版 | 新版 | 主平台导航，iframe 只显示内容，目标状态 |
| 旧版 | 新版 | 参数被旧版忽略，出现双导航；功能可用但视觉不合格 |

因此发布顺序固定为：

```text
场景库新版 → 验证 → 主平台新版
```

---

## 11. manifest 变更流程

新增、删除、改名或移动菜单时：

1. 场景库修改 `MENU_ITEMS` 和对应页面注册；
2. 自动测试 ID 唯一、页面可渲染；
3. 生成新 `menuVersion` manifest；
4. 生成 SHA-256；
5. 将差异清单发给主平台；
6. 主平台在发布前导入；
7. 双方记录版本映射；
8. 联合验证新增/变更项。

建议维护映射：

```text
主平台发布版本
场景库 Release ID
menuVersion
manifest SHA-256
```

这样出现菜单与页面不一致时，可以快速判断是哪一端版本未同步。
