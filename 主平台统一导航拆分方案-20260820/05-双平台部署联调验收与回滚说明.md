# 双平台部署、联调、验收与回滚说明

## 1. 总体原则

两端独立部署，不互相登录服务器：

```text
场景库团队 → 47.122.104.52
主平台团队 → 8.146.211.204
```

固定发布顺序：

```text
冻结菜单协议
  → 场景库构建测试
  → 场景库发布
  → 验证新旧入口
  → 主平台导入菜单并发布代码
  → 联合验收
```

---

## 2. 场景库发布前门禁

- [ ] 本次 `MENU_ITEMS` 已确认；
- [ ] manifest 自动生成并校验；
- [ ] `viewId` 全局唯一；
- [ ] `npm run typecheck` 通过；
- [ ] `npm run build:all` 通过；
- [ ] standalone 和 microapp 产物完整；
- [ ] 无参数独立版仍显示旧导航；
- [ ] `embedded=1` 隐藏 Sidebar 和顶部栏；
- [ ] 有效根/叶子 `viewId` 均能打开；
- [ ] 非法 ID 不白屏；
- [ ] 模型详情跳转回归通过；
- [ ] 发布包 SHA-256 已记录；
- [ ] 回滚 release 已确认。

## 3. 场景库部署方式

沿用现有 release 机制，不改变服务器拓扑：

```text
/nlplabProj/scene-library/releases/<NEW_RELEASE>
/nlplabProj/scene-library/current
/nlplabProj/scene-library/previous
/nlplabProj/scene-library/shared/
```

服务与入口：

```text
scene-library.service
127.0.0.1:3102
https://47.122.104.52/cockpit/
https://47.122.104.52/scene-library-api/health
```

发布流程仍为：

1. 本地构建；
2. 打包并计算 SHA-256；
3. 上传 `/tmp`；
4. 远端复核 SHA-256；
5. 安装到新 release，不切换；
6. 预检；
7. 记录旧 `current`；
8. 原子更新 `previous/current`；
9. 重启 service；
10. 技术和业务验证；
11. 失败自动/人工回滚。

预计不修改 Nginx、systemd unit、端口和共享数据。

## 4. 场景库发布后、主平台发布前验证

### 旧入口兼容

```text
https://47.122.104.52/cockpit/
```

预期：完整独立版，仍有原 Sidebar。

### 新嵌入入口

```text
https://47.122.104.52/cockpit/?embedded=1&viewId=smart-ops
```

预期：

- 无场景库 Sidebar；
- 无场景库顶部平台栏；
- 显示工业智能运维；
- 内容占满页面。

再选择至少一个深层页面验证：

```text
https://47.122.104.52/cockpit/?embedded=1&viewId=<叶子ID>
```

只有这些检查通过，才通知主平台开始上线。

## 6. 主平台部署

主平台按其既有流程完成：

1. 备份当前代码版本和菜单数据；
2. 导入/同步场景库菜单；
3. 发布宿主页和路由调整；
4. 验证 Nginx、前端资源和 API；
5. 使用实际权限账号验收；
6. 记录主平台版本与场景库 Release ID。

菜单数据和前端代码必须作为同一个变更窗口管理。失败时两者要一起恢复到兼容状态。

### 菜单结构

| 编号 | 用例 | 预期 |
|---|---|---|
| M-01 | 查看主平台一级菜单 | 只有一个“场景库” |

| M-04 | 检查排序和标题 | 与 manifest 一致 |
| M-05 | 无权限用户查看 | 不显示或不可进入受限菜单 |

### 页面定位

| 编号 | 用例 | 预期 |
|---|---|---|
| V-01 | 点击“工业智能运维 → 首页”（`smart-ops`） | 只显示对应分类首页内容，无场景库导航 |

### 内标签

| 编号 | 用例 | 预期 |
|---|---|---|
| T-01 | 内标签开启 | 按主平台确认的复用/独立策略显示 |
| T-02 | 内标签关闭 | 同一浏览器页普通路由切换 |

### 既有跨项目导航

| 编号 | 用例 | 预期 |
|---|---|---|
| N-01 | 场景页点击查看模型详情 | 主平台打开正确模型 ID |

| N-04 | 非法消息 | 主平台拒绝，不导航 |

### 业务回归

至少抽检每类高风险页面：

- 3D/WebGL；
- 数据图表；
- 文件上传/下载；
- 模型远程获取；
- 长列表和滚动；
- 仿真控制；
- 页面内部标签或步骤条；
- 全屏能力。

## 8. 问题快速归属

| 现象 | 优先检查方 | 优先检查内容 |
|---|---|---|
| 主平台没有场景库菜单 | 主平台 | 菜单导入、权限、启用状态 |
| 菜单层级错误 | 主平台 | manifest 转换和 parent 映射 |
| 点击后 query 不对 | 主平台 | 菜单 URL/Router 配置 |
| iframe 仍显示双导航 | 双方 | 主平台是否传 `embedded=1`；场景库版本是否最新 |
| 打开的业务页不对 | 双方 | `viewId` 是否正确；manifest 是否同版本 |
| 页面白屏 | 场景库 | ID 校验、组件加载和控制台错误 |
| iframe 整体无法访问 | 双方运维 | 源站、Nginx、网络、iframe 错误态 |
| API 数据失败 | 场景库/网络 | `/scene-library-api/` 和后端日志 |
| 模型详情跳转失败 | 双方 | `postMessage`、Origin、主平台监听和权限 |
| 顶部出现过多标签 | 主平台 | fullPath/query 和标签复用策略 |
| 切页太慢 | 双方评估 | iframe 重载成本，是否进入第二阶段优化 |

## 9. 回滚策略

### 场景库回滚

恢复切换前真实 `OLD_RELEASE`：

```text
current → OLD_RELEASE
恢复 APP_VERSION
重启 scene-library.service
验证健康接口和旧入口
```

不要回滚或删除 `shared/data`、`shared/model-cache`。

### 主平台回滚

主平台同时恢复：

- 宿主页/路由代码；
- 菜单与权限数据；
- 必要的环境配置。

如果只回滚代码、不回滚菜单，可能出现菜单可见但宿主页不认识参数。

### 跨版本兼容回滚

场景库新版兼容主平台旧版，因此优先回滚主平台通常仍可继续使用。若场景库也要回滚到旧版，应确保主平台同时恢复为不依赖嵌入参数隐藏导航的旧状态，否则会出现双导航。
