## 2026-08-20：模型详情导航消息 Origin 故障定位与场景库诊断增强

状态：**场景库已开发并通过本地构建；主平台热修与联合验收待完成。**

### 故障结论

- 四个模型详情地址已经是正确的 HTTPS history 路由，并非网址未更新；
- 场景库嵌入时发送受控 `scene-library:navigate`，消息中只有允许的路径和模型 ID，不直接打开完整详情 URL；
- 主平台当前 iframe 配置为同源 `/cockpit/`，浏览器产生的消息来源是 `https://8.146.211.204:3100`；
- 主平台运行代码仍用 `http://47.122.104.52:8081` 校验请求来源并作为响应目标，两处均与实际 origin 不一致；
- 主平台因此静默丢弃请求，场景库等待 5 秒后显示“主平台未响应”；
- `event.origin` 由浏览器生成，场景库无法伪造，因此功能恢复必须由主平台修正并发布。

### 场景库修改

- 超时提示改为明确要求检查 iframe 实际来源与消息来源白名单；
- 控制台增加 `iframeOrigin`、`expectedParentOrigin`、目标路径和模型 ID 诊断信息；
- 扩展 HTTPS 专项检查，继续保证四个详情 URL 为 HTTPS，且导航请求不携带任意完整外链；
- 新增 `09-模型详情跳转消息Origin热修说明.md`，给出主平台接收校验、响应 targetOrigin、备用入口和验收步骤；
- 修正 08 文档中错误的 hash 路由示例，当前主平台使用 `/three-model/detail` history 路由；
- 未采用任意来源、顶层强制跳转、新浏览器标签或 HTTP 降级兜底。

### 本地验证

```text

npm run verify:navigation：NAVIGATION_SPLIT_VERIFY_OK roots=20 nodes=1049
npm run verify:https-integration：HTTPS_INTEGRATION_VERIFY_OK models=4 files=17
npm run build:all：standalone 与 microapp 均构建成功
```

### 主平台待办

- 从 iframe 最终 `frameSrc` 动态计算允许的 origin；
- 接收请求时同时校验 `event.source` 与实际 origin；
- 返回 `scene-library:navigate-result` 时发往已验证的 `event.origin`；
- 保留既有模型路径白名单、四个模型 ID、内标签页开关和路由逻辑；
- 具体代码见 `09-模型详情跳转消息Origin热修说明.md`。

## 2026-08-20：方案建立

状态：**已规划，尚未修改业务代码，尚未部署。**

### 新需求

- 场景库不再在主平台 iframe 中显示自己的全局导航栏；
- 主平台负责场景库全部菜单导航；
- 主平台关于本项目只有一个一级菜单“场景库”；
- 场景库现有菜单树整体放到“场景库”之下；
- 原场景库根菜单成为主平台二级菜单；
- 原 children 继续成为三级或更深层菜单；
- iframe 只显示导航栏以外的业务内容。

### 方案决定

- 保持当前 iframe 集成；
- 不采用 qiankun；
- 第一版使用 `embedded=1&viewId=...` URL 参数；
- 主平台路由采用 `/scene-library?viewId=...`；
- 场景库无参数独立入口继续保留原导航；
- 不新增主平台到场景库的实时切页 `postMessage`；
- 现有场景库到主平台模型详情的消息协议保持不变；
- 菜单清单由 `MENU_ITEMS` 自动生成 JSON，避免人工录入；
- 场景库先发布，主平台后发布；
- 不改变场景库 Nginx、systemd、API 前缀和 release 目录。

## 2026-08-20：主平台分类首页兼容方案补充

状态：**场景库侧已部署；主平台整改方案已确定，尚未由主平台发布和联合验收。**

### 联调发现

- 场景库线上 Release `20260820-173922` 的 `embedded=1` 和 `viewId` 定位正常；
- 主平台普通叶子页面能够正确进入；
- 主平台菜单组件把存在 children 的二级分类当作纯展开目录；
- 因此二级分类原本对应的首页无法被选中；
- 不存在 children 的分类可作为普通菜单进入，但交互与其他分类不一致。

### 最终选择

- 不改造主平台通用父菜单点击行为；
- 主平台为全部 20 个二级分类统一增加一个排在首位的“首页”子菜单；
- 二级分类只负责展开和收起；
- 新增首页沿用分类原 `viewId`；
- 原 children 排在首页之后并保持原顺序和层级；
- 即使某分类原 children 为空，也生成唯一的“首页”；
- 20 个同名首页分别使用包含分类 `viewId` 的唯一菜单键、路由名和权限码；
- 合成首页只存在于主平台菜单数据中，不修改场景库 manifest schema，不新增场景库 `viewId`。

### 文档调整

- 新增 `07-主平台分类首页子菜单整改说明.md`；
- 更新 `00-方案总览与文档交付清单.md`；
- 更新 `03-主平台端开发调整指导.md`；
- 更新 `04-菜单清单与页面定位协议.md`；
- 更新 `05-双平台部署联调验收与回滚说明.md`；
- 更新本修改日志和云端更新执行记录。

### 发布边界

- 当前无需重新构建或部署场景库；
- 主平台需要修改菜单导入/转换或菜单配置；
- 如果主平台 iframe 宿主页尚未正确监听 `route.query.viewId`，需一并修改并发布主平台前端；
- 主平台完成发布后，按 07 文档 H-01 至 H-15 进行联合验收；
- 联合验收前，本项不得标记为“已验收”。

1. 每次代码、菜单、协议或部署变化都增加一条，不覆盖旧记录；
2. 记录事实和版本，不只写“已修改”；

6. 回滚也必须记录原因、目标和结果；
7. 密码、私钥、Token 和完整生产环境变量不得写入日志。
