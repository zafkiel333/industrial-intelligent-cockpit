# 场景库端开发调整指导

## 1. 调整目标

场景库从“带全局导航的完整独立应用”增加一种“只渲染内容的嵌入模式”。

```text
无参数独立访问：保留 Sidebar + 顶部栏 + 内容
embedded=1：      隐藏 Sidebar + 顶部栏，只显示内容
```

不删除 `Sidebar.tsx`，不把业务页面搬出 `App.tsx`，不改变现有页面 `viewId`。

---

## 2. 当前已有能力

当前 `AppProps` 已包含：

```ts
export interface AppProps {
  embedded?: boolean;
  viewId?: string;
  onNavigate?: (viewId: string, title?: string) => void;
}
```

并且：

- `activeTabId` 已可由 `viewId` 初始化；
- `viewId` 改变时已有 effect 更新 `activeTabId`；
- 顶部栏已有 `!embedded` 条件；
- 主内容 padding 已区分 embedded；
- `isKnownViewId` 已能检查 ID；
- `DEFAULT_VIEW_ID` 已存在。

因此主要不是重构页面，而是补齐独立入口的参数适配和 Sidebar 条件渲染。

---

## 3. URL 参数解析

建议新增纯函数，例如：

```ts
interface SceneLibraryLaunchOptions {
  embedded: boolean;
  viewId: string;
  requestedViewId?: string;
  invalidViewId: boolean;
}
```

解析规则：

1. 只把 `embedded=1` 解释为嵌入模式；
2. 使用 `URLSearchParams` 读取 `viewId`；
3. 对 `viewId` 执行 `trim()`；
4. 建议长度不超过 128；
5. 建议字符限制为字母、数字、下划线和连字符；
6. 最终必须通过 `isKnownViewId`；
7. 空值使用 `DEFAULT_VIEW_ID`；
8. 非法值不传给页面加载器，回退默认页并记录警告。

伪代码：

```ts
const params = new URLSearchParams(window.location.search);
const embedded = params.get('embedded') === '1';
const requestedViewId = params.get('viewId')?.trim();
const valid = requestedViewId && isKnownViewId(requestedViewId);
const viewId = valid ? requestedViewId : DEFAULT_VIEW_ID;
```

不要用 `innerHTML` 显示参数，不把 query 当成组件文件路径。

---

## 4. 独立入口调整

`index.tsx` 当前直接渲染：

```tsx
<App />
```

调整后将解析结果传给 App：

```tsx
<App embedded={launchOptions.embedded} viewId={launchOptions.viewId} />
```

建议把解析函数放入 `src/integration/`，便于单元测试，不要把所有逻辑堆在入口文件。

---

## 5. 隐藏全局导航

`App.tsx` 当前无论是否嵌入都会渲染 Sidebar：

```tsx
<Sidebar activeId={activeTabId} onSelect={handleSelect} compact={embedded} />
```

调整为：

```tsx
{!embedded && (
  <Sidebar activeId={activeTabId} onSelect={handleSelect} />
)}
```

顶部栏已经使用 `!embedded`，保留即可。

嵌入模式仍保留：

- `ScenarioMetaBar`；
- 页面内部标签、筛选器、按钮；
- 业务卡片和图表；
- 场景日志；
- 页面自身必要的返回/步骤控制。

本需求只移除“场景库全局导航”，不误删业务页面内部导航。

---

## 6. 菜单 manifest

为避免主平台人工录入，应从 `MENU_ITEMS` 自动生成：

```text
scene-library-menu.manifest.json
```

生成结果必须是纯数据，不包含：

- React 组件；
- 图标对象；
- 函数；
- 文件路径；
- 回调；
- 运行时状态。

至少包含：

```json
{
  "schemaVersion": "1.0",
  "menuVersion": "<发布ID或菜单版本>",
  "defaultViewId": "smart-ops",
  "items": [
    {
      "viewId": "smart-ops",
      "title": "工业智能运维",
      "order": 10,
      "children": []
    }
  ]
}
```

生成时自动检查：

- `viewId` 全局唯一；
- title 非空；
- children 是数组；
- 每个叶子 `viewId` 均能被 `isKnownViewId` 识别；
- 不存在无法渲染的菜单；
- 输出稳定排序；
- 记录 SHA-256。

manifest 是跨团队交付产物，不应成为另一份人工维护的菜单源。

---

## 7. 兼容性

必须保证下面地址继续工作：

```text
http://47.122.104.52:8081/cockpit/
```

它应继续显示原来的完整独立版。

新增支持：

```text
http://47.122.104.52:8081/cockpit/?embedded=1&viewId=smart-ops
```

它应只显示“工业智能运维”内容。

这种兼容设计允许场景库先发布、主平台后发布。

---

## 8. 与已有模型详情协议的关系

现有：

```text
scene-library:navigate
scene-library:navigate-result
```

继续保持不变。

URL `viewId` 负责：

```text
主平台菜单 → 场景库内部业务页面
```

已有 `postMessage` 负责：

```text
场景库业务页面 → 主平台模型详情路由
```

不要把两种方向混成一个不清晰协议。

---

## 9. 测试要求

### 参数测试

- 无 query；
- `embedded=1`；
- `embedded=0`；
- 有效根菜单 ID；
- 有效叶子 ID；
- 空 ID；
- 未知 ID；
- 超长 ID；
- 包含 `/`、HTML 或编码字符的 ID；
- 重复 query 参数。

### 布局测试

- embedded 模式无 Sidebar；
- embedded 模式无顶部平台栏；
- 主内容占满 iframe；
- 宽屏、窄屏和滚动正常；
- 3D Canvas 尺寸正确；
- 页面内部必要导航未被误删。

### 回归测试

- 原独立版导航仍可用；
- 所有原菜单仍能打开；
- API 前缀不变；
- 模型详情跳转不变；
- 上传、下载、模型资源、图表和日志正常。
