# HTTPS 协议切换与混合内容整改说明

> 编写日期：2026-08-20
> 适用范围：主平台 `ices-union` 与场景库 `industrial-intelligent-cockpit` 生产集成
> 结论：主平台是 HTTPS 页面。浏览器直接访问的资源必须是 HTTPS 或主平台同源代理地址；服务端代理到场景库 HTTP 兼容入口不属于浏览器混合内容。

## 1. 为什么必须修改

主平台生产入口已使用 HTTPS。浏览器会阻止 HTTPS 页面加载 HTTP iframe，这类安全限制叫“混合内容拦截”。因此，场景库即使通过 HTTP 独立访问完全正常，只要主平台仍用 HTTP 地址嵌入，就可能出现空白页、资源加载失败、消息来源校验失败或浏览器控制台 Mixed Content 报错。

前四个外部模型仿真页面还有另一条协议链：场景库后端需要访问主平台的模型 API。主平台 `3100` 端口现在只接受 HTTPS，而旧配置仍写成 HTTP，导致 TCP 可连接但请求失败，最终页面显示“外部模型服务暂不可用”。

这两项不是同一个问题，但都由协议从 HTTP 切换到 HTTPS 后旧配置未同步造成，必须一起整改。

## 2. 当前已提供的场景库地址

| 用途 | 正确地址 | 说明 |
|---|---|---|
| 主平台 iframe / 微应用生产集成 | `/cockpit/` 或 `https://47.122.104.52/cockpit/` | 可使用主平台同源代理或场景库 HTTPS 直连 |
| 场景库独立版 | `https://47.122.104.52/cockpit/` | 推荐的独立访问地址 |
| 场景库微应用入口 | `https://47.122.104.52/microapps/scene-library/` | 主平台加载微应用时使用 |
| 微应用脚本 | `https://47.122.104.52/microapps/scene-library/scene-library.js` | 如果主平台直接配置脚本地址则使用此地址 |
| 场景库公开 API | `https://47.122.104.52/scene-library-api/` | 浏览器或主平台访问时使用 |
| 旧 HTTP 兼容入口 | `http://47.122.104.52:8081` | 仅兼容独立调试；不得嵌入 HTTPS 主平台 |

特别注意：`8081` 仍是纯 HTTP 端口，不能写成 `https://47.122.104.52:8081`。标准 HTTPS 入口使用 443 端口，因此 URL 不需要写端口号。

## 3. 主平台必须修改的配置

### 3.1 场景库加载地址

主平台当前正式配置使用同源代理地址：

```text
/cockpit/
```

该方式可以继续使用。如果不使用同源代理而直接连接场景库，则把旧地址：

```text
http://47.122.104.52:8081/cockpit/
```

改为：

```text
https://47.122.104.52/cockpit/
```

原有 `embedded=1`、`viewId=...` 等 query 参数原样保留。例如：

```text
https://47.122.104.52/cockpit/?embedded=1&viewId=eq-0
```

### 3.2 `postMessage` 来源校验

如果主平台维护允许接收消息的来源白名单，必须以 iframe 最终 URL 计算，而不是硬编码。例如：

```ts
const expectedSceneLibraryOrigin = computed(
  () => new URL(frameSrc.value, window.location.href).origin,
);
```

使用 `/cockpit/` 时实际来源是 `https://8.146.211.204:3100`；使用场景库 HTTPS 直连时实际来源是 `https://47.122.104.52`。旧值 `http://47.122.104.52:8081` 与二者都不同，不能继续作为固定校验值。完整代码见 `09-模型详情跳转消息Origin热修说明.md`。

场景库发送的既有消息协议保持不变，包括：

```text
scene-library:ready
scene-library:location
scene-library:navigate
scene-library:navigate-result
```

### 3.3 CSP 或 iframe 域名白名单

如果主平台响应头配置了 Content-Security-Policy，至少确认 `frame-src`（或旧版 `child-src`）允许：

```text
https://47.122.104.52
```

如果主平台代码还有“可信 iframe 地址”“微应用地址”“跨域来源”等独立白名单，也需同步替换协议。

### 3.4 不应修改的内容

- 不改变 `viewId`、菜单 ID、页面名称和导航消息结构；
- 不把场景库改回新浏览器标签页方案；
- 不使用 `https://47.122.104.52:8081`；
- 不需要登录或修改场景库服务器，主平台只修改自身入口与白名单配置。

## 4. 场景库侧本次整改内容

场景库侧将同步完成：

1. 前四个外部模型仿真页面的后端 API 基地址由 HTTP 改为 `https://8.146.211.204:3100/three-model-api`；
2. 四个模型详情地址统一改为 `https://8.146.211.204:3100/three-model/detail?id=...`；
3. 初始化失败页面中的“查看资源详情”也改用已有的主平台导航协议，不再使用 `target="_blank"`；
4. 增加构建前自动检查，阻止受控范围重新出现 `http://8.146.211.204:3100`、`window.open` 或 `target="_blank"`；
5. 场景库 Nginx 增加 HTTPS 443，同时保留 HTTP 8081 兼容入口；
6. HTTPS 证书配置自动续期，并在续期成功后自动校验和重载 Nginx。

服务器内部 `http://127.0.0.1:3102` 不需要改成 HTTPS。它只发生在同一台服务器的 Nginx 与 Node 服务之间，不暴露给浏览器，因此不属于混合内容。

## 6. 联调验收清单

主平台发布配置后，逐项检查：

1. 浏览器地址栏为主平台 HTTPS 地址；
2. 网络面板中场景库文档、JS、CSS 和 API 全部使用 HTTPS；
3. 控制台没有 Mixed Content、CSP frame-src 或 origin 不匹配报错；
4. 场景库 20 个分类及其“首页”子菜单和叶子页面路由正常；
5. 前四个外部模型仿真页面均能加载模型数据，不再显示“外部模型服务暂不可用”；
6. 四页点击“查看资源详情”时，主平台按内标签开关决定打开内标签或当前页跳转；
7. 刷新主平台页面后，当前 `viewId` 能正确恢复；
8. 直接访问 `https://47.122.104.52/cockpit/` 仍能正常显示独立版。

## 7. 交给主平台开发的一句话

请保留主平台同源 `/cockpit/` 或改用场景库 HTTPS 入口，并让消息来源校验从 iframe 最终 `frameSrc` 动态计算；不要继续硬编码 `http://47.122.104.52:8081`，也不要把该 HTTP 地址直接嵌入 HTTPS 主平台。

> 2026-08-20 联调补充：主平台正式配置实际使用同源 `/cockpit/` 时，iframe 的浏览器 origin 是主平台自身 `https://8.146.211.204:3100`，不是场景库源站 origin。不能固定写死任意一个地址，应从 iframe 最终 `frameSrc` 动态计算。完整热修代码见 `09-模型详情跳转消息Origin热修说明.md`。
