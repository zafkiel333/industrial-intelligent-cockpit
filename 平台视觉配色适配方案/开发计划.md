# 平台视觉配色适配开发计划

> 日期：2026-08-11  
> 参考平台：https://equipms.inspuriip.com/  
> 当前状态：第三轮逐页文字对比度源码排查与通用修复已完成，生产构建通过；当前会话无本地浏览器控制入口，逐页截图验收仍待运行环境复核

## 1. 改造目标

在不改变现有页面结构、功能、接口和 3D 模型逻辑的前提下，使项目配色与参考平台相似、协调，并解决当前颜色分散、页面风格不完全统一的问题。

整体采用“浅色管理界面 + 深色工业可视化区域”：

- 导航、表格、表单和普通卡片使用浅灰白背景及企业蓝强调色；
- 3D 模型、复杂图表和仿真大屏保留深色背景，保证模型与数据清晰；
- 正常、提示、警告和故障继续使用绿、蓝、橙、红等业务状态色，不统一替换成品牌蓝。

参考平台目前无法从开发环境建立稳定连接，以下色值是待截图确认的初步方案，并非目标页面的精确取色结果。

|---|---|
| 品牌主色 | `#0068B7` |
| 品牌悬停色 | `#005A9E` |
| 页面背景 | `#E8EFF4` |

## 2. 开发内容

1. 建立统一主题变量，集中管理品牌色、背景色、文字色、边框色、状态色和图表色。
2. 优先调整应用外壳和共享组件，包括页面背景、侧栏、顶部区域、卡片、按钮、表格、输入框及弹窗。
3. 分批调整各业务页面，避免一次性替换大量 Tailwind 类名和十六进制颜色造成视觉回归。
4. 单独适配图表和 3D 场景：普通页面使用浅色主题，模型视窗和复杂可视化保留深色底板。
5. 保留现有 API、路由、数据处理、报告下载和模型加载功能，不借配色调整改变业务逻辑。

统一主题文件：

```text
index.css
```

其中 `index.css` 统一管理主题变量、历史深色类兼容映射、图表样式和 3D Canvas 视觉规则，避免逐页重复维护颜色。

2026-08-12 全量细审补充范围：

- 深色 Slate、Gray、Zinc、Neutral、Stone 容器及其任意透明度变体；
- 蓝、绿、红、橙、紫五类业务状态块、边框、渐变和悬停态；
- 按钮、卡片、表格、弹窗、抽屉、图表提示框和自定义近黑背景；
- 弹窗遮罩、3D Canvas、数字孪生 HUD 等需要保留中深色的明确例外。

2026-08-12 逐页面复核补充：

- 从 `App.tsx` 的静态导入、动态导入及 `import.meta.glob` 解析实际页面清单，共计 997 个页面模块；
- 对每个页面涉及的标准深色类、自定义十六进制渐变、径向暗角、纯黑/半透明黑背景、自定义边框和高亮文字进行分类检查；
- 普通信息组件统一浅化，图片、视频、3D、CSS 仿真和 HUD 按结构保留工业蓝灰背景，并单独校正浅色文字和业务状态色；
- 当前会话未提供本地浏览器控制入口，因此逐页截图和交互态的最终视觉验收保留为后续人工/浏览器环境复核项，不将静态检查等同于视觉验收。

## 3. 实施顺序

1. 根据参考截图确认最终色板。
2. 建立主题变量并接入项目入口。
3. 调整应用外壳及共享组件。
4. 分批调整管理页面、仿真页面和外部模型四个页面。
5. 调整图表、3D 场景、悬停、选中、禁用和告警状态。
6. 完成构建、功能、可读性和常见分辨率检查，并将每批修改写入《修改日志》。

每一批应保持可单独验证、可单独回退，不进行全项目机械颜色替换。

## 5. 验收要求

- 导航、卡片、按钮、表格、表单、弹窗和状态标签配色统一；
- 文字、按钮、边框和图表在浅色、深色区域均清晰可辨；
- 3D 模型、趋势图、告警状态和设备状态不因换色失真；

## 7. 第三轮逐页文字对比度排查（2026-08-12）

> 状态：源码排查与修复已完成。用户已明确要求修复“1号机组异常预测分析（全维推力瓦监控）”标题，并继续逐页面检查类似问题。

本轮按以下顺序执行：

1. 修复目标页面中 `text-transparent + bg-clip-text + 渐变背景` 在浅色主题下造成的标题低对比度；
2. 从 `App.tsx` 注册页面范围扫描透明文字、浅色文字叠加浅色容器、深色文字叠加深色视觉区、状态色背景与文字同色等高风险组合；
3. 优先通过统一主题规则修复具有共性的组合，仅对明确的页面特例增加局部语义类，避免机械修改大量页面；
4. 保留 3D、Canvas、视频、图片遮罩和 HUD 等深色视觉区域，并保证其中文字继续使用浅色；
5. 检查按钮、标题、说明文字、状态标签、图表图例、弹窗和空状态的普通、悬停、禁用与异常状态；
6. 执行构建、差异检查和高风险类名复扫，并将实际发现、修改文件和未完成的浏览器视觉验收写入修改日志。

验收要求：指定标题清晰可读；普通浅色区域不残留透明文字或低对比度浅字；深色可视化区域不出现深色文字；状态标签前景与背景可区分；不改变页面功能、API、数据计算、路由和 3D 模型逻辑。

执行结果：指定标题已改为实体深蓝文字并与操作按钮分离；主题层统一处理 123 个使用渐变透明文字的页面文件、42 个含低透明度单位/辅助文字的页面文件及 54 个含半透明业务文字的页面文件；同时修复 Recharts 浅色 Tooltip 的内联浅字、深色光标遮罩和 Brush 时间窗对比度。修复后的主要前景色在浅色卡片上的对比度为 5.19:1～8.56:1；`npm.cmd run build` 已通过，共转换 5,555 个模块。

## 8. 第四轮结构性视觉浮层排查（2026-08-12）

> 状态：源码排查与修复已完成。第三轮漏检了“Canvas/3D 模型组件与 HUD 浮层互为兄弟节点”的情况；类名扫描虽识别了文字和背景，却没有验证主题规则能否跨组件 DOM 层级实际命中。

本轮增加以下排查维度：

1. 修复 1 号机组柱状模型视窗中的“当前检视”和底部时间轴 HUD，明确指定深蓝灰半透明背景、浅色正文及高明度状态色；
2. 检查 Canvas、ThreeScene、视频、图片及 CSS 仿真视窗的兄弟浮层、嵌套浮层和组件外包裹层，不再只检查 Canvas 组件内部后代；
3. 检查无显式文字色、依赖父级继承的 HUD 文本，防止浅色主题把背景浅化、父级却继续继承浅色文字；
4. 检查业务色在深色 HUD 上是否被全局规则改成低明度深蓝、深绿、深红或深橙，并在视觉区恢复高明度色；
5. 检查图表内联 `contentStyle`、`itemStyle`、SVG `fill/stroke`、透明遮罩、Brush、Tooltip、选中态、悬停态、禁用态、弹窗遮罩和空状态；
6. 对动态内联颜色区分“文字”与“色点/进度条/模型材质”：文字需要对比度保护，纯视觉编码和 3D 材质继续保留业务颜色；
7. 优先增加可复用的“包含 Canvas 的可视化容器直属浮层”规则，同时为 1 号机组增加确定性局部类，避免再次依赖脆弱的 DOM 层级推断；
8. 完成生产构建、差异检查、结构性选择器复扫，并在修改日志中如实记录浏览器截图验收限制。

验收要求：“当前检视”、当前时间、时间轴说明、历史/预测标签在柱状模型背景上清晰可辨；其他 Canvas/3D 直属 HUD 同样保持深底浅字；普通内容卡片不被误改为深色；模型、图表、接口和交互逻辑不变。

执行结果：为 1 号机组模型外壳、当前检视和时间轴增加确定性作用域；新增包含 Canvas 的 `overflow-hidden` 视窗直属浮层规则，覆盖模型组件与 HUD 互为兄弟节点的情况；模型内部弱说明文字由 `#94a3b8` 提升为 `#b8c8d2`；深色视觉区的蓝、绿、红、橙、紫状态文字和对应深色半透明标签背景成对恢复。源码清点覆盖 11 个 React Three Fiber Canvas 文件、788 个原生 Three.js Renderer 文件、1 个 HTML Canvas 文件，并复核 139 处内联颜色/透明度使用。主要视觉文字的理论对比度为 5.07:1～13.95:1；生产构建通过。
