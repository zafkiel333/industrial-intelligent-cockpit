## 3. 本轮已经完成的代码改造

### 3.1 固定协议长表字段

Modbus 长表固定字段：

```text
timestamp,device_id,unit_id,function_code,address,raw_value,data_type,byte_order,scale,offset,unit,quality
```

IEC 61850 长表固定字段：

```text
timestamp,device_id,ied,object_reference,functional_constraint,value,unit,quality
```

约定：

- CSV、XLSX、JSON 三种文件均可承载长表。
- 允许增加扩展列，但固定列不能缺少或改名；缺少固定列时，预检返回明确错误。
- 上传窗口选择的设备 ID 是本批次最终设备标签，会覆盖文件内 `device_id` 的业务归属。
- Modbus 支持单值以及两个 16 位寄存器组成的 `float32`、`int32`、`uint32`，支持 `ABCD`、`BADC`、`CDAB`、`DCBA` 字节序，并应用 `scale` 和 `offset`。
- IEC 61850 按 `object_reference` 映射模型点位，保留 `ied`、功能约束、质量和源时间戳。

### 3.2 SCL 独立上传和永久保存

IEC 61850 上传可附带 `.icd`、`.cid`、`.scd`、`.ssd` 或 `.xml` SCL 文件。

生命周期：

```text
选择 SCL
  -> 创建导入任务
  -> SCL 分块写入 imports/<batchId>.scl.part
  -> 预检：只读取临时 SCL，不写永久目录
  -> 用户确认导入
  -> protocol/scl/<batchId>-<原文件名>
```

每个模型目录下的永久路径：

```text
<dataDirectory>/model-showcase/<sceneId>__model-<modelId>/protocol/scl/
```

批次清单增加以下元数据：

```text
sclFileName
sclPath
sclSize
sclSha256
```

删除运行数据、删除批次或重置当前数据不会自动删除 `protocol/scl/` 中的归档文件。SCL 是设备模型描述资料，不会作为历史测量记录写入 `current/state.json`。

服务端会进行基础结构检查：必须能够识别 `SCL`、`IED` 和 `LDevice`。浏览器端还会显示 IED、逻辑设备和数据对象数量。本轮没有接入完整 IEC 61850 XSD 校验，也没有把 SCL 自动转换为最终映射配置。

### 3.3 明显异常处理

本轮只处理不需要业务推断的异常：

| 异常 | 当前处理 |
|---|---|
| 固定列缺失 | 整个文件预检失败，列出缺少字段 |
| 首尾空白、常见小数分隔符、质量值大小写 | 自动规范化并计数 |
| 时间戳为空或无法解析 | 拒绝该行/时间组 |
| 空值、非数值、`NaN`、无穷值 | 剔除该点；若导致必需点位缺失，则拒绝整个时间记录 |
| 明显超出模型合理范围 | 剔除该点，不截断、不猜测替代值 |
| 同一时间同一点位重复 | 使用文件中最后一个值并计数 |
| 同一时间缺少任一模型必需点位 | 不导入该时间记录，不进入预测诊断 |
| 未配置点位 | 忽略并在预检列出未映射点位 |

不做以下复杂处理：单位自动推断、跨时间插值、自动补点、错列修复、业务规则冲突裁决。

预检新增统计：

```text
correctedValueCount
invalidValueCount
incompleteRecordCount
duplicatePointCount
```

## 5. 数据目录约定

每个模型隔离一个目录：

```text
<dataDirectory>/model-showcase/<sceneId>__model-<modelId>/
├─ current/
│  └─ state.json                 # 当前规范化记录、批次清单、数据版本

├─ imports/                      # 未完成上传和预检的临时文件

└─ protocol/
   └─ scl/                       # 确认后永久保存的 IEC 61850 SCL
```

服务启动时会自动创建四个模型目录、参考资料和 `protocol/scl/`。发布包不应包含生产上传数据；云端运行数据位于 release 目录外的 shared data。

创建 IEC 61850 任务时，在 JSON 中附带：

